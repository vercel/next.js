The `connection()` function allows you to indicate rendering should wait for an incoming user request before continuing.

It's useful when a component doesn't use [Request-time APIs](/docs/app/glossary#request-time-apis) like `cookies` or `headers`, but still needs to produce different output per request, such as `Math.random()` or `new Date()`.

```tsx filename="app/page.tsx" switcher
import { connection } from 'next/server'

export default async function Page() {
  const rand = await getRandomValue()
  return <span>{rand}</span>
}

async function getRandomValue() {
  await connection() // prerendering stops here
  return Math.random()
}
```

```jsx filename="app/page.js" switcher
import { connection } from 'next/server'

export default async function Page() {
  const rand = await getRandomValue()
  return <span>{rand}</span>
}

async function getRandomValue() {
  await connection() // prerendering stops here
  return Math.random()
}
```

## Examples

### Synchronous database drivers

Queries from synchronous database drivers like `better-sqlite3` complete during prerendering. Call `connection()` before your query to wait for an incoming request before running it:

```ts filename="app/lib/data.ts" switcher
import { connection } from 'next/server'
import Database from 'better-sqlite3'

const db = new Database('app.db')

export async function getVisitorCount() {
  await connection()
  return db.prepare('SELECT value FROM counters WHERE name = ?').get('visitors')
}
```

```js filename="app/lib/data.js" switcher
import { connection } from 'next/server'
import Database from 'better-sqlite3'

const db = new Database('app.db')

export async function getVisitorCount() {
  await connection()
  return db.prepare('SELECT value FROM counters WHERE name = ?').get('visitors')
}
```

Now any component that calls `getVisitorCount()` will be excluded from prerendering, along with the rest of its output.

## Reference

### Type

```ts
function connection(): Promise<void>
```

### Parameters

- The function does not accept any parameters.

### Returns

- The function returns a `void` Promise. It is not meant to be consumed.

## Good to know

- `connection` replaces [`unstable_noStore`](/docs/app/api-reference/functions/unstable_noStore) to better align with the future of Next.js.
- Common Request-time APIs suspend build-time prerendering. With [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching), these APIs can resolve during runtime prerendering, so a later synchronous read may still need an explicit boundary. See [Synchronous IO after request data](/docs/app/api-reference/functions/io#synchronous-io-after-request-data).
- With [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents), place the component that calls `connection()` inside a [`<Suspense>`](https://react.dev/reference/react/Suspense) boundary, either directly or through an ancestor such as a [`loading.js`](/docs/app/api-reference/file-conventions/loading) file. The nearest boundary's fallback is prerendered into the [static shell](/docs/app/glossary#static-shell), and the code after `connection()` runs at request time. Without a boundary, navigations to the route [block instead of being instant](/docs/messages/blocking-prerender-dynamic).
- With [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents), prefer [`io()`](/docs/app/api-reference/functions/io) for excluding content from the static shell. It works the same way, and it can also be called inside a [`"use cache"`](/docs/app/api-reference/directives/use-cache) scope, where it resolves immediately. Reach for `connection()` only when rendering should wait for a real user request.
