`instant()` from `@next/playwright` pauses dynamic server content while a Playwright test asserts on the initial or prefetched UI. It requires [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents).

```ts filename="e2e/navigation.test.ts" switcher highlight={7-11}
import { expect, test } from '@playwright/test'
import { instant } from '@next/playwright'

test('shows the dashboard shell', async ({ page }) => {
  await page.goto('/')

  await instant(page, async () => {
    await page.getByRole('link', { name: 'Dashboard' }).click()
    await page.waitForURL((url) => url.pathname === '/dashboard')
    await expect(page.getByRole('heading', { name: 'Dashboard' })).toBeVisible()
  })
})
```

```js filename="e2e/navigation.test.js" switcher highlight={7-11}
import { expect, test } from '@playwright/test'
import { instant } from '@next/playwright'

test('shows the dashboard shell', async ({ page }) => {
  await page.goto('/')

  await instant(page, async () => {
    await page.getByRole('link', { name: 'Dashboard' }).click()
    await page.waitForURL((url) => url.pathname === '/dashboard')
    await expect(page.getByRole('heading', { name: 'Dashboard' })).toBeVisible()
  })
})
```

## Installation

Install the helper alongside Playwright:

```bash package="pnpm"
pnpm add -D @next/playwright @playwright/test
```

```bash package="npm"
npm install -D @next/playwright @playwright/test
```

```bash package="yarn"
yarn add -D @next/playwright @playwright/test
```

```bash package="bun"
bun add -D @next/playwright @playwright/test
```

## Reference

```ts
function instant<T>(
  page: Page,
  callback: () => Promise<T>,
  options?: { baseURL?: string }
): Promise<T>
```

| Parameter         | Description                                                                                                            |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `page`            | The Playwright page to navigate and inspect.                                                                           |
| `callback`        | An async function containing navigation actions and assertions. Dynamic server content stays paused until it finishes. |
| `options.baseURL` | Optional application URL. Required before the page's first navigation; otherwise inferred from `page.url()`.           |

The returned promise resolves with the callback's result or rejects with its error. The helper releases the pause when the callback finishes, including when an assertion fails.

## Behavior

### Initial page loads

For `page.goto()` or a reload, the server sends the static shell while request-time content remains paused. Pass `baseURL` when the page has not loaded yet:

```ts filename="e2e/initial-load.test.ts" switcher highlight={5-15}
import { expect, test } from '@playwright/test'
import { instant } from '@next/playwright'

test('shows the initial shell', async ({ page, baseURL }) => {
  await instant(
    page,
    async () => {
      await page.goto('/dashboard')
      await expect(
        page.getByRole('heading', { name: 'Dashboard' })
      ).toBeVisible()
    },
    { baseURL }
  )
})
```

```js filename="e2e/initial-load.test.js" switcher highlight={5-15}
import { expect, test } from '@playwright/test'
import { instant } from '@next/playwright'

test('shows the initial shell', async ({ page, baseURL }) => {
  await instant(
    page,
    async () => {
      await page.goto('/dashboard')
      await expect(
        page.getByRole('heading', { name: 'Dashboard' })
      ).toBeVisible()
    },
    { baseURL }
  )
})
```

This example uses Playwright's configured `baseURL`. The pause does not stop hydration: Client Components that can resolve without server content may already be visible when assertions run.

### Client navigations

Click a link inside the callback to inspect the destination's prefetched UI. Its content can differ from the initial static shell, depending on the link's [prefetch configuration](/docs/app/guides/optimizing-prefetching).

Wait for the destination URL before asserting on its UI so a shared selector cannot match the source page. Assert on deferred content after `instant()` returns. Cache Components can preserve previous pages hidden in the DOM; use [visibility-aware locators](/docs/app/guides/preserving-ui-state#testing).

### Search-parameter updates

Changing only search parameters updates the existing page. If the update suspends on data that was not prefetched, React can keep the previous content visible instead of showing a fallback.

`instant()` holds that data until the callback finishes. Waiting for the updated URL or content inside the callback can therefore time out even when ordinary navigation works. If retaining content is the intended experience, test [pending feedback](/docs/app/guides/interactive-apps#step-3-filter-with-pending-feedback) and the completed update without the pause. A search-parameter update can still be instant when the content it needs is already available.

### Production builds

The testing API is available automatically in `next dev` with Cache Components. For a production test, enable [`experimental.exposeTestingApiInProductionBuild`](/docs/app/api-reference/config/next-config-js/exposeTestingApiInProductionBuild) during both `next build` and `next start`. Keep this option disabled on user-facing production deployments.

## Good to know

- The helper tests which UI can render without waiting for dynamic server content. It does not measure loading time or prefetch latency.
- The pause applies to the browser context. Nested or concurrent `instant()` calls in the same context throw; separate contexts are independent.
- Entering and leaving the callback corresponds to **Pause on navigations** and **Resume** in the [Navigation Inspector](/docs/app/guides/instant-navigation#visualize-loading-states-with-the-nextjs-devtools).
- The pause uses a cookie scoped to the hostname, not the port. Avoid using it across different applications on the same hostname in one browser context.
