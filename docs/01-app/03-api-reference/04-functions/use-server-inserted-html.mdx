The `useServerInsertedHTML` hook lets a **Client Component** inject markup into the HTML document Next.js generates, from anywhere in the tree. It works in the App Router only and does nothing if called in the Pages Router.

The nodes you return are rendered separately from your page, and inserted into the HTML as Next.js generates it. The hook exists for CSS-in-JS style registries, which collect the rules produced during a render and flush them into the document ahead of the markup that uses them.

```tsx filename="app/registry.tsx" switcher
'use client'

import { useState } from 'react'
import { useServerInsertedHTML } from 'next/navigation'
import { StyleRegistry, createStyleRegistry } from 'styled-jsx'

export default function StyledJsxRegistry({
  children,
}: {
  children: React.ReactNode
}) {
  const [registry] = useState(() => createStyleRegistry())

  useServerInsertedHTML(() => {
    const styles = registry.styles()
    registry.flush()
    return <>{styles}</>
  })

  return <StyleRegistry registry={registry}>{children}</StyleRegistry>
}
```

```jsx filename="app/registry.js" switcher
'use client'

import { useState } from 'react'
import { useServerInsertedHTML } from 'next/navigation'
import { StyleRegistry, createStyleRegistry } from 'styled-jsx'

export default function StyledJsxRegistry({ children }) {
  const [registry] = useState(() => createStyleRegistry())

  useServerInsertedHTML(() => {
    const styles = registry.styles()
    registry.flush()
    return <>{styles}</>
  })

  return <StyleRegistry registry={registry}>{children}</StyleRegistry>
}
```

See [How to use CSS-in-JS libraries](/docs/app/guides/css-in-js) for the full setup, including `styled-components`.

## Parameters

```tsx
useServerInsertedHTML(callback: () => React.ReactNode)
```

| Parameter  | Type                    | Description                                                   |
| ---------- | ----------------------- | ------------------------------------------------------------- |
| `callback` | `() => React.ReactNode` | Returns the nodes to insert into the generated HTML document. |

## Returns

The hook does not return a value.

## Behavior

### The callback runs once per chunk of HTML

Next.js produces the HTML in chunks, and your callback runs once per chunk, not once per render. A component that renders once can have its callback invoked several times, so keep the callback free of side effects.

The callback runs whenever Next.js produces an HTML document, on a direct navigation and during build time prerender.

Content inserted while the `<head>` is still open goes there. Everything after is included in the body.

```tsx filename="app/page.tsx"
import { Suspense } from 'react'
import { Header } from './header'
import { Feed } from './feed'

export default function Page() {
  return (
    <>
      {/* Renders in the first chunk, so its rules go into <head>. */}
      <Header />
      <Suspense fallback={<p>Loading feed</p>}>
        {/* Resolves after the head is closed, so its rules go into <body>. */}
        <Feed />
      </Suspense>
    </>
  )
}
```

This assumes nothing above `Header` suspends. If something does, `Header` renders after the head has closed and its rules go into `<body>` as well.

In the style registry pattern above, `styled-jsx` collects the CSS rules it finds as your tree renders. Each time a chunk is ready the callback returns the rules gathered so far and clears the registry, so the next chunk carries only what was found since. Return the same nodes every time instead and the document ends up with one copy of them per chunk.

Style registries work because a `<style>` tag applies to the whole document wherever it ends up.

On a client navigation this hook does nothing. Your CSS-in-JS library injects rules in the browser itself, so styles still apply to components rendered after a transition.

### Prefer other options for inline scripts

Prefer declaring inline scripts in React Server Components. The hook is for nodes that support the tree being rendered, such as the `<style>` tags a CSS-in-JS registry collects as it renders.

A script is included in `<head>` only while nothing above it has suspended, so a change to the tree can move it into `<body>` with no error.

If you are already inside a Client Component module and cannot reach the root layout, the hook is a way to get a script into the document. Writing a `<script>` in that component's JSX is not an alternative, because React creates the element but never executes it on a client navigation, and logs an error in development saying so.

The inline script approach, including applying a stored theme before the browser paints, is developed in [Preventing a flash before hydration](/docs/app/guides/preventing-flash-before-hydration).

Next.js also does not add a [nonce](/docs/app/guides/content-security-policy) to what you return. Under a `script-src` policy that requires one, the script is emitted without a `nonce` attribute and the browser blocks it.
