Use `generateMarkdown` to customize the Markdown returned by a route after Next.js renders the route's React tree.

`generateMarkdown` only runs when:

- `experimental.markdown` is enabled in `next.config.js`
- the route is opted into Markdown output
- the request is a full `GET` or `HEAD` document request that prefers `text/markdown`
- the route runs in the Node.js runtime

Normal HTML requests are not affected.

## Reference

<AppOnly>

### App Router

Export `generateMarkdown` from a `layout.js` or `page.js` file.

```tsx filename="app/blog/[slug]/page.tsx" switcher
export const markdown = true

export async function generateMarkdown(
  props: PageProps<'/blog/[slug]'>,
  helpers: { renderDefault(): Promise<string> }
) {
  const content = await helpers.renderDefault()

  return ['# Blog export', content].join('\n\n')
}

export default function Page() {
  return <p>Hello</p>
}
```

```jsx filename="app/blog/[slug]/page.js" switcher
export const markdown = true

export async function generateMarkdown(props, { renderDefault }) {
  const content = await renderDefault()

  return ['# Blog export', content].join('\n\n')
}

export default function Page() {
  return <p>Hello</p>
}
```

Layouts also receive a `children` helper containing the Markdown generated by nested segments:

```jsx filename="app/blog/layout.js"
export const markdown = true

export async function generateMarkdown(_props, { children }) {
  return ['layout-start', await children, 'layout-end'].join('\n')
}

export default function Layout({ children }) {
  return <section>{children}</section>
}
```

#### Parameters

- `props`: The same props passed to the route segment during rendering.
- `helpers.renderDefault()`: Returns the default Markdown for the current segment.
- `helpers.children`: Layout-only helper that resolves to the Markdown generated by child segments.

</AppOnly>

<PagesOnly>

### Pages Router

Export `generateMarkdown` from a page:

```tsx filename="pages/blog/[slug].tsx" switcher
export const markdown = true

export async function generateMarkdown(
  context: {
    props: { title: string }
    query: { slug?: string | string[] }
  },
  helpers: { renderDefault(): Promise<string> }
) {
  const content = await helpers.renderDefault()

  return [`title:${context.props.title}`, content].join('\n')
}

export default function Page({ title }: { title: string }) {
  return <p>{title}</p>
}
```

```jsx filename="pages/blog/[slug].js" switcher
export const markdown = true

export async function generateMarkdown(context, { renderDefault }) {
  const content = await renderDefault()

  return [`title:${context.props.title}`, content].join('\n')
}

export default function Page({ title }) {
  return <p>{title}</p>
}
```

#### Parameters

- `context.props`: The resolved page props.
- `context.query`: The request query, including dynamic route params.
- `helpers.renderDefault()`: Returns the default Markdown for the page.

</PagesOnly>

### Returns

`generateMarkdown` can return:

- a string
- a promise that resolves to a string
- `null` or `undefined` to omit the current segment

## Good to know

- Export `markdown = true` or `markdown = { components: ... }` from the same route to opt it into Markdown output.
- In App Router, `generateMarkdown` is supported in pages and layouts.
- In Pages Router, `generateMarkdown` is supported in pages only. `_app` and `_document` are not part of Markdown generation.
- `generateMarkdown` is not supported in the Edge runtime.
- If you do not export `generateMarkdown`, Next.js uses the default serializer.
- `helpers.renderDefault()` uses the currently merged Markdown component overrides for that segment.
