`proxy.go` runs Go code before a request is routed, using Go's `net/http` APIs.

```go filename="proxy.go" highlight={9,10}
package main

import (
  "net/http"
  "next/go"
)

func Proxy(w http.ResponseWriter, r *http.Request) {
  w.Header().Set("x-proxy", "go")
  next.Next(w)
}
```

To use it, enable `experimental.goRoutes`, follow the [Go setup](/docs/app/api-reference/file-conventions/route-go#setup), and create `proxy.go` next to `app` (or inside `src`). Export a `Proxy` function with the signature above. A project can have only one Proxy file, so `proxy.go` cannot be combined with `proxy.ts` or `proxy.js`.

## Reference

Import the `next/go` package for the Proxy helpers. Next.js adds it to your `go.mod` when you first import it.

| Helper                                     | Behavior                                   |
| ------------------------------------------ | ------------------------------------------ |
| `next.Next(w, options...)`                 | Continue routing the request.              |
| `next.Rewrite(w, destination, options...)` | Route the request to another URL.          |
| Return without calling either              | Send the response written to `w` directly. |

Use standard Go APIs for everything else, such as `http.Redirect` for redirects and `http.SetCookie` for cookies. When the request continues or is rewritten, cookies set with `http.SetCookie` are available through [`cookies()`](/docs/app/api-reference/functions/cookies) in the page or route that handles it.

> **Good to know**: The package is named `next`. If a function already has a variable named `next`, such as a `next http.Handler` parameter, import the package under another name: `nextgo "next/go"`.

### ProxyOptions

`next.Next` and `next.Rewrite` accept an optional `next.ProxyOptions` value to change the headers of the request that continues:

```go
type ProxyOptions struct {
  Request RequestOptions
}

type RequestOptions struct {
  Headers http.Header
}
```

`Request.Headers` replaces the request headers. Leave it `nil` to keep them unchanged, or pass an empty `http.Header{}` to remove them all. Go keeps the host in `r.Host` instead of `r.Header`, so set it explicitly when you clone the headers.

## Examples

### Rewriting a request

Call `next.Rewrite` to serve another path while keeping the original URL in the browser.

```go filename="proxy.go" highlight={10,14}
package main

import (
  "net/http"
  "next/go"
)

func Proxy(w http.ResponseWriter, r *http.Request) {
  if r.URL.Path == "/old-path" {
    next.Rewrite(w, "/new-path")
    return
  }

  next.Next(w)
}
```

### Modifying request headers

Clone the incoming headers, change them, and pass them in `ProxyOptions`.

```go filename="proxy.go" highlight={13-16}
package main

import (
  "net/http"
  "next/go"
)

func Proxy(w http.ResponseWriter, r *http.Request) {
  headers := r.Header.Clone()
  headers.Set("Host", r.Host)
  headers.Set("x-proxy", "go")
  headers.Del("x-example")
  options := next.ProxyOptions{
    Request: next.RequestOptions{Headers: headers},
  }
  next.Next(w, options)
}
```

## Good to know

- Go Proxy runs on every request.
- Other `.go` files in the same directory as `proxy.go` are compiled with it and must use `package main`. Do not define a `main` function; Next.js generates it. If your project root already contains Go code, put the proxy in `src/proxy.go`, and put shared code in packages that `proxy.go` imports.
- Go Proxy is only supported in App Router applications. A build fails if the project also has Pages Router routes or an `i18n` configuration. Custom `_app`, `_document`, and `_error` files are allowed.
- `r.URL` is the URL a JavaScript Proxy would receive. Requests that the route could interpret differently from Proxy, such as paths with an encoded `.rsc` suffix, receive a `404` response before Proxy runs. Requests with a query string over 64 KiB or 4,096 parameters receive a `414` response.
- Go Proxy requires Turbopack. Self-host with `next build` and `next start`; deploying to a platform requires an adapter that supports Go middleware.
