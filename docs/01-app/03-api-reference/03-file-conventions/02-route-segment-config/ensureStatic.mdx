The `unstable_ensureStatic` route segment config controls how much of a route Next.js serves from a static prerender. Export it from a [page](/docs/app/api-reference/file-conventions/page) or [layout](/docs/app/api-reference/file-conventions/layout) to require static rendering for the [App Shell](/docs/app/glossary#app-shell), [prefetches](/docs/app/guides/prefetching), or the whole page.

```tsx filename="app/blog/layout.tsx" highlight={1} switcher
export const unstable_ensureStatic = 'navigation'

export default function Layout({ children }: { children: React.ReactNode }) {
  return <>{children}</>
}
```

```jsx filename="app/blog/layout.js" highlight={1} switcher
export const unstable_ensureStatic = 'navigation'

export default function Layout({ children }) {
  return <>{children}</>
}
```

> **Good to know**:
>
> - The `unstable_ensureStatic` export only works when [`cacheComponents`](/docs/app/api-reference/config/next-config-js/cacheComponents) is enabled. The build fails otherwise.
> - Exporting `unstable_ensureStatic` from a Client Component throws an error.

## Reference

The export accepts `'auto'`, `'shell'`, `'prefetch'`, `'navigation'`, or `false`. The default is `'auto'`, which is equivalent to omitting the export.

| Value              | App Shell     | Per-link prefetch | Navigation and initial load |
| ------------------ | ------------- | ----------------- | --------------------------- |
| `'auto'` (default) | Default       | Default           | Default                     |
| `false`            | Default       | Default           | Default                     |
| `'shell'`          | Static output | Default           | Default                     |
| `'prefetch'`       | Static output | Static output     | Default                     |
| `'navigation'`     | Static output | Static output     | Static output               |

"Default" means Next.js serves the response from static output when the route allows it and renders it per request otherwise, the same as without the export. "Static output" means Next.js serves prerendered output for that stage. The output can include Suspense fallbacks for content that renders at a later stage.

The static levels become progressively stricter: `'prefetch'` includes `'shell'`, and `'navigation'` includes both. Unlike `'auto'`, `false` rejects a static level set elsewhere on the route. See [Combining levels across layouts and pages](#combining-levels-across-layouts-and-pages).

### `'shell'`

Serves the route's [App Shell](/docs/app/glossary#app-shell) from static output. Reads of [`cookies()`](/docs/app/api-reference/functions/cookies) and [`headers()`](/docs/app/api-reference/functions/headers) anywhere in the route behave as if they were below [`unstable_prefetch()`](/docs/app/api-reference/functions/prefetch): the content that reads them renders on a per-link prefetch or on the navigation, and the shell shows the fallback of the nearest `<Suspense>` boundary.

Requires [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching). Without it, a route has no App Shell, so the value has no effect and Next.js logs a warning.

Because the shell cannot include session data, [instant validation](/docs/app/api-reference/file-conventions/route-segment-config/instant) reports a `cookies()` or `headers()` read outside `<Suspense>` as an insight in development.

### `'prefetch'`

Serves the App Shell and per-link prefetches, requested with [`<Link prefetch={true}>`](/docs/app/api-reference/components/link#prefetch), from static output. Reads of `cookies()` and `headers()` behave as if they were below [`unstable_navigation()`](/docs/app/api-reference/functions/navigation): the content that reads them renders on the navigation.

Without Partial Prefetching, default prefetches already use static output, so this value has no additional effect. `<Link prefetch={true}>` can still prefetch request-time content, the same as a navigation.

### `'navigation'`

Requires every segment of the route to prerender completely, so initial loads and client navigations use static output. This level also works with Cache Components alone, without enabling Partial Prefetching.

Unlike `'shell'` and `'prefetch'`, this level does not allow server content to wait for a later rendering stage.

Server content that requires per-request work fails `next build` and shows an error in the development overlay, even when it is wrapped in `<Suspense>` or the segment sets [`instant = false`](/docs/app/api-reference/file-conventions/route-segment-config/instant#disabling-instant):

- Uncached data, such as a `fetch` or database call without [`use cache`](/docs/app/api-reference/directives/use-cache).
- [`connection()`](/docs/app/api-reference/functions/connection), `cookies()`, `headers()`, and server-side `searchParams`.
- A `use cache` scope whose [`expire`](/docs/app/api-reference/functions/cacheLife#expire) is under five minutes, whose [`stale`](/docs/app/api-reference/functions/cacheLife#stale) is under 30 seconds, or whose [`revalidate`](/docs/app/api-reference/functions/cacheLife#revalidate) is `0`. A `stale` time between 30 seconds and five minutes is allowed.
- A promise for request-dependent server data passed to a Client Component, whether or not the component reads it.

These constraints also apply to [`generateMetadata`](/docs/app/api-reference/functions/generate-metadata) and [`generateViewport`](/docs/app/api-reference/functions/generate-viewport).

Data cached with `use cache` can be prerendered. Calling [`unstable_prefetch()`](/docs/app/api-reference/functions/prefetch) or [`unstable_navigation()`](/docs/app/api-reference/functions/navigation) also remains allowed, because these functions do not defer work during a static prerender.

#### Dynamic route parameters

Dynamic routes must provide [`generateStaticParams()`](/docs/app/api-reference/functions/generate-static-params) with at least one result. Each result must include all dynamic parameters for the route, even if a parameter is only read in a Client Component or is unused.

Parameters returned by `generateStaticParams()` can be read during prerendering. For parameter values that were not prerendered at build time, Next.js waits for the static result to be generated before serving the response.

#### Client Components

Client Components can load request-specific content in the browser. Inside `<Suspense>`, `use(browser())` and [`use(io())`](/docs/app/api-reference/functions/io) are allowed. The prerender includes the fallback for the deferred content. See [Rendering components only in the browser](/docs/app/guides/single-page-applications#rendering-components-only-in-the-browser).

Client hooks such as [`useParams()`](/docs/app/api-reference/functions/use-params) and [`useSearchParams()`](/docs/app/api-reference/functions/use-search-params) are also allowed. They do not remove the `generateStaticParams()` requirement for dynamic routes. Passing a request-dependent promise from a Server Component still requires server work and fails validation.

#### How validation works

The `'navigation'` level validates the fully rendered route during development and `next build`. In development, errors appear in the dev overlay with the source location and suggested fixes. During `next build`, the error includes the APIs that can prevent the route from being prerendered.

The error guidance depends on where the data is accessed:

- Page or layout content: [runtime data](/docs/messages/ensure-static-route-runtime) or [uncached data](/docs/messages/ensure-static-route-dynamic)
- `generateMetadata()`: [runtime data](/docs/messages/ensure-static-metadata-runtime) or [uncached data](/docs/messages/ensure-static-metadata-dynamic)
- `generateViewport()`: [runtime data](/docs/messages/ensure-static-viewport-runtime) or [uncached data](/docs/messages/ensure-static-viewport-dynamic)

### `false`

Behaves like `'auto'`, but fails the build if another segment on the route sets `'shell'`, `'prefetch'`, or `'navigation'`. It is compatible with `'auto'`, `false`, and segments without the export. Use it on a route that should not be made static, so that a level added later to a shared layout is caught instead of applied.

Like `'shell'`, it requires Partial Prefetching and logs a warning without it.

## Combining levels across layouts and pages

A level set on a layout applies to every route that renders the layout, including its nested layouts, pages, and [parallel routes](/docs/app/api-reference/file-conventions/parallel-routes). Within a route, the level covers every segment, including the layouts above the one that sets it.

Leaving the export unset or setting it to `'auto'` is compatible with any level and does not override another segment's setting. A descendant can set a stricter static level, but not a weaker one:

```tsx filename="app/blog/layout.tsx"
export const unstable_ensureStatic = 'prefetch'
```

```tsx filename="app/blog/[slug]/page.tsx"
export const unstable_ensureStatic = 'navigation' // allowed, stricter than 'prefetch'
```

A weaker level on a child segment fails the build:

```text filename="Terminal"
A child segment cannot override a parent segment with a less-constrained `unstable_ensureStatic`.
```

Mixing `false` with `'shell'`, `'prefetch'`, or `'navigation'` in a parent and child fails with:

```text filename="Terminal"
A child segment cannot override a parent segment with an incompatible `unstable_ensureStatic`.
```

Parallel routes rendered together must set the same value, leave the export unset, or use `'auto'`. Conflicting values fail with:

```text filename="Terminal"
Parallel slots cannot have incompatible `unstable_ensureStatic`.
```

## TypeScript

```tsx filename="app/blog/layout.tsx"
type EnsureStatic = 'auto' | 'shell' | 'prefetch' | 'navigation' | false

export const unstable_ensureStatic: EnsureStatic = 'navigation'
```
