The `unstable_ensureStatic` route segment config sets how much of a route Next.js serves from a static prerender. At `'navigation'`, the highest level, any part of the route that needs per-request work is a build error.

> **Good to know**:
>
> - The `unstable_ensureStatic` export only works when [`cacheComponents`](/docs/app/api-reference/config/next-config-js/cacheComponents) is enabled. The build fails otherwise.
> - Exporting `unstable_ensureStatic` from a Client Component throws an error.

```tsx filename="app/blog/layout.tsx" switcher
export const unstable_ensureStatic = 'navigation'

export default function Layout({ children }: { children: React.ReactNode }) {
  return <>{children}</>
}
```

```jsx filename="app/blog/layout.js" switcher
export const unstable_ensureStatic = 'navigation'

export default function Layout({ children }) {
  return <>{children}</>
}
```

## Reference

The export accepts one of the following values. Each level includes the ones before it.

| Value                         | App Shell     | Per-link prefetch | Navigation and initial load |
| ----------------------------- | ------------- | ----------------- | --------------------------- |
| `'auto'` (default) or `false` | Default       | Default           | Default                     |
| `'shell'`                     | Static output | Default           | Default                     |
| `'prefetch'`                  | Static output | Static output     | Default                     |
| `'navigation'`                | Static output | Static output     | Static output               |

"Default" means Next.js serves the response from static output when the route allows it and renders it per request otherwise, the same as without the export. "Static output" means the response is always served from the prerender the build already generated.

### `'shell'`

Serves the route's [App Shell](/docs/app/glossary#app-shell) from static output. Reads of [`cookies()`](/docs/app/api-reference/functions/cookies) and [`headers()`](/docs/app/api-reference/functions/headers) anywhere in the route behave as if they were below [`unstable_prefetch()`](/docs/app/api-reference/functions/prefetch): the content that reads them renders on a per-link prefetch or on the navigation, and the shell shows the fallback of the nearest `<Suspense>` boundary.

Requires [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching). Without it, a route has no App Shell, so the value has no effect and Next.js logs a warning.

Because the shell cannot include session data, [instant validation](/docs/app/api-reference/file-conventions/route-segment-config/instant) reports a `cookies()` or `headers()` read outside `<Suspense>` as an insight in development.

### `'prefetch'`

Serves the App Shell and per-link prefetches, requested with [`<Link prefetch={true}>`](/docs/app/api-reference/components/link#prefetch), from static output. Reads of `cookies()` and `headers()` behave as if they were below [`unstable_navigation()`](/docs/app/api-reference/functions/navigation): the content that reads them renders on the navigation.

Without Partial Prefetching, this is how Cache Components prefetches by default, so the value has no additional effect.

### `'navigation'`

Requires every segment of the route to prerender completely at build time, so the initial page load is served as static HTML.

Any content that would render per request fails `next build` and shows an error in the development overlay, even when it is wrapped in `<Suspense>` or the segment sets [`instant = false`](/docs/app/api-reference/file-conventions/route-segment-config/instant#disabling-instant):

| Fails                                                                                                                           | Allowed                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Uncached data, such as `fetch` or a database call without [`use cache`](/docs/app/api-reference/directives/use-cache)           | Data cached with `use cache`                                                                                                                    |
| [`connection()`](/docs/app/api-reference/functions/connection)                                                                  | [`unstable_prefetch()`](/docs/app/api-reference/functions/prefetch) and [`unstable_navigation()`](/docs/app/api-reference/functions/navigation) |
| `cookies()` and `headers()`                                                                                                     | Request-specific content loaded by a Client Component after hydration                                                                           |
| `params` not returned by [`generateStaticParams`](/docs/app/api-reference/functions/generate-static-params), and `searchParams` | `params` returned by `generateStaticParams`, or read on the client with `useParams()` and `useSearchParams()`                                   |
| A `use cache` scope whose [`expire`](/docs/app/api-reference/functions/cacheLife#expire) is under five minutes                  | A `use cache` scope with a short [`stale`](/docs/app/api-reference/functions/cacheLife#stale) time                                              |
| A promise for any of the above passed to a Client Component, whether or not it is used                                          | `use(browser())` and client-side data loading inside `<Suspense>`                                                                               |

### `false`

Behaves like `'auto'`, but fails the build if any other segment on the route sets a level. Use it on a route that should not be made static, so that a level added later to a shared layout is caught instead of applied.

Like `'shell'`, it requires Partial Prefetching and logs a warning without it.

## Combining levels across layouts and pages

A level set on a layout applies to every route that renders the layout, including its nested layouts, pages, and [parallel routes](/docs/app/api-reference/file-conventions/parallel-routes). Within a route, the level covers every segment, including the layouts above the one that sets it.

A segment below it can set a stricter level, but not a weaker one:

```tsx filename="app/blog/layout.tsx"
export const unstable_ensureStatic = 'prefetch'
```

```tsx filename="app/blog/[slug]/page.tsx"
export const unstable_ensureStatic = 'navigation' // allowed, stricter than 'prefetch'
```

A weaker level on a child segment fails the build:

```bash filename="Terminal"
A child segment cannot override a parent segment with a less-constrained `unstable_ensureStatic`.
```

Mixing `false` with any other level fails the same way, with the word "incompatible" in place of "less-constrained".

Parallel routes rendered together must set the same level, or leave it unset:

```bash filename="Terminal"
Parallel slots cannot have incompatible `unstable_ensureStatic`.
```

## TypeScript

```tsx
type EnsureStatic = 'auto' | 'shell' | 'prefetch' | 'navigation' | false

export const unstable_ensureStatic: EnsureStatic = 'navigation'
```
