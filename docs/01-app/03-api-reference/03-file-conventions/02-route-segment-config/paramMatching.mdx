Use `unstable_paramMatching` to control how a dynamic route handles parameter values that are not returned by [`generateStaticParams`](/docs/app/api-reference/functions/generate-static-params).

For example, this route prerenders `/products/featured` during the build. When any other value is requested, Next.js resolves the product slug before serving a fallback:

```tsx filename="app/products/[slug]/page.tsx" highlight={3-5} switcher
import type { ParamMatching } from 'next'

export const unstable_paramMatching = {
  slug: 'blocking',
} satisfies ParamMatching<'slug'>

export function generateStaticParams() {
  return [{ slug: 'featured' }]
}
```

```jsx filename="app/products/[slug]/page.js" highlight={1-3} switcher
export const unstable_paramMatching = {
  slug: 'blocking',
}

export function generateStaticParams() {
  return [{ slug: 'featured' }]
}
```

## Reference

The export maps a dynamic parameter to one of the following modes:

| Mode          | Behavior for a value not returned by `generateStaticParams`         |
| ------------- | ------------------------------------------------------------------- |
| `'not-found'` | Return a `404` response.                                            |
| `'blocking'`  | Do not serve a fallback that omits this parameter.                   |
| `'fallback'`  | Serve the route's fallback while the requested content is rendered. |
| `'dynamic'`   | Render the parameter at request time.                               |

Use the optional `ParamMatching` type to check the parameter names and matching modes. Pass the route's parameter names as its type argument.

### `unstable_generateParamMatching`

To compute the policy in a function, export `unstable_generateParamMatching` instead:

```tsx filename="app/products/[slug]/page.tsx" highlight={3-7} switcher
import type { ParamMatching } from 'next'

export async function unstable_generateParamMatching(): Promise<
  ParamMatching<'slug'>
> {
  return { slug: 'blocking' }
}
```

```jsx filename="app/products/[slug]/page.js" highlight={1-3} switcher
export async function unstable_generateParamMatching() {
  return { slug: 'blocking' }
}
```

The function takes no arguments. A route cannot export both `unstable_paramMatching` and `unstable_generateParamMatching`.

> **Good to know**:
>
> - Parameter matching requires [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents).
> - `unstable_paramMatching` and `unstable_generateParamMatching` can only be exported from Server Component pages and layouts that use the [Node.js runtime](/docs/app/api-reference/file-conventions/route-segment-config/runtime).
> - Each key must name a dynamic parameter from the current segment or a parent segment.
> - With [`ensureStatic = 'navigation'`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic#navigation), use `'blocking'` or `'not-found'`. The `'fallback'` and `'dynamic'` modes require request-time rendering.
