The `enablePrerenderSourceMaps` option lets Next.js use existing source maps for errors during the prerender phase of `next build`. When source maps are available, error stack traces point to the original source code. It defaults to `true`.

Source maps are read when an error is first logged, so builds without errors don't pay for loading them.

This option does not generate source maps. Webpack does not generate server source maps by default. To generate them when investigating prerender errors, use [`next build --debug-prerender`](/docs/app/api-reference/cli/next#debugging-prerender-errors).

To disable it, set `enablePrerenderSourceMaps` to `false`:

```ts filename="next.config.ts" switcher highlight={4}
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  enablePrerenderSourceMaps: false,
}

export default nextConfig
```

```js filename="next.config.js" switcher highlight={3}
/** @type {import('next').NextConfig} */
const nextConfig = {
  enablePrerenderSourceMaps: false,
}

module.exports = nextConfig
```

## Reference

| Option                      | Type      | Default |
| --------------------------- | --------- | ------- |
| `enablePrerenderSourceMaps` | `boolean` | `true`  |

Disabling source maps during prerendering can reduce [build memory usage](/docs/app/guides/memory-usage#disable-source-maps) when many errors are logged, but makes prerendering errors harder to debug.

## Version History

| Version   | Changes                                                                                                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------ |
