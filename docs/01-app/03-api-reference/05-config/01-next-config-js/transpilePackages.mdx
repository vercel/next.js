Use `transpilePackages` to run a dependency through the project compiler instead of treating it as untouched runtime code. Values are package names, including scoped names like `@scope/pkg`. Paths and glob patterns are not supported.

```js filename="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  transpilePackages: ['package-name', '@scope/pkg'],
}

module.exports = nextConfig
```

This replaces the `next-transpile-modules` package.

## When you need it

Add a package to `transpilePackages` when any of the following apply:

- It ships TypeScript, JSX, or modern syntax that needs the project compiler.
- It needs the configured browser targets applied.
- It is a Pages Router server-side dependency you want bundled instead of loaded through Node.js `require` at runtime. App Router already bundles Server Component and Route Handler dependencies unless the package is listed in [`serverExternalPackages`](/docs/app/api-reference/config/next-config-js/serverExternalPackages).

Turbopack (the default) already runs TypeScript and JSX transforms on `node_modules` as well as workspace packages, so the syntax case is mostly a webpack concern. Under `next build --webpack` you need `transpilePackages` when a Pages Router import resolves to a TypeScript or JSX file whose real path is in `node_modules` or sits outside the next app's directory, for example an `apps/web` app importing `packages/ui` in the same monorepo.

> **Good to know**: A package cannot appear in both `transpilePackages` and [`serverExternalPackages`](/docs/app/api-reference/config/next-config-js/serverExternalPackages); Next.js throws at build start if it does. Packages listed in [`optimizePackageImports`](/docs/app/api-reference/config/next-config-js/optimizePackageImports) and the entries in [`default-transpiled-packages.json`](https://github.com/vercel/next.js/blob/canary/packages/next/src/lib/default-transpiled-packages.json) are added automatically; you do not need to repeat them.
