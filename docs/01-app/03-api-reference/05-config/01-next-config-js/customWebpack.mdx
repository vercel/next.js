---
title: customWebpack
description: Use a project-installed webpack version instead of the version bundled with Next.js.
version: experimental
---

The experimental `customWebpack` option makes webpack mode use your project's installed `webpack` package instead of the version bundled with Next.js.

First, install a compatible webpack version:

```bash package="pnpm"
pnpm add -D webpack@^5.98.0
```

```bash package="npm"
npm install --save-dev webpack@^5.98.0
```

```bash package="yarn"
yarn add --dev webpack@^5.98.0
```

```bash package="bun"
bun add --dev webpack@^5.98.0
```

Then enable the option in `next.config`:

```ts filename="next.config.ts" switcher highlight={5}
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    customWebpack: true,
  },
}

export default nextConfig
```

```js filename="next.config.js" switcher highlight={4}
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    customWebpack: true,
  },
}

module.exports = nextConfig
```

> **Good to know**:
>
> - This option only affects webpack mode. It does not change Turbopack or Rspack behavior.
> - When the option is omitted or `false`, Next.js uses its bundled webpack version and does not require webpack to be installed in your project.
> - Next.js declares `webpack` as an optional peer dependency with the range `^5.98.0`.
> - Enabling this option without installing webpack causes Next.js to exit with an error that explains how to install it.
> - Custom webpack versions may contain changes that are not yet compatible with Next.js. Test development and production builds before upgrading webpack.
