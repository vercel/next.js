## Usage

Turbopack FileSystem Cache enables Turbopack to reduce work across `next dev` or `next build` commands. When enabled, Turbopack will save and restore data to the `.next` folder between builds, which can greatly speed up subsequent builds and dev sessions.

> **Good to know:** The FileSystem Cache is **enabled by default** for both `next dev` and `next build`. For `next build` it is disabled by default in non-Vercel CI environments, where the cache is unlikely to persist between builds. You can explicitly enable or disable it with the flags below.

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    // Filesystem caching is enabled by default; set to `false` to disable it.
    turbopackFileSystemCacheForDev: true,
    turbopackFileSystemCacheForBuild: true,
  },
}

export default nextConfig
```

```js filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    // Filesystem caching is enabled by default; set to `false` to disable it.
    turbopackFileSystemCacheForDev: true,
    turbopackFileSystemCacheForBuild: true,
  },
}

module.exports = nextConfig
```

## Version Changes

| Version   | Changes                                                                                    |
| --------- | ------------------------------------------------------------------------------------------ |
| `v16.3.0` | FileSystem caching is enabled by default for builds (disabled by default in non-Vercel CI) |
| `v16.1.0` | FileSystem caching is enabled by default for development                                   |
| `v16.0.0` | Beta release with separate flags for build and dev                                         |
| `v15.5.0` | Persistent caching released as experimental on canary releases                             |
