Configure TypeScript behavior with the `typescript` option in `next.config.js`:

```js filename="next.config.js"
module.exports = {
  typescript: {
    ignoreBuildErrors: false,
    tsconfigPath: 'tsconfig.json',
  },
}
```

## Options

| Option              | Type      | Default           | Description                                                      |
| ------------------- | --------- | ----------------- | ---------------------------------------------------------------- |
| `compilerPackage`   | `string`  | `'typescript'`    | Package providing a TypeScript-compatible compiler CLI.          |
| `ignoreBuildErrors` | `boolean` | `false`           | Allow production builds to complete even with TypeScript errors. |
| `tsconfigPath`      | `string`  | `'tsconfig.json'` | Path to a custom `tsconfig.json` file.                           |

## `compilerPackage`

Select an installed package that provides a TypeScript-compatible compiler CLI instead of the default `typescript` package. For example, to use [tsc-rs](https://github.com/pingdotgg/ts-rust), install `tsc-rs` as a development dependency and configure:

```js filename="next.config.js"
module.exports = {
  typescript: {
    compilerPackage: 'tsc-rs',
  },
}
```

The official `typescript` package is not required when using this option. Next.js uses the selected package for `next build`, `next dev` setup, `next typegen`, and reading TypeScript configuration (including path aliases). It continues to generate `next-env.d.ts` and route types and apply its recommended `tsconfig` settings.

The package must expose a Node.js CLI entry in its `bin` field, named `tsc` (including versioned names such as `tsc6`), or a single binary with any name. The CLI must support `--version`, `--showConfig`, `--project`, and the type-checking flags accepted by `tsc`. `--version` must report the compatible TypeScript version as `Version <version>`, which may differ from the package's release version. A custom checker can be packaged with a compatible CLI wrapper. Next.js does not load an alternative compiler's JavaScript API or guarantee its diagnostic or editor-plugin compatibility.

- [`experimental.useTypeScriptCli`](/docs/app/api-reference/config/next-config-js/useTypeScriptCli) must remain enabled (the default).
- `tsconfigPath` selects the project passed to the selected CLI.
- `ignoreBuildErrors` skips checking, including the selected CLI, but still performs TypeScript setup.
- If the configured package is missing, Next.js reports an installation error instead of falling back to or installing `typescript`.
- Type-check telemetry records that a custom CLI was used, without recording the package name or path.

## `ignoreBuildErrors`

Next.js fails your **production build** (`next build`) when TypeScript errors are present in your project.

If you'd like Next.js to dangerously produce production code even when your application has errors, you can disable the built-in type checking step.

Note that this completely skips the TypeScript type checking step. It does not run TypeScript and suppress errors, it bypasses the check entirely.

If disabled, be sure you are running type checks as part of your build or deploy process, otherwise this can be very dangerous.

```js filename="next.config.js"
module.exports = {
  typescript: {
    // !! WARN !!
    // Dangerously allow production builds to successfully complete even if
    // your project has type errors.
    // !! WARN !!
    ignoreBuildErrors: true,
  },
}
```

## `tsconfigPath`

Use a different TypeScript configuration file for builds or tooling:

```js filename="next.config.js"
module.exports = {
  typescript: {
    tsconfigPath: 'tsconfig.build.json',
  },
}
```

See the [TypeScript configuration](/docs/app/api-reference/config/typescript#custom-tsconfig-path) page for more details.
