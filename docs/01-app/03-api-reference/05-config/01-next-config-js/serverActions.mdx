Configure the allowed origins and request body size limit for Server Actions with `experimental.serverActions` in `next.config.js`. For how Server Actions work, see the [Server Actions guide](/docs/app/guides/server-actions).

## `allowedOrigins`

`experimental.serverActions.allowedOrigins` is a list of additional trusted hosts from which Server Actions can be invoked.

To prevent cross-site request forgery (CSRF), Next.js compares the host in the request's `Origin` header with `x-forwarded-host`, or `host` when `x-forwarded-host` is absent. A mismatch is rejected unless the origin host matches an entry in `allowedOrigins`. Requests without an `Origin` header bypass this comparison.

> **Good to know**: Server Actions are stable and enabled by default in Next.js 14 and later. The `allowedOrigins` and `bodySizeLimit` options remain experimental and must be configured under `experimental.serverActions`.

```js filename="next.config.js"
/** @type {import('next').NextConfig} */

module.exports = {
  experimental: {
    serverActions: {
      allowedOrigins: ['my-proxy.com', '*.my-proxy.com'],
    },
  },
}
```

### Host matching

Only the [`host`](https://developer.mozilla.org/en-US/docs/Web/API/URL/host) of the request's `Origin` header is matched against your entries, which is the hostname plus the port when the URL carries one. For a request from `https://my-proxy.com/checkout`, that is `my-proxy.com`. For one from `https://my-proxy.com:8443/checkout`, `my-proxy.com:8443`. Write your entries the same way.

Wildcard patterns match subdomains. `*` matches one subdomain level, and `**` matches one or more levels. Include a separate entry for the bare host, as in the example above.

| Entry               | Matches                                   | Does not match                          |
| ------------------- | ----------------------------------------- | --------------------------------------- |
| `my-proxy.com`      | `my-proxy.com`                            | `my-proxy.com:8443`, `app.my-proxy.com` |
| `*.my-proxy.com`    | `app.my-proxy.com`                        | `my-proxy.com`, `app.my-proxy.com:8443` |
| `**.my-proxy.com`   | `app.my-proxy.com`, `app.eu.my-proxy.com` | `my-proxy.com`                          |
| `my-proxy.com:8443` | `my-proxy.com:8443`                       | `my-proxy.com`                          |

Partial replacement is not supported. Write `*.my-proxy.com`, rather than `app-*.my-proxy.com`. Using `**` is only supported at the start of the pattern. A port cannot be wildcarded, so write it out in full: `my-proxy.com:8443`, or `*.my-proxy.com:8443` for its subdomains.

### Reverse proxies and development tunnels

No entry is needed when the reverse proxy forwards the browser-facing host in `x-forwarded-host`. If it forwards an internal host such as `localhost:3000` instead, add the browser-facing host to `allowedOrigins`.

The check runs in production as well as in development, so the list applies to your deployed app and not only to local work.

The top-level [`allowedDevOrigins`](/docs/app/api-reference/config/next-config-js/allowedDevOrigins) option controls access to development-server assets and endpoints separately. Add a tunnel hostname there if access to those resources is blocked. Add it to `experimental.serverActions.allowedOrigins` if Server Actions fail the host comparison. For a tunnel that needs both settings:

```js filename="next.config.js"
/** @type {import('next').NextConfig} */

module.exports = {
  allowedDevOrigins: ['*.tunnel.example.com'],
  experimental: {
    serverActions: {
      allowedOrigins: ['*.tunnel.example.com'],
    },
  },
}
```

## `bodySizeLimit`

The maximum request body size for a Server Action is **1 MB** by default. This limits the server resources used to parse large requests.

Set `experimental.serverActions.bodySizeLimit` to change the limit. The value can be a number of bytes, such as `1000`, or a size string, such as `'500kb'` or `'3mb'`.

```js filename="next.config.js"
/** @type {import('next').NextConfig} */

module.exports = {
  experimental: {
    serverActions: {
      bodySizeLimit: '2mb',
    },
  },
}
```

The limit applies to the entire HTTP request body. For `multipart/form-data` uploads, this includes files, form fields, boundaries, and part headers. Allow room for this overhead when choosing a limit for file uploads.

## Enabling Server Actions (v13)

In Next.js 13, enable Server Actions by setting `experimental.serverActions` to `true`:

```js filename="next.config.js"
/** @type {import('next').NextConfig} */
const config = {
  experimental: {
    serverActions: true,
  },
}

module.exports = config
```
