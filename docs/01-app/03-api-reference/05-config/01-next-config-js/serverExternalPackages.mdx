---
title: serverExternalPackages
description: Opt-out specific dependencies from the Server Components bundling and use native Node.js `require`.
---

Dependencies used inside [Server Components](/docs/app/getting-started/server-and-client-components) and [Route Handlers](/docs/app/api-reference/file-conventions/route) will automatically be bundled by Next.js.

If a dependency is using Node.js specific features, you can choose to opt-out specific dependencies from the Server Components bundling and use native Node.js `require`.

```js filename="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  serverExternalPackages: ['@acme/ui'],
}

module.exports = nextConfig
```

## Monorepos and symlinked packages

Packages listed in `serverExternalPackages` are also externalized when they resolve to a path outside of `node_modules`. This is the case for workspace packages in a monorepo (for example, pnpm `workspace:*` dependencies), which are symlinked into `node_modules` and resolve to their real location in the workspace.

At runtime, Node.js loads these packages from their real location, and their files are included in the [output file tracing](/docs/app/api-reference/config/next-config-js/output).

This behavior is controlled by the experimental `serverExternalPackagesMonorepo` option, which defaults to `true`. Set it to `false` to bundle packages that resolve outside of `node_modules`, even when they are listed in `serverExternalPackages`:

```js filename="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  serverExternalPackages: ['my-workspace-pkg'],
  experimental: {
    serverExternalPackagesMonorepo: false,
  },
}

module.exports = nextConfig
```
