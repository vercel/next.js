You can mutate data in Next.js using [React Server Functions](https://react.dev/reference/rsc/server-functions), which run on the server and write directly to your database or filesystem. This page will go through how you can [create](#creating-server-functions) and [invoke](#invoking-server-functions) Server Functions, how to [revalidate](#revalidating-the-cache) the content that changed, and how to [show progress and errors](#making-it-feel-responsive) while the write is in flight. To handle a write from a caller that isn't your own frontend, such as a webhook, use a [Route Handler](/docs/app/api-reference/file-conventions/route).

For Next.js-specific behaviors (single-roundtrip response, sequential dispatch, security, deployment), see [Server Actions and Mutations](/docs/app/guides/server-actions).

## What are Server Functions?

A **Server Function** is an asynchronous function that runs on the server. You can call one from the client through a network request, which is why it must be async. In an `action` or mutation context they are also called **Server Actions**, and that is the form the rest of this page uses.

> [!WARNING]
> Server Functions are reachable via direct POST requests, not just through your application's UI. Always verify authentication and authorization inside every Server Function. See the [Data Security guide](/docs/app/guides/data-security#authentication-and-authorization) for recommended patterns.

## Creating Server Functions

A Server Function is defined with the [`use server`](https://react.dev/reference/rsc/use-server) directive. Where you put the directive decides what it covers.

**At the top of a file**, it marks every export in that file as a Server Function. This is the usual choice: it keeps writes in one place, and it is the only form a Client Component can import from.

```ts filename="app/lib/actions.ts" switcher
'use server'

import { auth } from '@/lib/auth'

export async function createPost(formData: FormData) {
  const session = await auth()
  if (!session?.user) {
    throw new Error('Unauthorized')
  }
  // Mutate data
  // Revalidate cache
}

export async function deletePost(formData: FormData) {
  const session = await auth()
  if (!session?.user) {
    throw new Error('Unauthorized')
  }
  // Verify the user owns this resource before deleting
  // Mutate data
  // Revalidate cache
}
```


Every export in a `use server` file must be `async`, and the file must not export anything that is not a Server Function.

The directive can also go at the top of a single function, including one declared inside a Server Component. See [`use server`](/docs/app/api-reference/directives/use-server) for those placements and the rules that come with each.

### Passing actions as props

Instead of importing a Server Function inside a Client Component, a Server Component can pass one down as a prop. This keeps the Client Component generic: it knows it submits a form, not which write it performs, so the same component can be reused with a different action. It is also how you hand down an action that was created with values only the server has, such as an id closed over by the parent.

Server Functions are the one kind of function that can cross the boundary this way, as a reference rather than as code:

```jsx
<ClientComponent updateItemAction={updateItem} />
```

```tsx filename="app/client-component.tsx" switcher
'use client'

export default function ClientComponent({
  updateItemAction,
}: {
  updateItemAction: (formData: FormData) => void
}) {
  return <form action={updateItemAction}>{/* ... */}</form>
}
```

```jsx filename="app/client-component.js" switcher
'use client'

export default function ClientComponent({ updateItemAction }) {
  return <form action={updateItemAction}>{/* ... */}</form>
}
```

## Invoking Server Functions

A mutation is triggered either by a form submission or by an event handler in a Client Component.

### Forms

React extends the HTML [`<form>`](https://react.dev/reference/react-dom/components/form) element so a Server Function can be passed to the `action` prop. This works in Server and Client Components alike, and in a Server Component it works before JavaScript loads:

```tsx filename="app/ui/form.tsx" switcher
import { createPost } from '@/app/actions'

export function Form() {
  return (
    <form action={createPost}>
      <input type="text" name="title" />
      <input type="text" name="content" />
      <button type="submit">Create</button>
    </form>
  )
}
```

```jsx filename="app/ui/form.js" switcher
import { createPost } from '@/app/actions'

export function Form() {
  return (
    <form action={createPost}>
      <input type="text" name="title" />
      <input type="text" name="content" />
      <button type="submit">Create</button>
    </form>
  )
}
```

The action receives the [`FormData`](https://developer.mozilla.org/docs/Web/API/FormData/FormData) object and reads fields with `formData.get()`, as in `createPost` above.

### Event Handlers

Outside a form, invoke a Server Function from an event handler such as `onClick`. Wrap the call in [`startTransition`](https://react.dev/reference/react/useTransition), which gives you a pending flag and lets a failure reach the nearest error boundary:

```tsx filename="app/like-button.tsx" highlight={4,8,14-19} switcher
'use client'

import { incrementLike } from './actions'
import { useState, useTransition } from 'react'

export default function LikeButton({ initialLikes }: { initialLikes: number }) {
  const [likes, setLikes] = useState(initialLikes)
  const [isPending, startTransition] = useTransition()

  return (
    <>
      <p>Total Likes: {likes}</p>
      <button
        disabled={isPending}
        onClick={() =>
          startTransition(async () => {
            const updatedLikes = await incrementLike()
            startTransition(() => setLikes(updatedLikes))
          })
        }
      >
        Like
      </button>
    </>
  )
}
```

```jsx filename="app/like-button.js" highlight={4,8,14-19} switcher
'use client'

import { incrementLike } from './actions'
import { useState, useTransition } from 'react'

export default function LikeButton({ initialLikes }) {
  const [likes, setLikes] = useState(initialLikes)
  const [isPending, startTransition] = useTransition()

  return (
    <>
      <p>Total Likes: {likes}</p>
      <button
        disabled={isPending}
        onClick={() =>
          startTransition(async () => {
            const updatedLikes = await incrementLike()
            startTransition(() => setLikes(updatedLikes))
          })
        }
      >
        Like
      </button>
    </>
  )
}
```

The inner `startTransition` is not a typo. React loses the transition scope across an `await`, so a state update after one has to be wrapped again to stay part of the transition. This applies after [every `await`](https://react.dev/reference/react/useTransition#react-doesnt-treat-my-state-update-after-await-as-a-transition), and it is why holding server data in local state is often more trouble than letting revalidation deliver it as a prop.

Calling the function directly in the handler without a transition also works, but you get no pending flag and a rejected promise has nowhere to go, so the click appears to do nothing. [Making it feel responsive](#making-it-feel-responsive) covers the rest.

## Revalidating the cache

The write has landed on the server, but anything [cached](/docs/app/getting-started/caching) still holds the old value. Label a cache entry with [`cacheTag`](/docs/app/getting-started/caching#cachetag), then invalidate that label after writing:

```tsx filename="app/lib/actions.ts" highlight={1,12} switcher
import { updateTag } from 'next/cache'
import { redirect } from 'next/navigation'

export async function createPost(formData: FormData) {
  const post = await db.post.create({
    data: {
      title: formData.get('title'),
      content: formData.get('content'),
    },
  })

  updateTag('posts')
  redirect(`/posts/${post.id}`)
}
```

```jsx filename="app/lib/actions.js" highlight={1,12} switcher
import { updateTag } from 'next/cache'
import { redirect } from 'next/navigation'

export async function createPost(formData) {
  const post = await db.post.create({
    data: {
      title: formData.get('title'),
      content: formData.get('content'),
    },
  })

  updateTag('posts')
  redirect(`/posts/${post.id}`)
}
```

[`updateTag`](/docs/app/api-reference/functions/updateTag) expires the tag immediately, so the user sees their own write rather than stale content. It is the right default after a mutation, and it works only in Server Actions.

Three others exist for cases where that is not what you want:

- [`revalidateTag`](/docs/app/api-reference/functions/revalidateTag) refreshes in the background instead, serving stale content meanwhile. Use it when a delay is fine, and when you need to invalidate from a Route Handler.
- [`revalidatePath`](/docs/app/api-reference/functions/revalidatePath) invalidates a whole route path, for when you do not know which tags it depends on.
- [`refresh`](/docs/app/api-reference/functions/refresh) re-renders the current route without invalidating anything, for data that was never cached.

For which one to reach for, including how each interacts with the re-render that ships in the action's response, see [Choosing a cache update](/docs/app/guides/server-actions#choosing-a-cache-update).

## Making it feel responsive

A write travels to the server and back. Until it returns the interface has to say something, and if it fails someone has to hear about it.

### Pending state

Wrap the call in a transition and use the flag it hands you. [`useTransition`](https://react.dev/reference/react/useTransition) is the default choice, because it works the same way for event handlers, forms, and anything else:

```tsx filename="app/ui/create-post-button.tsx" switcher
'use client'

import { useTransition } from 'react'
import { createPost } from '@/app/lib/actions'
import { LoadingSpinner } from '@/app/ui/loading-spinner'

export function CreatePostButton() {
  const [isPending, startTransition] = useTransition()

  return (
    <button disabled={isPending} onClick={() => startTransition(createPost)}>
      {isPending ? <LoadingSpinner /> : 'Create Post'}
    </button>
  )
}
```

```jsx filename="app/ui/create-post-button.js" switcher
'use client'

import { useTransition } from 'react'
import { createPost } from '@/app/lib/actions'
import { LoadingSpinner } from '@/app/ui/loading-spinner'

export function CreatePostButton() {
  const [isPending, startTransition] = useTransition()

  return (
    <button disabled={isPending} onClick={() => startTransition(createPost)}>
      {isPending ? <LoadingSpinner /> : 'Create Post'}
    </button>
  )
}
```

Inside a `<form action={...}>`, React starts the transition for you, so there is no `startTransition` to write. Read the pending flag with [`useFormStatus`](https://react.dev/reference/react-dom/hooks/useFormStatus) from a component rendered inside that form.

Reach for [`useActionState`](https://react.dev/reference/react/useActionState) when you need the value the function returned, such as a validation message to show next to a field. It reports pending too, but the return value is the reason to pick it.

### Optimistic updates

A pending spinner tells the user to wait. An optimistic update skips the wait by showing the expected result immediately, then reconciling when the server answers. [`useOptimistic`](https://react.dev/reference/react/useOptimistic) handles the reverting for you if the write fails:

```tsx filename="app/ui/like-button.tsx" switcher
'use client'

import { useOptimistic, useTransition } from 'react'
import { incrementLike } from '@/app/lib/actions'

export function LikeButton({ likes }: { likes: number }) {
  const [, startTransition] = useTransition()
  const [optimisticLikes, addOptimisticLike] = useOptimistic(
    likes,
    (current, amount: number) => current + amount
  )

  return (
    <button
      onClick={() =>
        startTransition(async () => {
          addOptimisticLike(1)
          await incrementLike()
        })
      }
    >
      {optimisticLikes} likes
    </button>
  )
}
```

```jsx filename="app/ui/like-button.js" switcher
'use client'

import { useOptimistic, useTransition } from 'react'
import { incrementLike } from '@/app/lib/actions'

export function LikeButton({ likes }) {

    likes,

    </button>

```

The optimistic value only applies while the transition is running, so `addOptimisticLike` has to be called inside it. `likes` arrives as a prop from a Server Component, and `incrementLike` revalidates the tag it belongs to, so the confirmed value comes back through a re-render rather than through local state.

### Handling errors

Split failures by whether you expected them.

**Expected failures**, such as a rejected form field or a name already taken, are part of the interface. Return them from the Server Function instead of throwing, and render them with `useActionState`.

**Unexpected failures**, such as the database being unreachable, should throw. An error thrown inside a transition propagates to the nearest error boundary, which is what makes the transition worth using even when you do not need the pending flag. Without one, a rejected promise has nowhere to go and the click silently does nothing. [Error handling](/docs/app/getting-started/error-handling) covers where boundaries go.

See the [Building interactive apps](/docs/app/guides/interactive-apps) guide for a step-by-step walkthrough of all three, including forms, filters, and moving items between lists.

> **Good to know**: With the **experimental** [`useOffline`](/docs/app/guides/offline-support) config enabled, a Server Action interrupted by a connectivity drop stays pending and completes when the network returns.

## Examples

### Redirect after a mutation

You may want to redirect the user to a different page after a mutation. You can do this by calling [`redirect`](/docs/app/api-reference/functions/redirect) within the Server Function.

```ts filename="app/lib/actions.ts" switcher
'use server'

import { auth } from '@/lib/auth'
import { revalidatePath } from 'next/cache'
import { redirect } from 'next/navigation'

export async function createPost(formData: FormData) {
  const session = await auth()
  if (!session?.user) {
    throw new Error('Unauthorized')
  }
  // Mutate data
  // ...

  revalidatePath('/posts')
  redirect('/posts')
}
```

```js filename="app/lib/actions.js" switcher
'use server'

import { auth } from '@/lib/auth'
import { revalidatePath } from 'next/cache'
import { redirect } from 'next/navigation'

export async function createPost(formData) {
  const session = await auth()
  if (!session?.user) {
    throw new Error('Unauthorized')
  }
  // Mutate data
  // ...

  revalidatePath('/posts')
  redirect('/posts')
}
```

Calling `redirect` [throws](/docs/app/api-reference/functions/redirect#behavior) a framework handled control-flow exception. Any code after it won't execute. If you need fresh data, call [`revalidatePath`](/docs/app/api-reference/functions/revalidatePath) or [`revalidateTag`](/docs/app/api-reference/functions/revalidateTag) beforehand.

### Cookies

You can `get`, `set`, and `delete` cookies inside a Server Action using the [`cookies`](/docs/app/api-reference/functions/cookies) API.

When you [set or delete](/docs/app/api-reference/functions/cookies#understanding-cookie-behavior-in-server-functions) a cookie in a Server Action, Next.js re-renders the current page and its layouts on the server so the **UI reflects the new cookie value**.

> **Good to know**: The server update applies to the current React tree, re-rendering, mounting, or unmounting components, as needed. Client state is preserved for re-rendered components, and effects re-run if their dependencies changed.

```ts filename="app/actions.ts" switcher
'use server'

import { cookies } from 'next/headers'

export async function exampleAction() {
  const cookieStore = await cookies()

  // Get cookie
  cookieStore.get('name')?.value

  // Set cookie
  cookieStore.set('name', 'Delba')

  // Delete cookie
  cookieStore.delete('name')
}
```

```js filename="app/actions.js" switcher
'use server'

import { cookies } from 'next/headers'

export async function exampleAction() {
  // Get cookie
  const cookieStore = await cookies()

  // Get cookie
  cookieStore.get('name')?.value

  // Set cookie
  cookieStore.set('name', 'Delba')

  // Delete cookie
  cookieStore.delete('name')
}
```

### useEffect

You can use the React [`useEffect`](https://react.dev/reference/react/useEffect) hook to invoke a Server Action when the component mounts or a dependency changes. This is useful for mutations that depend on global events or need to be triggered automatically. For example, `onKeyDown` for app shortcuts, an intersection observer hook for infinite scrolling, or when the component mounts to update a view count:

```tsx filename="app/view-count.tsx" switcher
'use client'

import { incrementViews } from './actions'
import { useState, useEffect, useTransition } from 'react'

export default function ViewCount({ initialViews }: { initialViews: number }) {
  const [views, setViews] = useState(initialViews)
  const [isPending, startTransition] = useTransition()

  useEffect(() => {
    startTransition(async () => {
      const updatedViews = await incrementViews()
      startTransition(() => setViews(updatedViews))
    })
  }, [])

  // You can use `isPending` to give users feedback
  return <p>Total Views: {views}</p>
}
```
