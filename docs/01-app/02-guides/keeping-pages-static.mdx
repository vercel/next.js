Before Cache Components, you chose a rendering mode for an entire route. [Route segment configs](/docs/app/guides/caching-without-cache-components#dynamic) such as `dynamic = 'force-static'`, `dynamic = 'force-dynamic'`, and `dynamic = 'error'` controlled whether Next.js prerendered the route, rendered it on demand, or failed when it could not be prerendered.

[Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) lets a route combine prerendered UI, cached content, and request-specific content. Use [`ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) when part or all of the route must remain static. Next.js defers request-specific content to a later stage when possible and reports an error when the required output cannot be static.

## Decide what should stay static

Static output does not depend on request-specific data. Next.js can generate it before a request and reuse it across requests.

With [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching), Next.js can prepare a route in three [navigation stages](/docs/app/glossary#navigation-stages):

1. A default `<Link>` loads the App Shell.
2. `<Link prefetch={true}>` can also load content for that link's URL.
3. The navigation renders anything that remains after the click.

Each `ensureStatic` level requires one more stage to be static. In the following diagram, gray marks static output and blue marks content that can render at request time:

Choose a level by how much of the route must be static:

- `'shell'`: the [App Shell](/docs/app/glossary#app-shell), which a default `<Link>` loads and all links to the route share.
- `'prefetch'`: the App Shell and the per-link prefetch from `<Link prefetch={true}>`, which can include content for the link's [URL data](/docs/app/glossary#url-data), such as `params`.
- `'navigation'`: the complete route, including what the navigation returns.

A page can set a stricter level than its layout. The following example uses each level for a different part of a store.

## Example

The example builds an online store with these App Router routes and supporting modules:

```txt
app/
├── store/
│   ├── layout.tsx         # Shared layout with the cart
│   ├── page.tsx           # Product catalog
│   ├── products/
│   │   └── [slug]/
│   │       └── page.tsx   # Product details and live inventory
│   └── guides/
│       └── [id]/
│           └── page.tsx   # Editorial buying guides
└── ui/
    ├── cart.tsx
    └── product.tsx
lib/
└── guides.ts
```

Enable [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) and [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching):

```ts filename="next.config.ts" highlight={4,5}
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}

export default nextConfig
```

### Step 1: Serve a static App Shell

The starting app already places request-specific UI behind `<Suspense>`. The shared store layout includes a `CartButton` that reads the cart count from a cookie:

```tsx filename="app/ui/cart.tsx"
import { cookies } from 'next/headers'

export async function CartButton() {
  const value = Number((await cookies()).get('cart-count')?.value ?? 0)
  return <button>Cart ({value})</button>
}
```

The layout renders a static cart fallback while the current count loads:

```tsx filename="app/store/layout.tsx"
import Link from 'next/link'
import { Suspense } from 'react'
import { CartButton } from '@/app/ui/cart'

export default function StoreLayout({ children }: LayoutProps<'/store'>) {
  return (
    <>
      <nav>
        <Link href="/store">Products</Link>
        <Link href="/store/guides">Buying guides</Link>
        <Suspense fallback={<button>Cart (0)</button>}>
          <CartButton />
        </Suspense>
      </nav>
      <main>{children}</main>
    </>
  )
}
```

The cookie makes the App Shell specific to each visitor, so Next.js renders it on the server. Add `ensureStatic = 'shell'` to require a static App Shell instead:

```tsx filename="app/store/layout.tsx" highlight={5}
import Link from 'next/link'
import { Suspense } from 'react'
import { CartButton } from '@/app/ui/cart'

export const ensureStatic = 'shell'

export default function StoreLayout({ children }: LayoutProps<'/store'>) {
  // ...
}
```

A default `<Link>` into the store now loads a static App Shell. It shows the `Cart (0)` fallback. A per-link prefetch or navigation replaces the fallback with the current cart count.

If only `CartButton` needed to stay out of the runtime App Shell, you could call [`await prefetch()`](/docs/app/api-reference/functions/prefetch) inside that subtree. In this example, the entire store shell must remain static, including after future changes, so the layout sets `ensureStatic = 'shell'`.

### Step 2: Serve static product prefetches

The catalog uses `prefetch={true}` for each product link:

```tsx filename="app/store/page.tsx"
<Link href="/store/products/coffee-grinder" prefetch={true}>
  Coffee grinder
</Link>
```

Product pages combine product details, which rarely change, with inventory that changes as orders come in. `ProductDetails` caches its query with [`use cache`](/docs/app/api-reference/directives/use-cache). `Inventory` reads the current stock level for each request:

```tsx filename="app/ui/product.tsx"
import { db } from '@/lib/db'

type Params = Promise<{ slug: string }>

export async function ProductDetails({ params }: { params: Params }) {
  const { slug } = await params
  const product = await getProduct(slug)
  return <h1>{product.name}</h1>
}

export async function Inventory({ params }: { params: Params }) {
  const { slug } = await params
  const { stock } = await db.inventory.findUniqueOrThrow({ where: { slug } })
  return <p>{stock} in stock</p>
}

async function getProduct(slug: string) {
  'use cache'
  return db.product.findUniqueOrThrow({ where: { slug } })
}
```

The product page renders each part in its own `<Suspense>` boundary, so the inventory query does not hold back the product details:

```tsx filename="app/store/products/[slug]/page.tsx"
import { Suspense } from 'react'
import { Inventory, ProductDetails } from '@/app/ui/product'

export default function ProductPage({
  params,
}: PageProps<'/store/products/[slug]'>) {
  return (
    <>
      <Suspense fallback={<p>Loading product...</p>}>
        <ProductDetails params={params} />
      </Suspense>
      <Suspense fallback={<p>Loading...</p>}>
        <Inventory params={params} />
      </Suspense>
    </>
  )
}
```

The layout's `'shell'` level does not require per-link prefetches to be static. Each product prefetch can still read the cart cookie and render on the server for the current visitor. On a catalog with many product links, each visible link can trigger a server render before the user clicks it.

Add `ensureStatic = 'prefetch'` to the product page:

```tsx filename="app/store/products/[slug]/page.tsx" highlight={4}
import { Suspense } from 'react'
import { Inventory, ProductDetails } from '@/app/ui/product'

export const ensureStatic = 'prefetch'

export default function ProductPage({
  params,
}: PageProps<'/store/products/[slug]'>) {
  // ...
}
```

Next.js now uses only static output for each product prefetch instead of rendering it for the current visitor. Inventory renders after the user follows the link.

A level applies to the whole route, including the layouts above the segment that sets it. On product routes, `'prefetch'` also covers the store layout. The per-link prefetch contains the cart fallback, and the current count renders during navigation. The catalog keeps the layout's `'shell'` level.

If only one subtree needed to stay out of per-link prefetches, you could call [`await navigation()`](/docs/app/api-reference/functions/navigation) inside that subtree. Here, every per-link prefetch for a product route must remain static, so the page sets `ensureStatic = 'prefetch'`.

### Step 3: Prerender the buying guides

The guide page reads a theme preference from `cookies()` and reads `params` inside `<Suspense>`:

```tsx filename="app/store/guides/[id]/page.tsx"
import { Suspense } from 'react'
import { cookies } from 'next/headers'

export default function GuidePage({ params }: PageProps<'/store/guides/[id]'>) {
  return (
    <Suspense fallback={<p>Loading guide...</p>}>
      <Guide params={params} />
    </Suspense>
  )
}

async function Guide({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const theme = (await cookies()).get('theme')?.value
  return <article data-theme={theme}>Buying guide: {id}</article>
}
```

Run `next build`. The build produces a partial prerender for the route:

```text filename="Terminal"
Route (app)
└ ◐ /store/guides/[id]

◐  (Partial Prerender)  prerendered as static HTML with dynamic server-streamed content
```

Buying guides are editorial pages, so the complete page should be static. Add `ensureStatic = 'navigation'`:

```diff filename="app/store/guides/[id]/page.tsx"
  import { Suspense } from 'react'
  import { cookies } from 'next/headers'

+ export const ensureStatic = 'navigation'

  export default function GuidePage({ params }) {
    // ...
  }
```

Run `next build` again. To prerender a dynamic route, Next.js needs parameter values. The guide route does not export `generateStaticParams()`, so the build stops before rendering it:

```bash filename="Terminal"
Error: Page "/store/guides/[id]": `ensureStatic = "navigation"` requires an exported `generateStaticParams()` function.
Learn more: https://nextjs.org/docs/messages/generate-static-params#with-ensurestatic
    at ignore-listed frames
> Build error occurred
Error: Failed to collect page data for /store/guides/[id]
```

Export `generateStaticParams()` and return at least one buying guide ID. Next.js prerenders the returned IDs during the build. Other allowed IDs can still be generated on demand and stored in the ISR cache. With `'navigation'`, the first request waits for the complete static page instead of receiving a fallback shell. See [ISR with Cache Components](/docs/app/guides/incremental-static-regeneration-cache-components#at-runtime).

```tsx filename="app/store/guides/[id]/page.tsx" highlight={3,7-10}
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { getGuideIds } from '@/lib/guides'

export const ensureStatic = 'navigation'

export async function generateStaticParams() {
  const ids = await getGuideIds()
  return ids.map((id) => ({ id }))
}

export default function GuidePage({ params }: PageProps<'/store/guides/[id]'>) {
  return (
    <Suspense fallback={<p>Loading guide...</p>}>
      <Guide params={params} />
    </Suspense>
  )
}

async function Guide({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const theme = (await cookies()).get('theme')?.value
  return <article data-theme={theme}>Buying guide: {id}</article>
}
```

`generateStaticParams()` provides the parameter values, but it does not make request-time data or uncached data static.

Run `next build` again. The build confirms that the route is not fully static, but its abbreviated output does not identify the source:

```bash filename="Terminal"
Error: Route "/store/guides/[id]": Next.js encountered uncached or runtime data on a route that must be fully static.

This route is configured to be fully static, but uncached or runtime data prevents it from being fully prerendered.

Ways to fix this:
  - [cache] For uncached data (`fetch`, database calls): cache the access with `"use cache"` (does not apply to `connection()`)
  - [remove] Remove the data access
  - [client] Read search params on the client with `useSearchParams()` (only applies to `searchParams`)

Learn more: https://nextjs.org/docs/messages/static-route-dynamic
    at Suspense (<anonymous>)
    at nav (<anonymous>)
    at body (<anonymous>)
    at html (<anonymous>)
```

The build identifies the affected route, but it is difficult to use for locating each data access. Use `next dev` while fixing the route. Open `/store/guides/coffee` to rerun the same validation with source-mapped locations that update as you edit. For the equivalent build workflow, see [Find blocking work](/docs/app/guides/building#find-blocking-work).

`cookies()` is only available for a request, so the development overlay shows the [runtime data error](/docs/messages/static-route-runtime) twice: once for the theme cookie in `Guide`, and once for `CartButton` in the store layout.

The `'navigation'` setting on the guide page also applies to the store layout. Although `CartButton` is inside `<Suspense>`, no later server-rendering stage remains for the cart count. Deferring it with [`navigation()`](/docs/app/api-reference/functions/navigation) therefore does not satisfy the static requirement.

The build error covers both uncached and runtime data, so it includes three fix categories. In development, Next.js identifies these two accesses as runtime data and removes the cache option. The overlay shows the runtime-data fix set:

The client fix card applies only to `searchParams`, not `cookies()`. Buying guides do not need a per-user theme, so remove the cookie access from `Guide`:

```diff filename="app/store/guides/[id]/page.tsx"
  import { Suspense } from 'react'
- import { cookies } from 'next/headers'
  import { getGuideIds } from '@/lib/guides'

  // ...

  async function Guide({ params }) {
    const { id } = await params
-   const theme = (await cookies()).get('theme')?.value
-   return <article data-theme={theme}>Buying guide: {id}</article>
+   return <article>Buying guide: {id}</article>
  }
```

The cart must still show the current visitor's count. Because the cookie is not `HttpOnly`, the browser can read it. Make `CartButton` a Client Component that suspends with [`use(browser())`](/docs/app/guides/single-page-applications#rendering-components-only-in-the-browser) during prerendering:

```tsx filename="app/ui/cart.tsx" highlight={1,7-8}
'use client'

import { use } from 'react'
import { browser } from 'react-dom'

export function CartButton() {
  use(browser('The cart count is stored in a cookie.'))
  return <button>Cart ({readCartCount()})</button>
}

function readCartCount() {
  const match = document.cookie.match(/(?:^|; )cart-count=(\d+)/)
  return Number(match?.[1] ?? 0)
}
```

During prerendering, `use(browser())` suspends, so the static output includes the `<Suspense>` fallback, `Cart (0)`. After the page loads, the browser replaces the fallback with the current count. The layout does not change, and the product pages keep their `'prefetch'` behavior.

Reload the page to confirm that both runtime data errors clear. Next, load the guide content from the database. Add a query alongside `getGuideIds()` in `lib/guides.ts`:

```ts filename="lib/guides.ts"
import { db } from '@/lib/db'

export async function getGuide(id: string) {
  return db.guide.findUniqueOrThrow({ where: { id } })
}
```

Call `getGuide()` from `Guide`, keeping the `ensureStatic` and `generateStaticParams()` exports:

```diff filename="app/store/guides/[id]/page.tsx"
  import { Suspense } from 'react'
- import { getGuideIds } from '@/lib/guides'
+ import { getGuide, getGuideIds } from '@/lib/guides'

  // ...

  async function Guide({ params }) {
    const { id } = await params
-   return <article>Buying guide: {id}</article>
+   const guide = await getGuide(id)
+   return <article>{guide.content}</article>
  }
```

Reload the page. Without caching, the database query would run for each request, which violates the static requirement. The development overlay shows the [uncached data error](/docs/messages/static-route-dynamic) with these fixes:

Buying-guide content is shared, so cache the query:

```ts filename="lib/guides.ts" highlight={4}
import { db } from '@/lib/db'

export async function getGuide(id: string) {
  'use cache'
  return db.guide.findUniqueOrThrow({ where: { id } })
}
```

Reload the page in development to confirm that the uncached data error clears. Then run `next build` to confirm that the guide pages and their content are fully prerendered.

If the guide data must load on every request, first confirm that the route no longer needs to be fully static. Then [remove the static requirement](/docs/messages/static-route-runtime#remove-the-static-requirement). Because `Guide` already renders inside `<Suspense>`, the route can show its fallback while the data loads.
