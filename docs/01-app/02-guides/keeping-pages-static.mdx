[Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) lets a single route combine a static shell, cached content, and request-specific content that streams in later. Before Cache Components, static and dynamic rendering were a route-level choice, made with [route segment configs](/docs/app/guides/caching-without-cache-components#dynamic) such as `dynamic = 'force-static'`.

Some routes must still avoid request-time server work, either to control compute costs or to stay fully prerendered as the code changes. [`ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) makes that requirement explicit, so a later change that adds request-time rendering is reported instead of going unnoticed.

## Example

As an example, this guide keeps parts of an online store static. The store has the following files:

```txt
app/
├── layout.tsx
├── store/
│   ├── layout.tsx         # Shared layout with the cart
│   ├── page.tsx           # Product catalog
│   ├── products/
│   │   └── [slug]/
│   │       └── page.tsx   # Product details and live inventory
│   └── guides/
│       └── [id]/
│           └── page.tsx   # Editorial buying guides
└── ui/
    ├── cart.tsx
    └── product.tsx
lib/
├── db.ts
├── guides.ts
└── products.ts
```

With [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching), Next.js loads a route in [navigation stages](/docs/app/glossary#navigation-stages): the App Shell, an optional per-link prefetch, and the navigation. Each `ensureStatic` level keeps one more stage static, and each step applies one level to a different part of the store. In the following diagram, gray marks output that must stay static, while blue marks work that can render later:

Enable [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) and [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching):

```ts filename="next.config.ts" highlight={4,5}
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}

export default nextConfig
```

### Step 1: Load the store layout without the cart

The store layout is shared by the catalog, product pages, and buying guides. Its navigation includes a `CartButton` that reads the cart count from a cookie:

```tsx filename="app/ui/cart.tsx"
import { cookies } from 'next/headers'

export async function CartButton({ count }: { count?: number }) {
  const value = count ?? Number((await cookies()).get('cart-count')?.value ?? 0)
  return <button>Cart ({value})</button>
}
```

When `count` is passed, `CartButton` skips the cookie read. The layout uses this for the `<Suspense>` fallback, so the fallback renders `Cart (0)` without request data:

```tsx filename="app/store/layout.tsx"
import Link from 'next/link'
import { Suspense } from 'react'
import { CartButton } from '@/app/ui/cart'

export default function StoreLayout({ children }: LayoutProps<'/store'>) {
  return (
    <>
      <nav>
        <Link href="/store">Products</Link>
        <Link href="/store/guides">Buying guides</Link>
        <Suspense fallback={<CartButton count={0} />}>
          <CartButton />
        </Suspense>
      </nav>
      <main>{children}</main>
    </>
  )
}
```

A default `<Link>` into the store loads the route's [App Shell](/docs/app/glossary#app-shell), which is the same for all links to that route. Because the layout reads a cookie, Next.js renders the App Shell on the server for each visitor, so the shell can include their cart count. Add `ensureStatic = 'shell'` so the App Shell comes from static output instead:

```tsx filename="app/store/layout.tsx" highlight={5}
import Link from 'next/link'
import { Suspense } from 'react'
import { CartButton } from '@/app/ui/cart'

export const ensureStatic = 'shell'

export default function StoreLayout({ children }: LayoutProps<'/store'>) {
  // ...
}
```

A default `<Link>` into the store now loads an App Shell that Next.js generates once, with the `Cart (0)` fallback in place of the cart. The cart count renders later, during a per-link prefetch or the navigation.

### Step 2: Prefetch product details

Product pages show product details, which rarely change, and live inventory, which changes as orders come in. `ProductDetails` caches its query with [`use cache`](/docs/app/api-reference/directives/use-cache), while `Inventory` reads the stock level for each request:

```tsx filename="app/ui/product.tsx"
import { db } from '@/lib/db'

type Params = Promise<{ slug: string }>

export async function ProductDetails({ params }: { params: Params }) {
  const { slug } = await params
  const product = await getProduct(slug)
  return <h1>{product.name}</h1>
}

export async function Inventory({ params }: { params: Params }) {
  const { slug } = await params
  const { stock } = await db.inventory.findUniqueOrThrow({ where: { slug } })
  return <p>{stock} in stock</p>
}

async function getProduct(slug: string) {
  'use cache'
  return db.product.findUniqueOrThrow({ where: { slug } })
}
```

The product page renders each part in its own `<Suspense>` boundary, so the inventory query does not hold back the product details:

```tsx filename="app/store/products/[slug]/page.tsx"
import { Suspense } from 'react'
import { Inventory, ProductDetails } from '@/app/ui/product'

export default function ProductPage({
  params,
}: PageProps<'/store/products/[slug]'>) {
  return (
    <>
      <Suspense fallback={<p>Loading product...</p>}>
        <ProductDetails params={params} />
      </Suspense>
      <Suspense fallback={<p>Checking availability...</p>}>
        <Inventory params={params} />
      </Suspense>
    </>
  )
}
```

A default `<Link>` loads only the App Shell. A `<Link prefetch={true}>` also loads a per-link prefetch, which can include static or cached content that depends on the link's [URL data](/docs/app/glossary#url-data), such as `params`. To load the product heading before the user clicks, the catalog page links to each product with `prefetch={true}`. Its `getProducts()` query is cached like `getProduct()`:

```tsx filename="app/store/page.tsx" highlight={10}
import Link from 'next/link'
import { getProducts } from '@/lib/products'

export default async function StorePage() {
  const products = await getProducts()
  return (
    <ul>
      {products.map((product) => (
        <li key={product.slug}>
          <Link href={`/store/products/${product.slug}`} prefetch={true}>
            {product.name}
          </Link>
        </li>
      ))}
    </ul>
  )
}
```

The layout's `'shell'` level does not cover these per-link prefetches. The store layout reads the cart cookie, so Next.js renders each per-link prefetch on the server for the current visitor. The prefetch can include their cart count. A catalog page with many product links causes a server render for each visible link on each visit, and the prefetched UI gives no sign of that work.

Add `ensureStatic = 'prefetch'` to the product page:

```tsx filename="app/store/products/[slug]/page.tsx" highlight={4}
import { Suspense } from 'react'
import { Inventory, ProductDetails } from '@/app/ui/product'

export const ensureStatic = 'prefetch'

export default function ProductPage({
  params,
}: PageProps<'/store/products/[slug]'>) {
  // ...
}
```

A per-link prefetch of a product now comes from static output that Next.js generates once per product and reuses for all visitors. It contains the product heading, the `Cart (0)` fallback, and the **Checking availability...** fallback. The cart count and the inventory render when the user follows the link.

A level applies to the whole route, including the layouts above the segment that sets it. On product routes, `'prefetch'` also covers the store layout, so the cart count moves to the navigation. The catalog keeps the layout's `'shell'` level.

The product pages are not generated at build time. On a new deployment, the first prefetch of a product serves the route's fallback shell, without the product heading. Next.js generates the page in the background, and later prefetches include the heading. See [ISR with Cache Components](/docs/app/guides/incremental-static-regeneration-cache-components#at-runtime).

### Step 3: Prerender the buying guides

Buying guides are editorial pages, so the complete page should be prerendered. The `'navigation'` level covers the last stage, so it requires the complete route to be static. The guide page reads a theme preference from `cookies()`, and like the product page, it reads `params` inside `<Suspense>`. Add `ensureStatic = 'navigation'` to it:

```tsx filename="app/store/guides/[id]/page.tsx" highlight={4}
import { Suspense } from 'react'
import { cookies } from 'next/headers'

export const ensureStatic = 'navigation'

export default function GuidePage({ params }: PageProps<'/store/guides/[id]'>) {
  return (
    <Suspense fallback={<p>Loading guide...</p>}>
      <Guide params={params} />
    </Suspense>
  )
}

async function Guide({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const theme = (await cookies()).get('theme')?.value
  return <article data-theme={theme}>Buying guide: {id}</article>
}
```

Run `next build`. A fully static route is prerendered at build time. Without `generateStaticParams()`, the build has no `id` values to prerender, so it stops before rendering the route:

```bash filename="Terminal"
Error: Page "/store/guides/[id]": `ensureStatic = "navigation"` requires an exported `generateStaticParams()` function.
Learn more: https://nextjs.org/docs/messages/generate-static-params#with-ensurestatic
    at ignore-listed frames
> Build error occurred
Error: Failed to collect page data for /store/guides/[id]
```

Export `generateStaticParams()` and return the buying guide IDs. Unlike a product page, a guide that was not prerendered has no fallback shell to serve, so Next.js waits for the page to be generated. Return all IDs so that the guides are ready at build time:

```tsx filename="app/store/guides/[id]/page.tsx" highlight={3,7-10}
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { getGuideIds } from '@/lib/guides'

export const ensureStatic = 'navigation'

export async function generateStaticParams() {
  const ids = await getGuideIds()
  return ids.map((id) => ({ id }))
}

export default function GuidePage({ params }: PageProps<'/store/guides/[id]'>) {
  return (
    <Suspense fallback={<p>Loading guide...</p>}>
      <Guide params={params} />
    </Suspense>
  )
}

async function Guide({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const theme = (await cookies()).get('theme')?.value
  return <article data-theme={theme}>Buying guide: {id}</article>
}
```

If the route has multiple dynamic segments, the returned objects must include all of them. See the [`generateStaticParams` error guide](/docs/messages/generate-static-params#with-ensurestatic) for the full requirement.

The product page can export `generateStaticParams()` too, for example to prerender featured products so their first prefetch includes the heading. Under `'prefetch'` it is optional.

Start the development server and open a guide URL. `cookies()` is only available for a request, so the development overlay shows the [runtime data error](/docs/messages/static-route-runtime) twice: once for the theme cookie in `Guide`, and once for `CartButton` in the store layout.

As with the product pages, `'navigation'` on the guide page also applies to the store layout. `CartButton` is inside `<Suspense>`, but `'navigation'` is the final stage, and no later stage can render it. The client fix only applies to `searchParams`. Buying guides do not need a per-user theme, so remove the cookie access from `Guide`:

```diff filename="app/store/guides/[id]/page.tsx"
  import { Suspense } from 'react'
- import { cookies } from 'next/headers'
  import { getGuideIds } from '@/lib/guides'

  // ...

  async function Guide({ params }) {
    const { id } = await params
-   const theme = (await cookies()).get('theme')?.value
-   return <article data-theme={theme}>Buying guide: {id}</article>
+   return <article>Buying guide: {id}</article>
  }
```

The cart is per-user, so it has to stay. The cart count is not an `HttpOnly` cookie, so the browser can read it instead. Make `CartButton` a Client Component that suspends with [`use(browser())`](/docs/app/guides/single-page-applications#rendering-components-only-in-the-browser) when it has no `count`:

```tsx filename="app/ui/cart.tsx" highlight={1,7-9}
'use client'

import { use } from 'react'
import { browser } from 'react-dom'

export function CartButton({ count }: { count?: number }) {
  if (count === undefined) {
    use(browser('The cart count is stored in a cookie.'))
  }
  return <button>Cart ({count ?? readCartCount()})</button>
}

function readCartCount() {
  const match = document.cookie.match(/(?:^|; )cart-count=(\d+)/)
  return Number(match?.[1] ?? 0)
}
```

During prerendering, `use(browser())` suspends, so the static output of the store routes includes the `<Suspense>` fallback, `Cart (0)`. The browser renders the real count after the page loads. The layout code stays the same, and the product pages keep their `'prefetch'` behavior.

Reload the page to confirm that both runtime data errors clear. Next, load the guide content from the database. Add a query alongside `getGuideIds()` in `lib/guides.ts`:

```ts filename="lib/guides.ts"
import { db } from '@/lib/db'

export async function getGuide(id: string) {
  return db.guide.findUniqueOrThrow({ where: { id } })
}
```

Call `getGuide()` from `Guide`, keeping the `ensureStatic` and `generateStaticParams()` exports:

```diff filename="app/store/guides/[id]/page.tsx"
  import { Suspense } from 'react'
- import { getGuideIds } from '@/lib/guides'
+ import { getGuide, getGuideIds } from '@/lib/guides'

  // ...

  async function Guide({ params }) {
    const { id } = await params
-   return <article>Buying guide: {id}</article>
+   const guide = await getGuide(id)
+   return <article>{guide.content}</article>
  }
```

If request-time rendering is intentional, first confirm that the route no longer needs to be fully static, then [remove the static requirement](/docs/messages/static-route-runtime#remove-the-static-requirement). `Guide` already renders inside `<Suspense>`, so the route shows the fallback while the data loads.
