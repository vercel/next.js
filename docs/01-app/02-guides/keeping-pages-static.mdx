Use [`ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) to prevent changes from accidentally adding request-time server rendering to a route's App Shell, per-link prefetch, or navigation output.

Use this guide after adopting [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) and deciding which data to cache or stream. `ensureStatic` is a final safeguard for a static site or route that must preserve specific static output as it evolves. If you are replacing `dynamic = 'force-static'`, first follow the [Cache Components migration guide](/docs/app/guides/migrating-to-cache-components#dynamic--force-static).

For example, an email app can require:

- A static inbox shell shared by every thread.
- A static per-link prefetch containing the selected thread's cached header.
- Message bodies to wait until the user opens the thread.

`ensureStatic` sets the route-wide requirement. To decide which content belongs in each stage, use [`prefetch()`](/docs/app/api-reference/functions/prefetch), [`navigation()`](/docs/app/api-reference/functions/navigation), and the [optimizing prefetching guide](/docs/app/guides/optimizing-prefetching).

## Example

The examples build a mail route in three stages:

| Stage             | Loaded when                           | Mail UI                                    |
| ----------------- | ------------------------------------- | ------------------------------------------ |
| App Shell         | A default `<Link>` becomes visible    | Inbox frame and thread loading state       |
| Per-link prefetch | A `<Link prefetch={true}>` is visible | Cached subject, sender, and thread actions |
| Navigation        | The user opens the thread             | Message bodies and other deferred content  |

Each later stage can include UI from earlier stages and add content that becomes available at that point. A per-link prefetch can add URL-specific UI to the App Shell, and the navigation renders the remaining content. The App Shell and per-link prefetch are partial results. Navigation produces the complete result.

On an initial load, Next.js serves a [static HTML shell](/docs/app/glossary#static-shell). With `ensureStatic = 'prefetch'`, it can include the same static or cached UI as a per-link prefetch, but it cannot include request-specific data.

See the [Next.js mail demo](https://next16-mail.vercel.app/) and its [source code](https://github.com/aurorascharff/next16-mail) for a complete example.

This guide requires [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents). The `'shell'` and `'prefetch'` levels also require [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching):

```ts filename="next.config.ts" highlight={4,5}
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}

export default nextConfig
```

Choose the level based on what the route needs:

| Route                                           | Typical approach                                                                                   |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Documentation, marketing page, or static blog   | Use `'navigation'` when all server output must remain static.                                      |
| Large or frequently revalidated product catalog | Cache product data with `use cache` and `cacheLife`, then use `'shell'` or `'prefetch'` if needed. |
| Dashboard, mail, or media app                   | Keep an earlier stage static while request-specific content renders during a later stage.          |

Fully static rendering is not the default goal for every route. Use the least restrictive level that preserves the experience and caching behavior you need.

## 1. Require a static App Shell

Set `ensureStatic = 'shell'` when the route's shared shell must not render per request:

```tsx filename="app/mail/layout.tsx" highlight={1}
export const ensureStatic = 'shell'

export default function MailLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <main>
      <nav>Inbox</nav>
      {children}
    </main>
  )
}
```

The shell can include static and cached content. Request-specific work behind `<Suspense>` moves to the per-link prefetch or navigation instead of making the shell render per request.

You can apply a similar cutoff to an individual subtree with [`await prefetch()`](/docs/app/api-reference/functions/prefetch). Use `'shell'` when the static App Shell is a route-wide requirement instead of adding the cutoff to every request-specific subtree.

## 2. Require static per-link prefetches

Set `ensureStatic = 'prefetch'` when both the shared shell and each per-link prefetch must be static:

```tsx filename="app/mail/[threadId]/page.tsx" highlight={4}
import { Suspense } from 'react'
import { cookies } from 'next/headers'

export const ensureStatic = 'prefetch'

export default function ThreadPage({ params }: PageProps<'/mail/[threadId]'>) {
  return (
    <>
      <Suspense fallback={<p>Loading thread...</p>}>
        <ThreadHeader params={params} />
      </Suspense>
      <Suspense fallback={<p>Loading messages...</p>}>
        <Messages params={params} />
      </Suspense>
    </>
  )
}

async function ThreadHeader({
  params,
}: {
  params: PageProps<'/mail/[threadId]'>['params']
}) {
  const { threadId } = await params
  const thread = await getThread(threadId)
  return <h1>{thread.subject}</h1>
}

async function Messages({
  params,
}: {
  params: PageProps<'/mail/[threadId]'>['params']
}) {
  const { threadId } = await params
  const userId = (await cookies()).get('user-id')?.value ?? 'anonymous'
  const messages = await db.messages.list({ threadId, userId })
  return (
    <ul>
      {messages.map((message) => (
        <li key={message.id}>{message.body}</li>
      ))}
    </ul>
  )
}

async function getThread(threadId: string) {
  'use cache'
  return db.threads.find(threadId)
}
```

Link to each thread with `prefetch={true}` so its cached, URL-specific header can be ready before the click:

```tsx filename="app/mail/thread-list.tsx" highlight={6}
import Link from 'next/link'

export function ThreadLink({ id, subject }: { id: string; subject: string }) {
  return (
    <Link href={`/mail/${id}`} prefetch={true}>
      {subject}
    </Link>
  )
}
```

The cached thread header can render in the per-link prefetch because the link supplies `threadId`. The request-specific messages wait until navigation completes the route.

You can apply a similar cutoff to an individual subtree with [`await navigation()`](/docs/app/api-reference/functions/navigation). Use `'prefetch'` when static App Shell and per-link prefetch output are route-wide requirements.

## 3. Require the complete route to be static

Set `ensureStatic = 'navigation'` when every server-rendered part of the route must be produced during prerendering:

```tsx filename="app/blog/[slug]/page.tsx" highlight={1}
export const ensureStatic = 'navigation'

export function generateStaticParams() {
  return [{ slug: 'welcome' }, { slug: 'roadmap' }]
}

export default async function Page({ params }: PageProps<'/blog/[slug]'>) {
  const { slug } = await params
  const post = await getPost(slug)
  return <article>{post.body}</article>
}

async function getPost(slug: string) {
  'use cache'
  return db.posts.find(slug)
}
```

Navigation is the complete route result. There is no later server-rendering stage, so request-specific server work produces a validation error. Client Components can still read browser data, and cached server data can be prerendered.

Use this level for routes such as documentation or marketing pages where request-time server rendering would be a regression. Setting it on the root layout applies the requirement to every route in the app. Prefer a nested layout or page when only one part of the app must remain static.

## Choose route-wide enforcement or a local cutoff

Use `ensureStatic` when the rendering requirement applies to the whole route. Use the functions when only one subtree should move to a later stage:

| Goal                                                      | Use                           |
| --------------------------------------------------------- | ----------------------------- |
| Require a static App Shell for the route                  | `ensureStatic = 'shell'`      |
| Move one subtree out of the App Shell                     | `await prefetch()`            |
| Require static App Shell and per-link prefetches          | `ensureStatic = 'prefetch'`   |
| Move one subtree out of every prefetch                    | `await navigation()`          |
| Require all server-rendered route output to remain static | `ensureStatic = 'navigation'` |

For guidance on choosing which links should resolve URL data and which content should wait until navigation, see [Optimizing prefetching](/docs/app/guides/optimizing-prefetching).
