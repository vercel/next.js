Before Cache Components, static and dynamic rendering were a route-level choice. [Route segment configs](/docs/app/guides/caching-without-cache-components#dynamic) such as `dynamic = 'force-static'`, `dynamic = 'force-dynamic'`, and `dynamic = 'error'` controlled whether the entire route was prerendered, rendered on demand, or failed when it could not be prerendered.

[Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) moves this boundary to the component and function level. A single route can have a static shell, cached content, and request-specific content that streams in later. Shared UI can render first without requiring the entire route to be static.

Some routes must still avoid request-time server work, to control compute costs or to stay fully prerendered as the codebase changes. [`ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) makes that requirement explicit, so a later change that adds request-time rendering is reported instead of going unnoticed.

## Decide what should stay static

Static output does not depend on request-specific data. Next.js can generate it before a request and reuse it across requests.

With [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching), Next.js loads a route's server-rendered output in stages, before and during a client navigation. These are the route's [navigation stages](/docs/app/glossary#navigation-stages):

1. A default `<Link>` loads the route's [App Shell](/docs/app/glossary#app-shell), which the links to that route share.
2. A `<Link prefetch={true}>` also loads static or cached content that depends on the link's [URL data](/docs/app/glossary#url-data), such as `params`. This is the per-link prefetch.
3. When the user follows the link, the navigation returns the rest of the route.

Each `ensureStatic` value extends the static requirement through one more stage. In the following diagram, gray marks output that must remain static, while blue marks work that can render later:

Choose the level by the last stage that must stay static:

- `'shell'` when the App Shell that a default `<Link>` loads must come from static output.
- `'prefetch'` when per-link prefetches must also come from static output.
- `'navigation'` when the complete route must be prerendered.

A page can set a stricter level than its layout. The following example uses each level for a different part of a store.

## Example

An online store has a shared layout with a cart, product pages with live inventory, and editorial buying guides.

Enable [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) and [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching):

```ts filename="next.config.ts" highlight={4,5}
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}

export default nextConfig
```

### Step 1: Load the store layout without the cart

The store layout is shared by the catalog, product pages, and buying guides. Its navigation includes a `CartButton` that reads the cart count from a cookie:

```tsx filename="app/ui/cart.tsx"
import { cookies } from 'next/headers'

export async function CartButton({ count }: { count?: number }) {
  const value = count ?? Number((await cookies()).get('cart-count')?.value ?? 0)
  return <button>Cart ({value})</button>
}
```

When `count` is passed, `CartButton` skips the cookie read. The layout uses this for the `<Suspense>` fallback, so the fallback renders `Cart (0)` without request data:

```tsx filename="app/store/layout.tsx"
import Link from 'next/link'
import { Suspense } from 'react'
import { CartButton } from '@/app/ui/cart'

export default function StoreLayout({ children }: LayoutProps<'/store'>) {
  return (
    <>
      <nav>
        <Link href="/store">Products</Link>
        <Link href="/store/guides">Buying guides</Link>
        <Suspense fallback={<CartButton count={0} />}>
          <CartButton />
        </Suspense>
      </nav>
      <main>{children}</main>
    </>
  )
}
```

Without `ensureStatic`, the App Shell that a default `<Link>` loads is rendered for each request, so it can include the cart count. Add `ensureStatic = 'shell'` so the App Shell comes from static output instead:

```tsx filename="app/store/layout.tsx" highlight={5}
import Link from 'next/link'
import { Suspense } from 'react'
import { CartButton } from '@/app/ui/cart'

export const ensureStatic = 'shell'

export default function StoreLayout({ children }: LayoutProps<'/store'>) {
  // ...
}
```

A default `<Link>` into the store now loads the App Shell from static output, with the `<Suspense>` fallback in place of the cart. The cart renders later, during a per-link prefetch or the navigation.

### Step 2: Prefetch product details

Product pages show product details, which rarely change, and live inventory, which changes with every order. `ProductDetails` caches its query with [`use cache`](/docs/app/api-reference/directives/use-cache), while `Inventory` reads the stock level for each request:

```tsx filename="app/ui/product.tsx"
import { db } from '@/lib/db'

type Params = Promise<{ slug: string }>

export async function ProductDetails({ params }: { params: Params }) {
  const { slug } = await params
  const product = await getProduct(slug)
  return <h1>{product.name}</h1>
}

export async function Inventory({ params }: { params: Params }) {
  const { slug } = await params
  const { stock } = await db.inventory.findUniqueOrThrow({ where: { slug } })
  return <p>{stock} in stock</p>
}

async function getProduct(slug: string) {
  'use cache'
  return db.product.findUniqueOrThrow({ where: { slug } })
}
```

The product page renders each part in its own `<Suspense>` boundary, so the inventory query does not hold back the product details:

```tsx filename="app/store/products/[slug]/page.tsx"
import { Suspense } from 'react'
import { Inventory, ProductDetails } from '@/app/ui/product'

export default function ProductPage({
  params,
}: PageProps<'/store/products/[slug]'>) {
  return (
    <>
      <Suspense fallback={<p>Loading product...</p>}>
        <ProductDetails params={params} />
      </Suspense>
      <Suspense fallback={<p>Checking availability...</p>}>
        <Inventory params={params} />
      </Suspense>
    </>
  )
}
```

A default `<Link>` loads only the App Shell. To include the product details in the prefetch, the catalog page links to each product with `prefetch={true}`. Its `getProducts()` query is cached like `getProduct()`:

```tsx filename="app/store/page.tsx" highlight={10}
import Link from 'next/link'
import { getProducts } from '@/lib/products'

export default async function StorePage() {
  const products = await getProducts()
  return (
    <ul>
      {products.map((product) => (
        <li key={product.slug}>
          <Link href={`/store/products/${product.slug}`} prefetch={true}>
            {product.name}
          </Link>
        </li>
      ))}
    </ul>
  )
}
```

That per-link prefetch includes the product heading and the **Checking availability...** fallback. The uncached inventory query runs after the user follows the link.

The layout's `'shell'` level only covers the App Shell. A product link resolves `params` in its per-link prefetch, so each of those prefetches renders on the server, and nothing in the UI shows that cost. Add `ensureStatic = 'prefetch'` to the product page so its per-link prefetches come from static output too:

```tsx filename="app/store/products/[slug]/page.tsx" highlight={4}
import { Suspense } from 'react'
import { Inventory, ProductDetails } from '@/app/ui/product'

export const ensureStatic = 'prefetch'

export default function ProductPage({
  params,
}: PageProps<'/store/products/[slug]'>) {
  // ...
}
```

A level applies to the whole route, including the layouts above the segment that sets it. On product routes, the cart now renders during the navigation, and the per-link prefetch includes its fallback next to the product heading.

No product page is generated at build time, so the first prefetch of a product on a new deployment serves the route's fallback shell, without the product heading. Next.js generates the page in the background, and later prefetches include the heading. See [ISR with Cache Components](/docs/app/guides/incremental-static-regeneration-cache-components#at-runtime).

### Step 3: Prerender the buying guides

Buying guides are editorial pages whose complete server output should remain static. Add `ensureStatic = 'navigation'` to the guide page. Start with a page that reads a theme preference from `cookies()`. Like the product page, it reads `params` inside `<Suspense>`, so the route's shell does not wait for URL data:

```tsx filename="app/store/guides/[id]/page.tsx" highlight={4}
import { Suspense } from 'react'
import { cookies } from 'next/headers'

export const ensureStatic = 'navigation'

export default function GuidePage({ params }: PageProps<'/store/guides/[id]'>) {
  return (
    <Suspense fallback={<p>Loading guide...</p>}>
      <Guide params={params} />
    </Suspense>
  )
}

async function Guide({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const theme = (await cookies()).get('theme')?.value
  return <article data-theme={theme}>Buying guide: {id}</article>
}
```

Run `next build`. A fully static route is prerendered at build time, but a dynamic route without `generateStaticParams()` has no `id` values to prerender, so the build stops before it renders the route:

```bash filename="Terminal"
Error: Page "/store/guides/[id]": `ensureStatic = "navigation"` requires an exported `generateStaticParams()` function.
Learn more: https://nextjs.org/docs/messages/generate-static-params#with-ensurestatic
    at ignore-listed frames
> Build error occurred
Error: Failed to collect page data for /store/guides/[id]
```

Export `generateStaticParams()` and return all buying guide IDs. The product pages rely on the fallback shell until a page is generated, but `'navigation'` has no later stage to fall back to, so this list must be complete:

```tsx filename="app/store/guides/[id]/page.tsx" highlight={3,7-10}
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { getGuideIds } from '@/lib/guides'

export const ensureStatic = 'navigation'

export async function generateStaticParams() {
  const ids = await getGuideIds()
  return ids.map((id) => ({ id }))
}

export default function GuidePage({ params }: PageProps<'/store/guides/[id]'>) {
  return (
    <Suspense fallback={<p>Loading guide...</p>}>
      <Guide params={params} />
    </Suspense>
  )
}

async function Guide({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const theme = (await cookies()).get('theme')?.value
  return <article data-theme={theme}>Buying guide: {id}</article>
}
```

If the route has multiple dynamic segments, the returned objects must include all of them. See the [`generateStaticParams` error guide](/docs/messages/generate-static-params#with-ensurestatic) for the full requirement.

The product page can export `generateStaticParams()` too, for example to prerender featured products so their first prefetch includes the heading. Under `'prefetch'` it is optional.

From here, work in development. Next.js [validates the `'navigation'` requirement during both `next dev` and `next build`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic#validation). In development, errors include source-mapped stack traces that update as you edit. Build output is more abbreviated, and the build stops at the first route that fails.

Start the development server and open a guide URL. `cookies()` is only available for a request, so the development overlay shows the [runtime data error](/docs/messages/static-route-runtime) twice: once for the theme cookie in `Guide`, and once for `CartButton` in the store layout.

The client fix only applies to `searchParams`. Buying guides do not need a per-user theme, so remove the cookie access from `Guide`:

```diff filename="app/store/guides/[id]/page.tsx"

- import { cookies } from 'next/headers'
  import { getGuideIds } from '@/lib/guides'

  // ...

  async function Guide({ params }) {
    const { id } = await params
-   const theme = (await cookies()).get('theme')?.value
-   return <article data-theme={theme}>Buying guide: {id}</article>
+   return <article>Buying guide: {id}</article>
  }
```

The cart is per-user, so it has to stay. The cart count is not an `HttpOnly` cookie, so the browser can read it instead. Make `CartButton` a Client Component that suspends with [`use(browser())`](/docs/app/guides/single-page-applications#rendering-components-only-in-the-browser) when it has no `count`:

```tsx filename="app/ui/cart.tsx" highlight={1,7-9}
'use client'

import { use } from 'react'
import { browser } from 'react-dom'

export function CartButton({ count }: { count?: number }) {
  if (count === undefined) {
    use(browser('The cart count is stored in a cookie.'))
  }
  return <button>Cart ({count ?? readCartCount()})</button>
}

function readCartCount() {
  const match = document.cookie.match(/(?:^|; )cart-count=(\d+)/)
  return Number(match?.[1] ?? 0)
}
```

During prerendering, `use(browser())` suspends, so the static output of the store routes includes the `<Suspense>` fallback, `Cart (0)`. The browser renders the real count after the page loads. The layout code stays the same, and the product pages keep their `'prefetch'` behavior.

Reload the page to confirm that both runtime data errors clear. Next, load the guide content from the database. Add a query alongside `getGuideIds()` in `lib/guides.ts`:

```ts filename="lib/guides.ts"
import { db } from '@/lib/db'

export async function getGuide(id: string) {
  return db.guide.findUniqueOrThrow({ where: { id } })
}
```

Call `getGuide()` from `Guide`, keeping the `ensureStatic` and `generateStaticParams()` exports:

```diff filename="app/store/guides/[id]/page.tsx"
  import { Suspense } from 'react'
- import { getGuideIds } from '@/lib/guides'
+ import { getGuide, getGuideIds } from '@/lib/guides'
```
