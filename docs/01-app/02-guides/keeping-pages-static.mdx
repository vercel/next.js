Before Cache Components, static and dynamic rendering were primarily a route-level choice. [Route segment configs](/docs/app/guides/caching-without-cache-components#dynamic) such as `dynamic = 'force-static'`, `dynamic = 'force-dynamic'`, and `dynamic = 'error'` controlled whether the entire route was prerendered, rendered on demand, or failed when it could not be prerendered.

[Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) moves this boundary to the component and function level. A single route can have a static shell, cached content, and request-specific content that streams in later. Shared UI can render first without requiring the entire route to be static.

Some routes must still avoid request-time server work to control compute costs or remain fully prerendered as the codebase changes. [`ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) makes that requirement explicit, so later changes cannot silently introduce request-time rendering.

## Decide what should stay static

Static output does not depend on request-specific data. Next.js can generate it before a request and reuse it across requests. With [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching), a default `<Link>` loads the destination's [App Shell](/docs/app/glossary#app-shell). Setting `prefetch={true}` can also load static or cached [URL-specific content](/docs/app/guides/optimizing-prefetching#resolve-url-data-at-prefetch-time). The navigation request returns the remaining server-rendered content after the user follows the link.

Each `ensureStatic` value extends the static requirement through another part of route loading. Gray marks output that must remain static, while blue marks work that can render later:

## Example

An online store has product data, live inventory, and buying guides. Its shared layout, product pages, and buying guides have different static requirements.

Enable [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) and [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching):

```ts filename="next.config.ts" highlight={4,5}
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}

export default nextConfig
```

### Step 1: Protect the storefront shell

The store layout is shared by the catalog, product pages, and buying guides. Add `ensureStatic = 'shell'` so its App Shell remains static as the app changes:

```tsx filename="app/store/layout.tsx" highlight={3}
import Link from 'next/link'

export const ensureStatic = 'shell'

export default function StoreLayout({ children }: LayoutProps<'/store'>) {
  return (
    <>
      <nav>
        <Link href="/store">Products</Link>
        <Link href="/store/guides">Buying guides</Link>
      </nav>
      <main>{children}</main>
    </>
  )
}
```

A default `<Link>` into the store loads this shell from static output. If a later change adds request-specific content behind `<Suspense>`, that content renders during a per-link prefetch or navigation instead of making the shell render per request.

To keep one subtree out of the App Shell, call [`await prefetch()`](/docs/app/api-reference/functions/prefetch) within that subtree. `ensureStatic = 'shell'` applies the same boundary across the route.

### Step 2: Prefetch product details, not live inventory

A product page separates its cached summary from live inventory with `<Suspense>`. Add `ensureStatic = 'prefetch'` so the shell and each per-link prefetch remain static:

```tsx filename="app/store/products/[slug]/page.tsx" highlight={4}
import { Suspense } from 'react'
import { Inventory, ProductDetails } from '@/app/ui/product'

export const ensureStatic = 'prefetch'

export default function ProductPage({
  params,
}: PageProps<'/store/products/[slug]'>) {
  return (
    <>
      <Suspense fallback={<p>Loading product...</p>}>
        <ProductDetails params={params} />
      </Suspense>
      <Suspense fallback={<p>Checking availability...</p>}>
        <Inventory params={params} />
      </Suspense>
    </>
  )
}
```

`ProductDetails` uses [`use cache`](/docs/app/api-reference/directives/use-cache), while `Inventory` reads uncached data.

Update the product links with `prefetch={true}` so each link can resolve its cached, URL-specific product details:

```tsx filename="app/store/page.tsx" highlight={1}
<Link href={`/store/products/${product.slug}`} prefetch={true}>
  {product.name}
</Link>
```

When a product link becomes visible, its prefetch includes the product heading and **Checking availability...** fallback. The uncached inventory query runs after the user follows the link.

Pause the next navigation in the Next.js DevTools to inspect this result. Resume the navigation to load the current inventory.

`ensureStatic = 'prefetch'` requires the output returned by a link prefetch to be static. It does not define which product UI must be ready when the user clicks.

[Instant Navigation validation](/docs/app/api-reference/file-conventions/route-segment-config/instant) surfaces work that would block a client navigation. Check the prefetched UI in the inspector, then add an [`instant()` test](/docs/app/guides/instant-navigation#prevent-regressions-with-e2e-tests) to prevent regressions, such as the product heading no longer being ready before the click. The test can pass whether the UI came from static output or a prefetch for the current client session.

To keep one subtree out of both the App Shell and per-link prefetches, call [`await navigation()`](/docs/app/api-reference/functions/navigation) within that subtree. `ensureStatic = 'prefetch'` applies the same boundary to every prefetch for the route.

### Step 3: Prerender every buying guide

Buying guides are editorial pages whose complete server output should remain static. The dynamic `[id]` route reads a theme from `cookies()` and loads each guide from an uncached database query. Add `ensureStatic = 'navigation'`:

```tsx filename="app/store/guides/[id]/page.tsx" highlight={4}
import { cookies } from 'next/headers'
import { getGuide } from '@/lib/guides'

export const ensureStatic = 'navigation'

export default async function GuidePage({
  params,
}: PageProps<'/store/guides/[id]'>) {
  const { id } = await params
  const theme = (await cookies()).get('theme')?.value
  const guide = await getGuide(id)
  return <article data-theme={theme}>{guide.content}</article>
}
```

The `'navigation'` requirement is [validated during both `next dev` and `next build`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic#validation). Start the development server and open a guide URL. Because Next.js does not know which `id` values to prerender, the development overlay reports that the route requires an exported `generateStaticParams()` function and links to the [`generateStaticParams` error guide](/docs/messages/generate-static-params#with-ensurestatic).

Export [`generateStaticParams()`](/docs/app/api-reference/functions/generate-static-params) and return every buying guide ID:

```tsx filename="app/store/guides/[id]/page.tsx" highlight={4,6-9}
import { cookies } from 'next/headers'
import { getGuide, getGuideIds } from '@/lib/guides'

export const ensureStatic = 'navigation'

export async function generateStaticParams() {
  const ids = await getGuideIds()
  return ids.map((id) => ({ id }))
}

export default async function GuidePage({
  params,
}: PageProps<'/store/guides/[id]'>) {
  const { id } = await params
  const theme = (await cookies()).get('theme')?.value
  const guide = await getGuide(id)
  return <article data-theme={theme}>{guide.content}</article>
}
```

If the route has multiple dynamic segments, every result must include all of them.

Reload the guide URL. Because `cookies()` is only available for a request, the development overlay shows the [runtime data error](/docs/messages/static-route-runtime) with these fixes:

Buying-guide content is shared, so cache the query:

```ts filename="lib/guides.ts" highlight={4}
import { db } from '@/lib/db'

export async function getGuide(id: string) {
  'use cache'
  return db.guide.findUniqueOrThrow({ where: { id } })
}
```

Reload the page in development. The static-route error clears. Run `next build` again to confirm that the returned guide IDs and their content are fully prerendered.

If the guide must read uncached or request-specific data, remove `ensureStatic = 'navigation'` instead. That changes the route's requirement and allows the data to render per request.
