Before Cache Components, route segment configs such as [`dynamic = 'force-static'`](/docs/app/guides/caching-without-cache-components#dynamic), `dynamic = 'force-dynamic'`, and `dynamic = 'error'` selected a rendering mode for an entire route. [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) lets one route combine prerendered UI, cached content, and request-specific content that streams later.

Use [`ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) when an App Shell, a per-link prefetch, or a complete route must avoid request-time server rendering. With the App Shell and per-link prefetch levels, request-specific content can render later behind `<Suspense>`. `next dev` and `next build` identify work that prevents the selected output from remaining static.

## Decide what should stay static

Static output does not depend on request-specific data. Next.js can generate it before a request and reuse it across requests.

With [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching), route output becomes available in three [navigation stages](/docs/app/glossary#navigation-stages):

1. A default `<Link>` loads the App Shell.
2. `<Link prefetch={true}>` can also load content for that link's URL.
3. The navigation renders anything that remains after the click.

Each `ensureStatic` level extends the static requirement through one of these stages. In the following diagram, gray marks static output and blue marks content that can render at request time:

Choose a level by how much of the route must be static:

- `'shell'`: the [App Shell](/docs/app/glossary#app-shell), which a default `<Link>` loads and all links to the route share.
- `'prefetch'`: the App Shell and the per-link prefetch from `<Link prefetch={true}>`, which can include content for the link's [URL data](/docs/app/glossary#url-data), such as `params`.
- `'navigation'`: the complete route, including what the navigation returns.

## Example

To see how each level works, we'll add static requirements to three parts of an online store: its shared cart, product pages, and buying guides.

```txt
app/
├── store/
│   ├── layout.tsx         # Shared layout with the cart
│   ├── page.tsx           # Product catalog
│   ├── products/
│   │   └── [slug]/
│   │       └── page.tsx   # Product details and live inventory
│   └── guides/
│       └── [id]/
│           └── page.tsx   # Editorial buying guides
└── ui/
    ├── cart.tsx
    └── product.tsx
lib/
└── guides.ts
```

Enable [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) and [Partial Prefetching](/docs/app/api-reference/config/next-config-js/partialPrefetching):

```ts filename="next.config.ts" highlight={4,5}
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
}

export default nextConfig
```

### Step 1: Serve a static App Shell

The shared store layout renders the cart count from a cookie. `CartButton` reads the cookie on the server:

```tsx filename="app/ui/cart.tsx"
import { cookies } from 'next/headers'

export async function CartButton() {
  const value = Number((await cookies()).get('cart-count')?.value ?? 0)
  return <button>Cart ({value})</button>
}
```

The layout places `CartButton` inside `<Suspense>` so it can show a static fallback while the current count loads:

```tsx filename="app/store/layout.tsx"
import Link from 'next/link'
import { Suspense } from 'react'
import { CartButton } from '@/app/ui/cart'

export default function StoreLayout({ children }: LayoutProps<'/store'>) {
  return (
    <>
      <nav>
        <Link href="/store">Products</Link>
        <Link href="/store/guides">Buying guides</Link>
        <Suspense fallback={<button>Cart (0)</button>}>
          <CartButton />
        </Suspense>
      </nav>
      <main>{children}</main>
    </>
  )
}
```

The shared navigation should load from static output, but the cart count can remain request-specific. The `'shell'` level matches this requirement: it keeps the App Shell static and allows the cart count to render during a later per-link prefetch or navigation. Add `ensureStatic = 'shell'` to the layout:

```tsx filename="app/store/layout.tsx" highlight={5}
import Link from 'next/link'
import { Suspense } from 'react'
import { CartButton } from '@/app/ui/cart'

export const ensureStatic = 'shell'

export default function StoreLayout({ children }: LayoutProps<'/store'>) {
  // ...
}
```

A default `<Link>` into the store now loads a static App Shell with the `Cart (0)` fallback. A per-link prefetch or navigation replaces the fallback with the current cart count.

If only `CartButton` needed to be deferred from the App Shell, you could call [`await prefetch()`](/docs/app/api-reference/functions/prefetch) inside that subtree. In this example, the static requirement applies to the entire store shell, including after future changes, so the layout sets `ensureStatic = 'shell'`.

### Step 2: Serve static product prefetches

The catalog uses `prefetch={true}` for each product link:

```tsx filename="app/store/page.tsx"
<Link href="/store/products/coffee-grinder" prefetch={true}>
  Coffee grinder
</Link>
```

The product page renders cached product details and the current inventory. `ProductDetails` uses [`use cache`](/docs/app/api-reference/directives/use-cache), while `Inventory` reads the stock level for each request:

```tsx filename="app/ui/product.tsx"
import { db } from '@/lib/db'

type Params = Promise<{ slug: string }>

export async function ProductDetails({ params }: { params: Params }) {
  const { slug } = await params
  const product = await getProduct(slug)
  return <h1>{product.name}</h1>
}

export async function Inventory({ params }: { params: Params }) {
  const { slug } = await params
  const { stock } = await db.inventory.findUniqueOrThrow({ where: { slug } })
  return <p>{stock} in stock</p>
}

async function getProduct(slug: string) {
  'use cache'
  return db.product.findUniqueOrThrow({ where: { slug } })
}
```

The page prerenders the catalog's product URL with [`generateStaticParams()`](/docs/app/api-reference/functions/generate-static-params) and places each component in its own `<Suspense>` boundary, so inventory can render later without holding back the product details:

```tsx filename="app/store/products/[slug]/page.tsx"
import { Suspense } from 'react'
import { Inventory, ProductDetails } from '@/app/ui/product'

export function generateStaticParams() {
  return [{ slug: 'coffee-grinder' }]
}

export default function ProductPage({
  params,
}: PageProps<'/store/products/[slug]'>) {
  return (
    <>
      <Suspense fallback={<p>Loading product...</p>}>
        <ProductDetails params={params} />
      </Suspense>
      <Suspense fallback={<p>Loading...</p>}>
        <Inventory params={params} />
      </Suspense>
    </>
  )
}
```

The layout's `'shell'` requirement does not cover per-link prefetches. Because the catalog sets `prefetch={true}` on every product link, each visible link can still trigger a server render before the click. To use static output for the product details and defer inventory until navigation, set `ensureStatic = 'prefetch'` on the product page:

```tsx filename="app/store/products/[slug]/page.tsx" highlight={4}
import { Suspense } from 'react'
import { Inventory, ProductDetails } from '@/app/ui/product'

export const ensureStatic = 'prefetch'

export default function ProductPage({
  params,
}: PageProps<'/store/products/[slug]'>) {
  // ...
}
```

The product prefetch now contains static product details and the cart fallback. Inventory and the current cart count render during navigation.

An `ensureStatic` value covers the whole route, including layouts above the segment that exports it, so `'prefetch'` also applies to the store layout on product routes. If only one subtree needed to stay out of per-link prefetches, you could call [`await navigation()`](/docs/app/api-reference/functions/navigation) inside that subtree instead. Here, every product prefetch must remain static.

### Step 3: Prerender the buying guides

Product prefetches now contain static product details, while live inventory waits until navigation. The store also includes editorial buying guides. Each guide loads its content from the database and reads a theme preference from a cookie:

```tsx filename="app/store/guides/[id]/page.tsx"
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { getGuide } from '@/lib/guides'

export default function GuidePage({ params }: PageProps<'/store/guides/[id]'>) {
  return (
    <Suspense fallback={<p>Loading guide...</p>}>
      <Guide params={params} />
    </Suspense>
  )
}

async function Guide({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const guide = await getGuide(id)
  const theme = (await cookies()).get('theme')?.value
  return <article data-theme={theme}>{guide.content}</article>
}
```

The existing `getGuide()` helper performs the database query:

```ts filename="lib/guides.ts"
import { db } from '@/lib/db'

export async function getGuide(id: string) {
  return db.guide.findUniqueOrThrow({ where: { id } })
}
```

`db` represents a real database adapter. An in-memory object does not perform uncached I/O, so it will not produce the validation errors used later in this step.

Before adding another static requirement, run `next build` to see how the store routes currently render. The output marks all three as partial prerenders because they still contain request-specific or uncached work:

```text filename="Terminal"
Route (app)
├ ◐ /store
├ ◐ /store/guides/[id]
└   /store/products/[slug]
  ├ ◐ /store/products/[slug]
  └ ◐ /store/products/coffee-grinder

◐  (Partial Prerender)  prerendered as static HTML with dynamic server-streamed content
```

Partial output is expected for the store and product routes because their cart count and inventory render later. Buying guides should instead be complete static pages. The `'navigation'` level matches this requirement: no later server-rendering stage remains, so the complete server output must be static. Add `ensureStatic = 'navigation'`:

```diff filename="app/store/guides/[id]/page.tsx"
  import { Suspense } from 'react'
  import { cookies } from 'next/headers'

+ export const ensureStatic = 'navigation'

  export default function GuidePage({ params }) {
    // ...
  }
```

Run `next build` again. To prerender a dynamic route, Next.js needs parameter values. The guide route does not export `generateStaticParams()`, so the build stops before rendering it:

```bash filename="Terminal"
Error: Page "/store/guides/[id]": `ensureStatic = "navigation"` requires an exported `generateStaticParams()` function.
Learn more: https://nextjs.org/docs/messages/generate-static-params#with-ensurestatic
    at ignore-listed frames
> Build error occurred
Error: Failed to collect page data for /store/guides/[id]
```

Export `generateStaticParams()` and return at least one buying guide ID. Next.js prerenders the returned IDs during the build. It can generate other allowed IDs on their first request and store the result in the ISR cache. With `'navigation'`, that first request waits for the complete static page instead of receiving a fallback shell. See [ISR with Cache Components](/docs/app/guides/incremental-static-regeneration-cache-components#at-runtime).

Add a helper that returns the guide IDs to prerender:

```ts filename="lib/guides.ts"
export async function getGuideIds() {
  const guides = await db.guide.findMany({ select: { id: true } })
  return guides.map(({ id }) => id)
}
```

```tsx filename="app/store/guides/[id]/page.tsx" highlight={3,7-10}
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { getGuide, getGuideIds } from '@/lib/guides'

export const ensureStatic = 'navigation'

export async function generateStaticParams() {
  const ids = await getGuideIds()
  return ids.map((id) => ({ id }))
}

export default function GuidePage({ params }: PageProps<'/store/guides/[id]'>) {
  return (
    <Suspense fallback={<p>Loading guide...</p>}>
      <Guide params={params} />
    </Suspense>
  )
}

async function Guide({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const guide = await getGuide(id)
  const theme = (await cookies()).get('theme')?.value
  return <article data-theme={theme}>{guide.content}</article>
}
```

`generateStaticParams()` provides the parameter values, but it does not make request-time data or uncached data static.

Because every visitor can receive the same buying-guide content, the **Cache** fix is appropriate. Add the [`'use cache'` directive](/docs/app/api-reference/directives/use-cache) to `getGuide()` so Next.js can reuse the query result across requests:

```ts filename="lib/guides.ts" highlight={9}
import { db } from '@/lib/db'

export async function getGuideIds() {
  const guides = await db.guide.findMany({ select: { id: true } })
  return guides.map(({ id }) => id)
}

export async function getGuide(id: string) {
  'use cache'
  return db.guide.findUniqueOrThrow({ where: { id } })
}
```


The `'navigation'` requirement on the guide page covers the entire route, including the store layout. `<Suspense>` cannot defer these server reads because no later server-rendering stage remains.

The buying guides do not need a per-user theme, so remove that cookie access:

```diff filename="app/store/guides/[id]/page.tsx"
  import { Suspense } from 'react'
- import { cookies } from 'next/headers'
  import { getGuide, getGuideIds } from '@/lib/guides'

  // ...

    const { id } = await params
    const guide = await getGuide(id)
-   const theme = (await cookies()).get('theme')?.value
-   return <article data-theme={theme}>{guide.content}</article>
+   return <article>{guide.content}</article>
  }
```

The cart count must stay personalized. The app stores it in a non-`HttpOnly` cookie, so the browser can read it without server rendering. Convert `CartButton` to a Client Component and use [`use(browser())`](/docs/app/guides/single-page-applications#rendering-components-only-in-the-browser) to suspend during prerendering:

```tsx filename="app/ui/cart.tsx" highlight={1,3-4,7-8}
'use client'

import { use } from 'react'
import { browser } from 'react-dom'

export function CartButton() {
  use(browser('The cart count is stored in a cookie.'))
  return <button>Cart ({readCartCount()})</button>
}

function readCartCount() {
  const match = document.cookie.match(/(?:^|; )cart-count=(\d+)/)
  return Number(match?.[1] ?? 0)
}
```

During prerendering, `use(browser())` suspends, so the static output includes the `<Suspense>` fallback, `Cart (0)`. After the page loads, the browser replaces the fallback with the current count.

With the uncached and runtime data removed from the server render, `next build` now produces:

```text filename="Terminal"

├ ○ /store
├   /store/guides/[id]
│ ├ ◐ /store/guides/[id]
│ └ ○ /store/guides/coffee

  ├ ◐ /store/products/[slug]
```

The listed guide is now fully prerendered. For an unlisted guide ID, the first request waits while Next.js generates and stores the complete static page.

The store now keeps shared navigation in its static App Shell, includes cached product details in per-link prefetches, and guarantees complete static output for buying guides. Personalized cart and inventory data can still render later. If a future change adds request-time server work to a buying guide, `ensureStatic` reports it instead of silently changing the route's rendering behavior.
