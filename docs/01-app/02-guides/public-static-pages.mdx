Public pages show the same content to every user. Common examples include landing pages, marketing pages, blog indexes, product catalogs, and news sites.

Since the data is shared across users, these pages can be [prerendered]() and cached ahead of time. This leads to faster initial loads and lower server costs.

In practice, fully static pages are rare. A landing page might show a cookie banner based on the user's location. A news site might have a _breaking news_ section. A product page might show real-time stock updates. These UI elements depend on information that can only be determined at [request-time]().

[Diagram]

To handle this, developers often switch to [dynamic server rendering]() or [client-side rendering](). Both approaches come with trade-offs, you either give up the performance benefits of prerendering or show stale content while the page hydrates.

Next.js avoids this all-or-nothing choice. You can prerender most of a page ahead of time, and only render UI that requires request-time data on demand. This approach is called [Partial Prerendering]().

In this guide, you'll learn how to breakdown these public, _mostly_ static pages, cache shared data, and add dynamic UI elements where needed.

## Example

As an example, we'll use a product list page that includes a global promotional banner. You can view the source code [here]().

### Step 1: Create a product list page

Start by fetching external data and rendering a product list.

```tsx filename="app/page.tsx"
import { ProductList, type Product } from '@/app/_ui/product-list'

async function getProducts(): Promise<Product[]> {
  const response = await fetch('<https://next-recipe-api.vercel.dev/products>')

  return response.json()
}

export default async function Page() {
  const products = await getProducts()

  return <ProductList products={products} />
}
```

In Next.js, asynchronous data is **uncached** by default. This means the data is fetched on every user request.

When you run the development server, the framework warns that `"Uncached data was accessed outside of <Suspense>"`. This is because data fetching takes time and will delay the entire page from rendering. Next.js surfaces this warning to ensure your app loads instantly on every navigation.

To fix it, you have to explicitly choose how you want to unblock rendering:

1. **Cache** the data so the component can be prerendered with the rest of the page.
2. Opt this part into **streaming** so fetching and rendering doesn't block the rest of the page.

### Step 2: Prerendering the page

In our case, the product data is shared across all users, so we want to cache it.

Add the `'use cache` directive to the data function, or to the top of the file to mark all exports as cacheable.

```tsx filename="app/page.tsx" highlight="4"
import { ProductList, type Product } from '@/app/_ui/product-list'

async function getProducts(): Promise<Product[]> {
  'use cache'

  const response = await fetch('<https://next-recipe-api.vercel.dev/products>')

  return response.json()
}

export default async function Page() {
  const products = await getProducts()

  return <ProductList products={products} />
}
```

> UI vs. data layer caching
>
> Where you place `'use cache'` controls the caching boundary.
>
> - Placing it deeper in the data layer leaves the option for UI above it to be uncached.
> - Placing it higher up in the UI layer guarantees everything below is cached.

Since all data is now cached and no [request-time APIs]() are used, the entire page can be prerendered at build time.

You can confirm this by running `next build`. The build output shows the route as static.

```
Route (app)      Revalidate  Expire
┌ ○ /                   15m      1y
└ ○ /_not-found

○  (Static)  prerendered as static content
```

> **Good to know**:
> You can revalidate the product list in response to an event or after a specific period of time. See [revalidation]() for more information.

### Step 3: Add a dynamic promotion banner

As we mentioned earlier, fully static pages are rare in the real-world. As an example, let's add a promotional banner to the layout of our app.

```tsx filename="app/layout.tsx" highlight="5"
export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <PromotionalBanner />
        {children}
      </body>
    </html>
  )
}
```

This introduces uncached data into an otherwise static layout. Again, Next.js will warn that we're accessing uncached data outside of a `<Suspense>` boundary.

While some banners can be cached, this example is request specific because it depends on request-time APIs such as user location (`geolocation`) and campaign rules like A/B tests.

> **Good to know**: It's important to optimize this part of the UI because it is part of the root layout that is shared across all pages.

## Step 4: Partial Prerendering

In previous models, dynamic usage on a page would opt the whole page into dynamic rendering. And worse, global dynamic usage such as the root layout would force the entire application into a single rendering strategy.

With Next.js, we don't have to make this tradeoff. We can keep rendering UI on the server, retain prerendering for the majority of our page and don't have to forego dynamic features.

To fix the warning, we can wrap the promotion component in a `<Suspense>` boundary and provide a fallback that will be prerendered with the rest of the page.

```tsx
export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <Suspense fallback={<PromotionSkeleton />}>
          <Promotion />
        </Suspense>
        {children}
      </body>
    </html>
  )
}
```

Our route will now be partially prerendered. At build time, the page, layout and the promotion fallback will be prerendered. At request time, the promotion component will be rendered and streamed to the client when ready.

We can confirm this by running `next build`. The build logs show the route as partially prerendered.

```
Route (app)      Revalidate  Expire
┌ ◐ /                   15m      1y
└ ◐ /_not-found

◐  (Partial Prerender)  Prerendered as static HTML with dynamic server-streamed content

```
