Dates and times are tricky in server-rendered applications. A prerendered page bakes its HTML at build time, but the correct format depends on the user's timezone and locale, which are only known in the browser.

If you format a date on the server (for example, using a UTC fallback) and then reformat it on the client after hydration, the user sees a visible flash as the text changes. This guide shows how to avoid that by using an inline script that corrects the date **before the browser paints**.

## Example

As an example, we'll build an event page that displays a conference date.

We'll start with a static page that renders a UTC date, observe the flash when the client reformats it, and then fix it with an inline script that runs before the browser paints.

### Step 1: Render a static date

Let's start with a simple event page that formats a date on the server.

```tsx filename="app/events/page.tsx" switcher
const EVENT_DATE = new Date('2026-06-15T18:00:00Z')

export default function Page() {
  return (
    <section>
      <h1>Next.js Conf</h1>
      <p id="event-date">{EVENT_DATE.toLocaleDateString()}</p>
    </section>
  )
}
```

```jsx filename="app/events/page.js" switcher
const EVENT_DATE = new Date('2026-06-15T18:00:00Z')

export default function Page() {
  return (
    <section>
      <h1>Next.js Conf</h1>
      <p id="event-date">{EVENT_DATE.toLocaleDateString()}</p>
    </section>
  )
}
```

This page is static and prerendered at build time. The problem: `toLocaleDateString()` runs in Node.js during the build, so the output reflects the **server's** locale and timezone, not the user's.

A user in Tokyo sees a US-formatted date until React hydrates and the client re-renders with the correct locale. That causes a visible text change.

### Step 2: Fix the flash with an inline script

To correct the date **before the browser paints**, place a small inline `<script>` immediately after the element it targets. The browser executes inline scripts synchronously as it parses the HTML, so the DOM is updated before the first paint.

```tsx filename="app/events/page.tsx" switcher
const EVENT_DATE = '2026-06-15T18:00:00Z'

export default function Page() {
  return (
    <section>
      <h1>Next.js Conf</h1>
      <p id="event-date" suppressHydrationWarning>
        {new Date(EVENT_DATE).toLocaleDateString()}
      </p>
      <script
        dangerouslySetInnerHTML={{
          __html: `document.getElementById("event-date").textContent=new Date("${EVENT_DATE}").toLocaleDateString(undefined,{year:"numeric",month:"long",day:"numeric"})`,
        }}
      />
    </section>
  )
}
```

```jsx filename="app/events/page.js" switcher

  return (
    <section>
      <h1>Next.js Conf</h1>
      <p id="event-date" suppressHydrationWarning>
        {new Date(EVENT_DATE).toLocaleDateString()}
      </p>
      <script
        dangerouslySetInnerHTML={{
          __html: `document.getElementById("event-date").textContent=new Date("${EVENT_DATE}").toLocaleDateString(undefined,{year:"numeric",month:"long",day:"numeric"})`,
        }}
      />
    </section>
  )
}
```

Here's what happens:

1. The server renders a fallback date string into the `<p>` element during prerendering.
2. As the browser parses the HTML, the inline script runs **synchronously** and replaces the text with the user's locale-formatted date.
3. The user sees the correct date on first paint. No flash.

`suppressHydrationWarning` tells React not to warn about the text mismatch between the server-rendered HTML and the client DOM (which the inline script already corrected).

### Step 3: Extract a reusable component

If you display dates in multiple places, extract the pattern into a component.

```tsx filename="app/components/local-date.tsx" switcher
export function LocalDate({
  date,
  id,
  options,
}: {
  date: string
  id: string
  options?: Intl.DateTimeFormatOptions
}) {
  const opts = JSON.stringify(
    options ?? { year: 'numeric', month: 'long', day: 'numeric' }
  )

  return (
    <>
      <time id={id} dateTime={date} suppressHydrationWarning>
        {new Date(date).toLocaleDateString(undefined, options)}
      </time>
      <script
        dangerouslySetInnerHTML={{
          __html: `document.getElementById(${JSON.stringify(id)}).textContent=new Date(${JSON.stringify(date)}).toLocaleDateString(undefined,${opts})`,
        }}
      />
    </>
  )
}
```

```jsx filename="app/components/local-date.js" switcher
export function LocalDate({ date, id, options }) {

```

Now use it in any page:

```tsx filename="app/events/page.tsx" switcher
import { LocalDate } from '@/app/components/local-date'

export default function Page() {
  return (
    <section>
      <h1>Next.js Conf</h1>
      <LocalDate
        id="event-date"
        date="2026-06-15T18:00:00Z"
        options={{ year: 'numeric', month: 'long', day: 'numeric' }}
      />
    </section>
  )
}
```


The page stays fully static and prerendered, while every user sees dates formatted for their locale and timezone on first paint.

> **Good to know**:
>
> - Use a `<time>` element with a `dateTime` attribute for accessibility and SEO. Search engines and screen readers can parse the ISO string regardless of the displayed text.
> - Each `LocalDate` needs a unique `id` so the inline script targets the correct element.
> - The inline script only has access to browser globals. You cannot import modules or reference variables from your React component tree inside it.

## When to use other approaches

The inline script pattern works best for **static or cached pages** where you need locale-aware formatting without a visible flash. For other situations:

| Situation                                       | Approach                                                                                     |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Date depends on request data (cookies, headers) | Use [`connection()`](/docs/app/api-reference/functions/connection) to render at request time |
| Date updates live (countdown timers, clocks)    | Use a Client Component with `useEffect` and `suppressHydrationWarning`                       |
| Page is already fully dynamic                   | Format the date on the server using locale from the request headers                          |
