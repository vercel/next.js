Install the JavaScript Debugger (Nightly) extension in VS Code.

Create a file at .vscode/launch.json.

Add the following configuration:

{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Next.js: debug full stack",
      "type": "node",
      "request": "launch",
      "runtimeExecutable": "npm",
      "runtimeArgs": ["run", "dev"],
      "skipFiles": ["<node_internals>/**"],
      "console": "integratedTerminal",
      "serverReadyAction": {
        "pattern": "started server on .*, url: (https?://.*)$",
        "uriFormat": "%s",
        "action": "debugWithChrome"
      }
    }
  ]
}

Press F5 to start debugging.

👉 Change debugWithChrome to debugWithEdge if you prefer Edge.

Debugging in VS Code

Breakpoints work in both server code and browser code.

You can step through API routes, middleware, or front-end components.

To debug only server-side:

Run node --inspect node_modules/.bin/next dev

Attach VS Code debugger to port 9229.

Debugging in WebStorm

WebStorm has built-in support for debugging Next.js apps:

Go to Run → Edit Configurations.

Add a new Node.js configuration.

Set the working directory to your project root.

Set the JavaScript file to node_modules/.bin/next.

Add dev as an application parameter.

Start debugging with the play button.

For full-stack debugging, use Chrome DevTools integration (Preferences → Languages & Frameworks → JavaScript → Debugger → Built-in server).

Debugging with Browser DevTools

Chrome / Edge / Firefox

Open Developer Tools → Sources tab.

Look for your Next.js app’s source under the domain.

Set breakpoints in your React components.

React DevTools

Install the React DevTools browser extension.

Inspect props, state, and hooks in your React components.

Debugging the Server

Start Next.js with:

node --inspect node_modules/.bin/next dev

This opens the server debugger at localhost:9229.

Attach your debugger (VS Code, Chrome DevTools, etc.) to inspect server code.

Troubleshooting

Breakpoints Not Hitting

Ensure source maps are enabled (Next.js does this by default in dev).

Try restarting VS Code after modifying launch.json.

Port Conflicts

If port 9229 is in use, run:

node --inspect=9230 node_modules/.bin/next dev

Then update your debugger config to use 9230.

Windows Users

Use cross-env for environment variables.

npx cross-env NODE_OPTIONS='--inspect' next dev

Chrome vs Edge

Default config may point to Edge (debugWithEdge).

Replace with debugWithChrome if you prefer Chrome.
