# `vi.mocked` focused adapter controls

The suite was generated by the real repository command
`pnpm new-test --args true next-testing-mocked unit` in an isolated scratch
repository. The repository has no unit app-dir template, so its unchanged e2e
app-dir template was supplied only as that missing scratch generator input.
The six original outputs are retained separately before conversion to these
pure adapter controls; unused app/config scaffolding is not an integration change.

Jest is a raw-first bounded child driver and imports no facade or primitive
bundle. Five identity/routing cases run in one plain node:test process; private
CJS cache facades delegate captured real checker functions/receivers and preserve
all other descriptors/private state. They never supply an active runtime or make
a guard pass. Browser controls test only routing without opening a browser. The
separate fresh plain Node fixture creates
and disposes the existing assertion adapter runtime, owns its temporary directory,
and checks existing mock mutator guards. No raw mock-call lifetime refusal is
claimed. `pristine.case.mjs` is a prepared unchanged public-runner fixture for a
later separate root release; component preparation does not execute it.

The maintained CI case reads actual matching Next declarations using TypeScript,
without evaluating a facade or needing a Vitest controller/install. It runs six
Next-only programs, preserves complete diagnostics/inference first, and checks
the negative directives/modes and all20 named probe records. The standalone
consumer configuration is separate from full repository/package type checks.

The release type inputs are copied unchanged to the pinned reference and staged Next
facade consumers. `mocked.txt` and the matching exact/loose optional inputs must
pass, including their real negative directives. `mocked-readonly-observation.txt`
has no presumed pass/error status: compare its complete diagnostics between the
two lanes. The host also compares named inference probes, including generic
calls and primitive literal precision, against the reference without inventing
stronger inference. Full diagnostics and declaration-resolution inputs must be
retained before any comparison.

These are source-overlay adapter/type checks, not clean editor/package resolution,
public globals, named mock-type exports, actual Browser Mode, native/compiler,
Chai, or stable compatibility qualification. Existing suites and acceptance
fixtures are unchanged. All execution remains held until parent review/release.


The additive fifth case checks explicit shipped editor opt-ins in a separate
consumer created by genuine local package tarballs and an offline pnpm install.
It uses no `paths` mapping and installs neither Vitest nor Vite. The builder's
workspace dependency links are separate from that installed consumer. Eight
fresh TypeScript programs cover bare imports (including a helper's augmented
mock interface), config imports, the Node runner's existing globals, optional
import-meta types, ordinary application imports and three unresolved boundaries.
The same five positive source files are also checked against pinned Vitest 5.0.4
in a separate reference layout; that reference reuses its actual installation
and is not called a clean install. Full repository and package configuration
checks are separate from both consumers. This adds type opt-ins only: no runtime
redirect, Browser Mode, Chai global, controller, or editor-server execution is
qualified. `types: ["vitest/globals"]` without that package remains unresolved.
