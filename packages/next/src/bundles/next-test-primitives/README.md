# Next test primitives

The expect, spy, snapshot and assertion diff primitives are pinned to 5.0.4.
The separate `diff` entry bundles `@vitest/utils/diff` to format assertion values
before diagnostic serialization without initializing worker matcher globals in
the parent process.
The separate `error` entry bundles `@vitest/utils/error` for retry predicates
without loading the matcher registry into collection/host realms. Predicates
receive the pinned serialized error shape, including assertion differences.
This bundle does not load the Vitest runner or Vite. Regenerate with
`pnpm --filter=next exec taskr ncc_next_test_primitives`. The task also rebuilds
declarations and collects the dependency licenses.

`patches/@vitest__snapshot@5.0.4.patch` fixes snapshot retry rollback. Upstream
`SnapshotState.clearTest` assigned `undefined` for keys introduced by a failed
attempt, making the subsequent `pack` fail in `normalizeNewlines`. Restoring
existing original keys and deleting keys absent from the original data preserves
rollback semantics when the final retry changes or omits its snapshots. The
focused `test/unit/next-testing-stage2-api/snapshot-retry.test.ts` regression uses
the rebuilt primitive through `next/dist`. No dependency version is changed.

Source reference: Vitest revision `6a11cf66f99fa610b7364363d5ca42b66d994f40`,
`packages/snapshot/src/port/state.ts`, with the same affected implementation in
the published 5.0.4 package's `dist/index.js`. The existing bundled MIT license
collection is unchanged by the patch.


The separate `timers` entry bundles fake-timers 15.4.0 with the unchanged patch
from the selected Vitest source revision. That patch takes explicit native
timer/promisify modules instead of importing a controller. Its adapter supplies
that bridge only during context creation and restores the previous descriptor.
The caller owns the resulting clock and uninstall lifecycle. Clock declarations
and all dependency plus Jest/Vitest adapter licenses are regenerated by the same
NCC task; they do not depend on Vitest being installed in a package consumer.
The Next clock and wait adapters preserve the upstream copyright notices and
pinned behavior while enforcing existing Next scope/resource ownership.


The deep object-mocking helper also reuses the independent `@vitest/mocker`
5.0.4 primitive with Next-owned mock creation and disposal. This entry imports
no Vitest controller, runtime or Vite compiler. Its declaration and dependency
licenses are included in the existing primitive regeneration task.

The `browser` entry uses the same pinned matcher, spy, mock-object and snapshot
primitives, omitting the Node filesystem snapshot environment. It also exports
the pinned display format/inspect helpers. Browser snapshot IO belongs to the
parent-owned bridge and staged publication protocol; this bundle contains no
Vitest/Vite controller. Its declarations reuse the same private Chai namespace,
and the regeneration task rewrites static chunks and collects its licenses.
