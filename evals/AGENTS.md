# Eval authoring and publication

Read `evals/README.md` before changing an existing `agent-eval` fixture. Read
`evals/AGENT_BUILD_EVALS.md` before creating or changing an Agent Build task
in `evals/agent-build`, and `evals/RUN_AGENT_BUILD_EVALS.md` for the Harbor
format and the runners.

Keep existing `agent-eval` fixtures operational; they carry the published
history. New Agent Build tasks use the Harbor format and never join the legacy
suites or their `regression`, `competency`, and `audit` labels.

Before opening a pull request for a task, run
`evals/agent-build/tools/run-local.sh` and confirm the untouched fixture
scores 0, the reference repair scores 1, and every script in
`tests/bad-solutions/` scores 0 at the check its header names. Title every eval pull request
`eval:`. Its description always has a Results section generated by
`node evals/agent-build/tools/report.mjs <jobs-dir> <task ...>`: one results
table and the accuracy against cost chart. Refresh it as runs finish, and follow the
rest of the format in the authoring guide.

Do not export fixtures with `"publish": false` to `next-evals-oss` or publish
their results on nextjs.org/evals. Agent Build tasks do not enter that
pipeline; publishing their scores is a separate decision.
