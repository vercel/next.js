A page or layout on this route exports [`unstable_ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) with the `'navigation'` value, requiring all server-rendered work for the route to complete during prerendering.

During [prerendering](/docs/app/glossary#prerendering), `generateMetadata()` read request-specific data from `cookies()`, `headers()`, `params`, `searchParams`, or a short-lived cache. This data is not available in fully static output.

Uncached `fetch` requests, database calls, and `connection()` have different fixes. See [Uncached data in `generateMetadata()` on a route that must be fully static](/docs/messages/ensure-static-metadata-dynamic).

## Use static metadata

Choose this fix when metadata does not need request-specific data.

### Patterns

Replace `generateMetadata()` with a static [`metadata`](/docs/app/api-reference/functions/generate-metadata#metadata-object) export:

```jsx filename="app/dashboard/layout.jsx"
export const metadata = { title: 'My page' }

export default function Layout({ children }) {
  return <section>{children}</section>
}
```

### Trade-off

The metadata is determined during prerendering rather than per request.

### Gotchas

- This fixes metadata only. Page content and other segments must also satisfy the static requirement.
- A static export cannot read `cookies()`, `headers()`, `params`, or `searchParams`.

## Provide static parameters

Choose this fix when metadata depends on dynamic route [`params`](/docs/app/api-reference/file-conventions/page#params-optional).

### Patterns

Return the parameter values to prerender from [`generateStaticParams()`](/docs/app/api-reference/functions/generate-static-params):

```jsx filename="app/blog/[slug]/page.jsx"
export function generateStaticParams() {
  return [{ slug: 'hello' }]
}

export async function generateMetadata({ params }) {
  const { slug } = await params
  return { title: slug }
}
```

Include every dynamic parameter. An empty array does not satisfy the fully static requirement.

### Trade-off

The returned paths are generated at build time. Other values wait for a blocking prerender before Next.js serves their static output.

### Gotchas

- Include every dynamic parameter, including parameters used only by metadata.
- This fix applies only to route `params`. It does not make cookies, headers, search parameters, or short-lived caches static.

## Other options

### Extend the cache lifetime

A cache with a short lifetime can also count as runtime data. For fully static navigation, `expire` must be at least 300 seconds, `stale` at least 30 seconds, and `revalidate` greater than zero. Increase the lifetime only when serving shared, older metadata is acceptable.

## Verifying the fix

After applying a fix, rerun [`next build`](/docs/app/api-reference/cli/next#next-build-options) and confirm that the route completes prerendering. If the error also appeared in [`next dev`](/docs/app/api-reference/cli/next#next-dev-options), reload the route and confirm that the overlay clears. Wrapping the access in Suspense or setting `instant = false` does not relax the fully static requirement.

In `next dev`, the error overlay points at the failing function with file paths and line numbers. Run [`next build --debug-prerender`](/docs/app/guides/building#debug-prerender-errors) for full user-frame stack traces and `next build --debug-build-paths /dashboard /settings` to iterate on specific routes.

## Remove the static requirement

The `'navigation'` value is usually set deliberately to guarantee static output for the entire server-rendered route. Removing it relaxes that requirement for every segment, not only metadata.

If request-time rendering is intentional for this route, remove `unstable_ensureStatic = 'navigation'` from every page or layout that sets it. The route then follows the ordinary [Cache Components](/docs/app/getting-started/caching) rendering rules.
