A [Client Component](/docs/app/getting-started/server-and-client-components#using-client-components) called [`Math.random()`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Math/random) inline during render, and the surrounding tree had no [`<Suspense>`](https://react.dev/reference/react/Suspense) boundary. Client Components also render on the server, where this read interrupts [prerendering](/docs/app/glossary#prerendering). A parent `<Suspense>` boundary provides a fallback for that interruption. It does not make the component browser-only or ensure that a server-generated random value matches the first browser render.

The Server Component case is handled at [`Math.random()` during prerendering](/docs/messages/blocking-prerender-random). Other unpredictable client-side APIs ([`Date.now()`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/now), [`crypto.randomUUID()`](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)) have parallel error pages: [`Date.now()` in a Client Component](/docs/messages/blocking-prerender-current-time-client) and [Crypto APIs in a Client Component](/docs/messages/blocking-prerender-crypto-client).

## Ways to fix this

Choose based on where the value belongs:

| When you need the value                                                 | Approach                                                                                                    |
| ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Only in the browser                                                     | [`use(browser())` inside `<Suspense>`](#render-only-in-the-browser)                                         |
| In server-rendered HTML and the first browser render                    | [Generate it in a Server Component and pass it as a prop](#render-the-same-value-on-the-server-and-browser) |
| Inside a library that already preserves its server result for hydration | [Defer the library with `use(io())`](#keep-a-hydration-aware-library-server-rendered)                       |
| After an interaction, or while synchronizing with an external system    | [An event handler or effect](#move-into-effect-or-event-handler)                                            |

## Render only in the browser

Choose this fix when the random value belongs in the browser. Call [`use(browser())`](https://react.dev/reference/react-dom/browser) before the read to skip both static prerendering and request-time server rendering. React 19.3 includes `browser` from `react-dom`.

### Patterns

#### Create a browser-owned value

Place a [`<Suspense>`](https://react.dev/reference/react/Suspense) boundary above the component that calls `use(browser())`:

```jsx filename="app/page.js"
import { Suspense } from 'react'
import { RandomId } from './random-id'

export default function Page() {
  return (
    <Suspense fallback={<p>Loading label…</p>}>
      <RandomId />
    </Suspense>
  )
}
```

```jsx filename="app/random-id.js"
'use client'

import { use, useState } from 'react'
import { browser } from 'react-dom'

export function RandomId() {
  use(browser())
  const [id] = useState(() => Math.random())
  return <p>Random label: {id.toString(36).slice(2)}</p>
}
```

The state initializer runs after `use(browser())`, so the value is created in the browser and stays the same across re-renders. For a third-party widget, call `use(browser())` in a Client Component wrapper before returning the widget.

### Trade-off

The server sends the fallback, and the component appears after JavaScript loads. For useful server-rendered fallbacks and their trade-offs, see [Rendering client-specific content](/docs/app/guides/preventing-flash-before-hydration#rendering-client-specific-content).

### Gotchas

- Adding `use client` or `<Suspense>` alone does not guarantee browser-only rendering. See [What activates a Suspense boundary](https://react.dev/reference/react/Suspense#what-activates-a-suspense-boundary).
- A lazy `useState` initializer or a `useRef` does not defer a read past server rendering. The example works because `use(browser())` runs first.
- Keep fallbacks deterministic. A time or random read in a fallback can raise this error again.
- Keep browser-only wrappers close to the widget. Wrapping a layout's `children` can prevent nested pages from rendering on the server. See [unrendered segments](/docs/messages/instant-unrendered-segment).

## Move into effect or event handler

Choose this fix when an interaction produces the random value, or an effect synchronizes with an external system such as a running timer.

### Patterns

#### Compute on user interaction

Read the value in the event handler. If later events must reuse it, keep it in state or a ref.

```jsx filename="app/shuffle.js"
'use client'

import { useState } from 'react'

export function Shuffle() {
  const [seed, setSeed] = useState(0)
  return (
    <button onClick={() => setSeed(Math.random())}>Shuffle ({seed})</button>
  )
}
```

For a one-time browser value during initial rendering, prefer [`use(browser())`](#render-only-in-the-browser). The guide explains [the extra render and flash from mount effects](/docs/app/guides/preventing-flash-before-hydration#why-not-useeffect), and [subscriptions to browser values](/docs/app/guides/preventing-flash-before-hydration#subscribing-to-browser-values).

### Trade-off

An event-generated value appears after the interaction. An effect-based value uses a deterministic initial state until the effect runs. See [How to prevent flash before hydration](/docs/app/guides/preventing-flash-before-hydration).

### Gotchas

- Keep the initial render deterministic. A lazy state initializer still runs on the server unless `use(browser())` runs first.
- If an effect update can suspend a descendant, use [`startTransition`](https://react.dev/reference/react/startTransition) to keep existing content visible while the update resolves.

## Other options

### Render the same value on the server and browser

Generate the random value in a Server Component and pass the serialized result as a prop. The Client Component renders that prop instead of reading its own value during hydration. Use [`use cache`](/docs/messages/blocking-prerender-random) if the value can be reused, or [`await io()`](/docs/app/api-reference/functions/io) before the server read to exclude it from static prerendering.

### Keep a hydration-aware library server-rendered

Call [`use(io())`](/docs/app/api-reference/functions/io) before a widget only when its library already preserves its server result for hydration. The call suspends static prerendering but allows request-time server rendering. It does not preserve an arbitrary random value, so calling it directly before `Math.random()` can still produce a hydration mismatch. See the [third-party widget wrapper](/docs/messages/blocking-prerender-current-time-client#keep-a-hydration-aware-library-server-rendered).

## Verifying the fix

After applying a fix, reload the route and confirm the page immediately paints meaningful UI, with any `<Suspense>` fallbacks covering only the regions that stream in. A [`<Suspense>`](https://react.dev/reference/react/Suspense) boundary placed around the whole page body can pass validation with an empty shell, which defeats the point of an instant navigation.

If the component can also render at request time, test that path and check the browser console for hydration errors. A successful static build does not verify that a server-generated value matches the first browser render.

In [`next dev`](/docs/app/api-reference/cli/next#next-dev-options), the error overlay points at the failing component with file paths and line numbers. When working from a build instead, the default [`next build`](/docs/app/api-reference/cli/next#next-build-options) output is more abbreviated. Run `next build --debug-prerender` for full user-frame stack traces and `next build --debug-build-paths /dashboard /settings` to iterate on specific routes.

## Why `instant = false` doesn't clear this error

This error fires from the prerender, not from instant-navigation validation. `Math.random()` returns a different value on every render, so the prerender can't bake it into a static shell regardless of the segment's `instant` config or [`experimental.instantInsights.validationLevel`](/docs/app/api-reference/file-conventions/route-segment-config/instant#configuring-validation-defaults). Use one of the fixes above.
