A route with [Partial Prefetching](https://preview.nextjs.org/docs/app/glossary#partial-prefetching) reads [`params`](https://preview.nextjs.org/docs/app/api-reference/file-conventions/page#params-optional) or [`searchParams`](https://preview.nextjs.org/docs/app/api-reference/file-conventions/page#searchparams-optional) outside of [`<Suspense>`](https://react.dev/reference/react/Suspense).

Partial Prefetching prefetches one shared version of the route ahead of the click, so every link to it reuses the same prefetch instead of fetching a fresh one per URL. `params` and `searchParams` are specific to a single URL, so reading them outside a boundary ties that prefetch to one link. Next.js can no longer share it across links, leading to slower, more expensive prefetches.

This check only runs when [Partial Prefetching](https://preview.nextjs.org/docs/app/api-reference/config/next-config-js/partialPrefetching) is enabled, and it fires at navigation time rather than on every render. When this route is prerendered rather than prefetched, the same read surfaces as [runtime data during prerendering](/docs/messages/blocking-prerender-runtime) instead.

> **Good to know**: [`cookies()`](https://preview.nextjs.org/docs/app/api-reference/functions/cookies) and [`headers()`](https://preview.nextjs.org/docs/app/api-reference/functions/headers) don't trigger this. They vary per user, not per link, so the prefetch is still shared. Only per-URL values are a problem, and making them static with [`generateStaticParams`](https://preview.nextjs.org/docs/app/api-reference/functions/generate-static-params) doesn't help, since a static param still belongs to one URL.

## Wrap in or move into Suspense

Choose this fix when the route has content that doesn't depend on the URL. Keep that content outside the boundary so it stays part of the shared prefetch, and wrap the `params` or `searchParams` read in a [`<Suspense>`](https://react.dev/reference/react/Suspense) boundary so it [streams](https://preview.nextjs.org/docs/app/glossary#streaming) in after navigation. Every link keeps reusing the same prefetch, and only the URL-specific part renders per navigation.

### Patterns

#### Pass `searchParams` to a suspended child

Don't await `params` or `searchParams` at the top of the route. Pass the promise to a child that reads it inside its own boundary, so the rest of the route stays in the shared prefetch.

```jsx filename="app/dashboard/page.js"
import { Suspense } from 'react'
import { Results } from './results'

export default function Page({ searchParams }) {
  return (
    <DashboardShell>
      <DashboardHeader />
      <Suspense fallback={<ResultsSkeleton />}>
        <Results searchParams={searchParams} />
      </Suspense>
    </DashboardShell>
  )
}
```

```jsx filename="app/dashboard/results.js"
export async function Results({ searchParams }) {
  const { q } = await searchParams
  const widgets = await searchWidgets(q)
  return <WidgetList widgets={widgets} />
}
```

Learn more: [Using `searchParams` in the App Router](https://preview.nextjs.org/docs/app/api-reference/file-conventions/page#searchparams-optional).

#### Read `params` in the leaf that needs it

When only a small piece of UI depends on the route param, move the read down to that leaf and wrap it. Everything above stays in the shared prefetch.

```jsx filename="app/product/[id]/page.js"
import { Suspense } from 'react'
import { ProductDetails } from './product-details'

export default function Page({ params }) {
  return (
    <ProductLayout>
      <Suspense fallback={<DetailsSkeleton />}>
        <ProductDetails params={params} />
      </Suspense>
    </ProductLayout>
  )
}
```

```jsx filename="app/product/[id]/product-details.js"
export async function ProductDetails({ params }) {
  const { id } = await params
  const product = await getProduct(id)
  return <Details product={product} />
}
```

Learn more: [Streaming patterns and boundary placement](https://preview.nextjs.org/docs/app/guides/streaming).

### Trade-off

The shared parts of the route are prefetched, and the URL-dependent region streams in after navigation, so the user sees a fallback for that region. Design the fallback to approximate the final layout so the page doesn't visibly jump when the content arrives.

### Gotchas

- [`cookies()`](https://preview.nextjs.org/docs/app/api-reference/functions/cookies) and [`headers()`](https://preview.nextjs.org/docs/app/api-reference/functions/headers) don't need this treatment. They vary per user, not per link, so the prefetch is still shared. Only `params` and `searchParams` trigger this error.
- Making the route static with [`generateStaticParams`](https://preview.nextjs.org/docs/app/api-reference/functions/generate-static-params) does not resolve it. A static param is still specific to one URL, so it can't be part of a prefetch shared across links.
- The `params` and `searchParams` props are promises. Passing the promise down without awaiting it keeps the rest of the route in the shared prefetch; awaiting it above the boundary pulls the URL data back in.

## Disable validation on this route

Choose this fix when the route can't share a prefetch across links and you accept that its links prefetch per URL instead. Setting [`instant`](https://preview.nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/instant) to `false` opts the route out of instant-navigation validation and silences the warning.

### Patterns

#### Opt the page out

Add the export to the page that reads the URL data. Only that route stops being validated.

```jsx filename="app/dashboard/page.js"
export const instant = false

export default async function Page({ searchParams }) {
  const { q } = await searchParams
  return <Results query={q} />
}
```

Learn more: [Ensuring instant navigations](https://preview.nextjs.org/docs/app/guides/instant-navigation).

#### Opt the layout out

When a shared layout reads the URL data, set [`instant`](https://preview.nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/instant) to `false` on the layout. That layout segment stops being validated while descendant segments stay independently validated.

```jsx filename="app/dashboard/layout.js"
export const instant = false

export default function DashboardLayout({ children }) {
  return <DashboardShell>{children}</DashboardShell>
}
```

Learn more: [Route segment `instant` config](https://preview.nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/instant).

Use either pattern when:

- The route genuinely needs the URL param high in the tree to decide what to render, so there's no shared part worth prefetching.
- You're adopting Partial Prefetching incrementally and want to defer this route without changing how it renders today.

Don't use this to dismiss the error. Choose [Wrap in or move into Suspense](#wrap-in-or-move-into-suspense) when the route has any content that doesn't depend on the URL.

### Trade-off

Links to this route prefetch per URL instead of sharing one prefetch, so prefetches are slower and more expensive. Use this only when the route can't be structured around a shared prefetch.

### Gotchas

- Setting [`instant`](https://preview.nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/instant) to `false` opts out only the segment that exports it. Descendant segments remain validated by their own config or the global default.
- This export does not disable [Partial Prefetching](https://preview.nextjs.org/docs/app/glossary#partial-prefetching) or prefetching. It only silences the instant-navigation validation error for the segment.

## Verifying the fix

After applying a fix, reload the route to confirm the [static shell](https://preview.nextjs.org/docs/app/glossary#static-shell) renders real content. A [`<Suspense>`](https://react.dev/reference/react/Suspense) boundary placed around the whole page body can pass validation with an empty shell, which defeats the point of an instant navigation.

In [`next dev`](https://preview.nextjs.org/docs/app/api-reference/cli/next#next-dev-options), the error overlay points at the failing component with file paths and line numbers. When working from a build instead, the default [`next build`](https://preview.nextjs.org/docs/app/api-reference/cli/next#next-build-options) output is more abbreviated; run `next build --debug-prerender` for full user-frame stack traces and `next build --debug-build-paths /dashboard /settings` to iterate on specific routes.

## Don't want this validation?

Instant-navigation validation runs by default in [Cache Components](https://preview.nextjs.org/docs/app/api-reference/config/next-config-js/cacheComponents) apps and surfaces this error.

- **One segment**: add [`export const instant = false`](https://preview.nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/instant) to the page or layout file. This opts out the segment itself. Child segments are still validated during client navigations.
- **Entire app**: set [`experimental.instantInsights.validationLevel`](https://preview.nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/instant#configuring-validation-defaults) to `'manual-warning'` in `next.config`. This limits validation to segments that explicitly export `instant`.

See [Ensuring instant navigations](https://preview.nextjs.org/docs/app/guides/instant-navigation) for the full model.
