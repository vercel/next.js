A [Client Component](/docs/app/getting-started/server-and-client-components#using-client-components) called [`Date.now()`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/now), [`Date()`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date), or [`new Date()`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date) inline during render, and the surrounding tree had no [`<Suspense>`](https://react.dev/reference/react/Suspense) boundary. Client Components also render on the server, where this read interrupts [prerendering](/docs/app/glossary#prerendering). A parent `<Suspense>` boundary provides a fallback for that interruption. It does not make the component browser-only or ensure that a server-generated timestamp matches the first browser render.

An imported library can also read the current time during render. In that case, the stack trace may point to the hook or component that initializes the library instead of its internal `Date.now()` call.

The Server Component case is handled at [`Date.now()` during prerendering](/docs/messages/blocking-prerender-current-time). Other unpredictable client-side APIs ([`Math.random()`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Math/random), [`crypto.randomUUID()`](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)) have parallel error pages: [`Math.random()` in a Client Component](/docs/messages/blocking-prerender-random-client) and [Crypto APIs in a Client Component](/docs/messages/blocking-prerender-crypto-client).

## Render only in the browser

Choose this fix when the timestamp belongs in the browser. Call [`use(browser())`](https://react.dev/reference/react-dom/browser) before the read to skip both static prerendering and request-time server rendering. React 19.3 includes `browser` from `react-dom`.

### Patterns

#### Create a browser-owned value

Place a [`<Suspense>`](https://react.dev/reference/react/Suspense) boundary above the component that calls `use(browser())`:

```jsx filename="app/page.js"
import { Suspense } from 'react'
import { DateDisplay } from './date-display'

export default function Page() {
  return (
    <Suspense fallback={<time>Loading time…</time>}>
      <DateDisplay />
    </Suspense>
  )
}
```

```jsx filename="app/date-display.js"
'use client'

import { use, useState } from 'react'
import { browser } from 'react-dom'

export function DateDisplay() {
  use(browser())
  const [time] = useState(() => Date.now())
  return <time>{new Date(time).toLocaleTimeString()}</time>
}
```

The state initializer runs after `use(browser())`, so the value is created in the browser and stays the same across re-renders. For a third-party widget, call `use(browser())` in a Client Component wrapper before returning the widget.

### Trade-off

The server sends the fallback, and the component appears after JavaScript loads. For useful server-rendered fallbacks and their trade-offs, see [Rendering client-specific content](/docs/app/guides/preventing-flash-before-hydration#rendering-client-specific-content).

### Gotchas

- Adding `use client` or `<Suspense>` alone does not guarantee browser-only rendering. See [What activates a Suspense boundary](https://react.dev/reference/react/Suspense#what-activates-a-suspense-boundary).
- A lazy `useState` initializer or a `useRef` does not defer a read past server rendering. The example works because `use(browser())` runs first.
- <span id="render-the-same-value-on-the-server-and-browser" /> If the timestamp
  must appear in server-rendered HTML, generate it in a Server Component and
  pass the serialized result as a prop. Use [`use
  cache`](/docs/messages/blocking-prerender-current-time) if the value can be
  reused, or [`await io()`](/docs/app/api-reference/functions/io) before the
  server read to exclude it from static prerendering. For example, cache a
  copyright year on the server. For client-specific formatting of an existing
  timestamp, see [Rendering client-specific
  content](/docs/app/guides/preventing-flash-before-hydration#rendering-client-specific-content).
- <span id="suspend-with-useio" /><span id="keep-a-hydration-aware-library-server-rendered" /> If a library already preserves its server result for hydration (for example, in a dehydrated query cache), a wrapper with [`use(io())`](/docs/app/api-reference/functions/io#usage) inside a parent `<Suspense>` boundary allows request-time server rendering. It does not preserve an arbitrary timestamp, so calling it directly before `Date.now()` can still produce a hydration mismatch. See the `io` reference for the wrapper example.
- Keep fallbacks deterministic. A time or random read in a fallback can raise this error again.
- Keep browser-only wrappers close to the widget. Wrapping a layout's `children` can prevent nested pages from rendering on the server. See [unrendered segments](/docs/messages/instant-unrendered-segment).

## Move into effect or event handler

Choose this fix when an interaction produces the timestamp, or an effect synchronizes with an external system such as a running timer.

### Patterns

#### Compute on user interaction

Read the value in the event handler. If later events must reuse it, keep it in state or a ref.

```jsx filename="app/snapshot.js"
'use client'

import { useState } from 'react'

export function Snapshot() {
  const [taken, setTaken] = useState(null)
  return (
    <button onClick={() => setTaken(Date.now())}>
      {taken ? `Snapshot at ${new Date(taken).toLocaleString()}` : 'Snapshot'}
    </button>
  )
}
```

For a one-time browser value during initial rendering, prefer [`use(browser())`](#render-only-in-the-browser). The guide explains [the extra render and flash from mount effects](/docs/app/guides/preventing-flash-before-hydration#why-not-useeffect), and [subscriptions to browser values](/docs/app/guides/preventing-flash-before-hydration#subscribing-to-browser-values).

### Trade-off

An event-generated value appears after the interaction. An effect-based value uses a deterministic initial state until the effect runs. See [How to prevent flash before hydration](/docs/app/guides/preventing-flash-before-hydration).

### Gotchas

- Keep the initial render deterministic. A lazy state initializer still runs on the server unless `use(browser())` runs first.
- If an effect update can suspend a descendant, use [`startTransition`](https://react.dev/reference/react/startTransition) to keep existing content visible while the update resolves.

## For telemetry, use a timing API

Choose this fix when the timestamp isn't user-visible at all. Logging, performance instrumentation, span correlation: all measurements that need a clock but don't render anything. Switch to [`performance.now()`](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now), a high-resolution monotonic timer that doesn't carry the same semantic ("the current wall-clock time") that prevents prerendering.

### Patterns

#### Replace `Date.now()` with `performance.now()`

Drop-in replacement for any elapsed-time calculation.

```jsx filename="app/timed.js"
'use client'

import { useEffect } from 'react'

export function Timed() {
  useEffect(() => {
    const start = performance.now()
    doWork()
    const elapsedMs = performance.now() - start
    console.log(`doWork took ${elapsedMs}ms`)
  }, [])
  return null
}
```

Learn more: [`performance.now()`](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now).

### Trade-off

[`performance.now()`](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now) returns a high-resolution timestamp relative to time origin, not a wall-clock time. Use it only for durations.

### Gotchas

- [`performance.now()`](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now) values from the server and browser can't be compared. Each environment has its own time origin.
- Don't pass a [`performance.now()`](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now) value into the rendered output. It's non-deterministic between SSR and the browser.
- For absolute time in an observability tool, use `performance.timeOrigin + performance.now()` to get a wall-clock timestamp without tripping this error.

## Verifying the fix

After applying a fix, reload the route and confirm the page immediately paints meaningful UI, with any `<Suspense>` fallbacks covering only the regions that stream in. A [`<Suspense>`](https://react.dev/reference/react/Suspense) boundary placed around the whole page body can pass validation with an empty shell, which defeats the point of an instant navigation.

If the component can also render at request time, test that path and check the browser console for hydration errors. A successful static build does not verify that a server-generated value matches the first browser render.

In [`next dev`](/docs/app/api-reference/cli/next#next-dev-options), the error overlay points at the failing component with file paths and line numbers. When working from a build instead, the default [`next build`](/docs/app/api-reference/cli/next#next-build-options) output is more abbreviated. Run `next build --debug-prerender` for full user-frame stack traces and `next build --debug-build-paths /dashboard /settings` to iterate on specific routes.

## Why `instant = false` doesn't clear this error

This error fires from the prerender, not from instant-navigation validation. `new Date()` and `Date.now()` return a different value on every render, so the prerender can't bake them into a static shell regardless of the segment's `instant` config or [`experimental.instantInsights.validationLevel`](/docs/app/api-reference/file-conventions/route-segment-config/instant#configuring-validation-defaults). Use one of the fixes above.
