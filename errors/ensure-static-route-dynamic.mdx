A page or layout on this route exports [`unstable_ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) with the `'navigation'` value, requiring fully static server output.

During [prerendering](/docs/app/glossary#prerendering), the page or layout performed an uncached `fetch` request, database call, or `connection()`. The operation requires request-time server work and cannot be included in fully static output.

Request-specific reads from `cookies()`, `headers()`, `params`, or `searchParams` have different fixes. See [Runtime data on a route that must be fully static](/docs/messages/ensure-static-route-runtime).

## Cache the data

Choose this fix when the data can be shared across requests.

### Patterns

Cache the asynchronous function with [`use cache`](/docs/app/api-reference/directives/use-cache) and choose an appropriate [`cacheLife`](/docs/app/api-reference/functions/cacheLife) profile:

```jsx filename="app/page.jsx"
import { cacheLife } from 'next/cache'

export default async function Page() {
  'use cache'
  cacheLife('hours')
  const response = await fetch('https://api.example.com/content')
  const data = await response.json()
  return <h1>{data.title}</h1>
}
```

### Trade-off

Visitors share the cached result until it is revalidated.

### Gotchas

- This fix does not apply to [`connection()`](/docs/app/api-reference/functions/connection), whose purpose is to require request-time rendering.
- Caching does not make request-specific cookies, headers, parameters, or search parameters static.

### Short-lived caches

For fully static navigation, a cache's `expire` must be at least 300 seconds, `stale` at least 30 seconds, and `revalidate` greater than zero.

## Remove the data access

Choose this fix when the operation is unnecessary.

### Patterns

Remove the access rather than only removing the JSX that displays its result:

```jsx filename="app/page.jsx"
export const unstable_ensureStatic = 'navigation'

export default function Page() {
  return <h1>My page</h1>
}
```

### Trade-off

Every visitor receives the same output because the removed operation no longer runs per request.

### Gotchas

- Other uncached or runtime data in the route, including layouts and metadata, must also be resolved.
- If the operation is required per request, remove the `unstable_ensureStatic = 'navigation'` requirement instead.

## Verifying the fix

After applying a fix, reload the route and confirm that this error no longer appears and the page immediately paints meaningful UI. Wrapping the operation in Suspense or setting `instant = false` does not relax the fully static requirement.

In [`next dev`](/docs/app/api-reference/cli/next#next-dev-options), the error overlay points at the failing component with file paths and line numbers. When working from a build instead, the default [`next build`](/docs/app/api-reference/cli/next#next-build-options) output is more abbreviated. Run `next build --debug-prerender` for full user-frame stack traces and `next build --debug-build-paths /dashboard /settings` to iterate on specific routes.

## Don't want this validation?

If the route requires request-time server data, remove `unstable_ensureStatic = 'navigation'` from the pages or layouts that set it. The route then follows the ordinary [Cache Components](/docs/app/getting-started/caching) rendering rules.
