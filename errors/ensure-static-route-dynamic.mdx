A page or layout on this route exports [`unstable_ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) with the `'navigation'` value, requiring fully static server output.

During [prerendering](/docs/app/glossary#prerendering), the page or layout performed an uncached `fetch` request, database call, or `connection()`. The operation requires request-time server work and cannot be included in fully static output.

Request-specific reads from `cookies()`, `headers()`, `params`, or `searchParams` have different fixes. See [Runtime data on a route that must be fully static](/docs/messages/ensure-static-route-runtime).

## Cache the data

When the data can be shared across requests, cache the asynchronous function with [`use cache`](/docs/app/api-reference/directives/use-cache) and choose an appropriate [`cacheLife`](/docs/app/api-reference/functions/cacheLife) profile:

```jsx filename="app/page.jsx"
import { cacheLife } from 'next/cache'

export default async function Page() {
  'use cache'
  cacheLife('hours')
  const response = await fetch('https://api.example.com/content')
  const data = await response.json()
  return <h1>{data.title}</h1>
}
```

Visitors share the cached result until it is revalidated. This fix does not apply to [`connection()`](/docs/app/api-reference/functions/connection), whose purpose is to require request-time rendering.

## Remove the data access

When the operation is unnecessary, remove it rather than only removing the JSX that displays its result:

```jsx filename="app/page.jsx"
export const unstable_ensureStatic = 'navigation'

export default function Page() {
  return <h1>My page</h1>
}
```

Other uncached or runtime data in the route, including layouts and metadata, must also be resolved.

## Verifying the fix

Reload the route in [`next dev`](/docs/app/api-reference/cli/next#next-dev-options), then run [`next build`](/docs/app/api-reference/cli/next#next-build-options) and confirm that the route completes prerendering.

Wrapping the operation in Suspense or setting `instant = false` does not relax the fully static requirement.

## Don't want this validation?

If the route requires request-time server data, remove `unstable_ensureStatic = 'navigation'` from the pages or layouts that set it. The route then follows the ordinary [Cache Components](/docs/app/getting-started/caching) rendering rules.
