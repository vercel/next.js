A page or layout on this route exports [`unstable_ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) with the `'navigation'` value, requiring fully static server output.

During [prerendering](/docs/app/glossary#prerendering), `generateViewport()` read request-specific data from `cookies()`, `headers()`, `params`, `searchParams`, or a short-lived cache. This data is not available in fully static output.

Uncached `fetch` requests, database calls, and `connection()` have different fixes. See [Uncached data in `generateViewport()` on a route that must be fully static](/docs/messages/ensure-static-viewport-dynamic).

## Use static viewport

Choose this fix when viewport settings do not need request-specific data.

### Patterns

Replace `generateViewport()` with a static [`viewport`](/docs/app/api-reference/functions/generate-viewport#the-viewport-object) export:

```jsx filename="app/dashboard/layout.jsx"
export const viewport = { themeColor: 'black' }

export default function Layout({ children }) {
  return <section>{children}</section>
}
```

### Trade-off

The viewport is determined during prerendering rather than per request.

### Gotchas

- This fixes viewport settings only. Page content, metadata, and other segments must also satisfy the static requirement.
- A static export cannot read `cookies()`, `headers()`, `params`, or `searchParams`.

## Provide static parameters

Choose this fix when viewport settings depend on dynamic route [`params`](/docs/app/api-reference/file-conventions/page#params-optional).

### Patterns

Return the parameter values to prerender from [`generateStaticParams()`](/docs/app/api-reference/functions/generate-static-params):

```jsx filename="app/blog/[slug]/page.jsx"
export function generateStaticParams() {
  return [{ slug: 'hello' }]
}

export async function generateViewport({ params }) {
  const { slug } = await params
  return { themeColor: slug === 'hello' ? 'black' : 'white' }
}
```

Include every dynamic parameter. An empty array does not satisfy the fully static requirement.

### Trade-off

The returned paths are generated at build time. Other values wait for a blocking prerender before Next.js serves their static output.

### Gotchas

- Include every dynamic parameter, including parameters used only by the viewport.
- This fix applies only to route `params`. It does not make cookies, headers, search parameters, or short-lived caches static.

## Other options

### Extend the cache lifetime

A cache with a short lifetime can also count as runtime data. For fully static navigation, `expire` must be at least 300 seconds, `stale` at least 30 seconds, and `revalidate` greater than zero. Increase the lifetime only when serving shared, older viewport data is acceptable.

## Verifying the fix

After applying a fix, reload the route and confirm that this error no longer appears. Wrapping the access in Suspense or setting `instant = false` does not relax the fully static requirement.

In [`next dev`](/docs/app/api-reference/cli/next#next-dev-options), the error overlay points at the failing function with file paths and line numbers. When working from a build instead, the default [`next build`](/docs/app/api-reference/cli/next#next-build-options) output is more abbreviated. Run `next build --debug-prerender` for full user-frame stack traces and `next build --debug-build-paths /dashboard /settings` to iterate on specific routes.

## Don't want this validation?

If the route requires a request-time viewport, remove `unstable_ensureStatic = 'navigation'` from the pages or layouts that set it.
