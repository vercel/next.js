During prerendering or a client-side navigation, [`generateViewport()`](/docs/app/api-reference/functions/generate-viewport) called [`unstable_prefetch()`](/docs/app/api-reference/functions/prefetch) or [`unstable_navigation()`](/docs/app/api-reference/functions/navigation). `unstable_prefetch()` delays the viewport until a per-link prefetch or navigation. `unstable_navigation()` delays it until navigation.

Next.js needs the viewport before it can complete the route's [App Shell](/docs/app/glossary#app-shell). Holding the viewport until a later stage prevents Next.js from creating the App Shell and can make navigation slower. If the later timing is not intentional, remove the API call. If it is intentional, you can leave the behavior unchanged. To stop reporting the insight, disable validation for the segment.

For the same insight in the page body or metadata code, see [navigation stage API outside of Suspense](/docs/messages/instant-navigation-stage) or [navigation stage API in `generateMetadata()`](/docs/messages/instant-navigation-stage-metadata).

## Remove the API call

Choose this fix when you do not need to control when the viewport is included. Remove `unstable_prefetch()` or `unstable_navigation()` from [`generateViewport()`](/docs/app/api-reference/functions/generate-viewport). Keep `generateViewport()` and its existing caching.

### Patterns

#### Remove the API call

Remove the call to `unstable_prefetch()` or `unstable_navigation()`.

```jsx filename="app/dashboard/layout.js"
import { getViewport } from './data'

export async function generateViewport() {
  return getViewport()
}

export default function DashboardLayout({ children }) {
  return children
}
```

### Trade-off

Removing the API can increase the viewport work performed during prerendering and prefetching.

### Gotchas

- You do not need to replace `generateViewport()` with a static [`viewport`](/docs/app/api-reference/functions/generate-viewport#the-viewport-object) export. Use a static export only when the values are fixed for the route segment.

## Verifying the fix

After applying a fix, navigate to the route and confirm the insight no longer appears. The page should paint meaningful UI immediately.

In [`next dev`](/docs/app/api-reference/cli/next#next-dev-options), the error overlay identifies the failing component with a file path and line number. The default [`next build`](/docs/app/api-reference/cli/next#next-build-options) output is shorter. Run `next build --debug-prerender` for full user-frame stack traces or `next build --debug-build-paths /dashboard /settings` to inspect specific routes.

## Disable validation on this route

Choose this fix when the later viewport timing is intentional and you do not want Next.js to report the insight. Add [`export const instant = false`](/docs/app/api-reference/file-conventions/route-segment-config/instant) to the page or layout that exports `generateViewport()`. This disables instant-navigation validation for the segment. It does not change when the viewport becomes available.

```jsx filename="app/dashboard/layout.js"
export const instant = false
```

Child segments are still validated during client navigations.
