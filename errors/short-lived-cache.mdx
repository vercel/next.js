During [prerendering](/docs/app/glossary#prerendering) or Instant Navigation validation, a function used the [`use cache`](/docs/app/api-reference/directives/use-cache) directive, but its [`cacheLife`](/docs/app/api-reference/functions/cacheLife) settings excluded the cached result from required prerendered output.

This can happen in route content, [`generateMetadata()`](/docs/app/api-reference/functions/generate-metadata), or [`generateViewport()`](/docs/app/api-reference/functions/generate-viewport). A cached function can still require rendering at request time when its lifetime is too short.

## Why this error occurs

With [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents), a cache must meet these lifetime requirements to be included in prerendered output:

| Setting      | Required value                                                                                            |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| `expire`     | At least `300` seconds (five minutes)                                                                     |
| `stale`      | At least `30` seconds for prerendering, or `300` seconds for an [App Shell](/docs/app/glossary#app-shell) |
| `revalidate` | Greater than `0`                                                                                          |

For example, the built-in `seconds` profile expires after one minute, so its result is excluded from prerenders. A cache with `stale: 60` can be prerendered but is excluded from an App Shell.

The Cache card applies in every context. The other available fixes depend on where the cache is consumed and whether the route must be fully static.

## Increase the cache lifetime

Choose this fix when the data can remain cached long enough to meet the requirements above. Update the settings inside the cached function that produces the data.

### Patterns

#### Increase the relevant lifetime values

Set all values that fall below the required thresholds. This example meets both the prerendering and App Shell requirements:

```ts filename="app/data.ts"
import { cacheLife } from 'next/cache'

export async function getData() {
  'use cache'

  cacheLife({
    stale: 300,
    revalidate: 60,
    expire: 300,
  })

  const response = await fetch('https://api.example.com/data')
  return response.json()
}
```

The card shows only `expire` as an abbreviated example. Increasing `expire` alone does not fix a cache excluded by a short `stale` value or by `revalidate: 0`.

Learn more: [`cacheLife`](/docs/app/api-reference/functions/cacheLife).

### Trade-off

Longer lifetimes allow the cached data to be included in prerendered output, but may serve older data. Choose values that match the freshness your data requires.

### Gotchas

- Set `cacheLife` in the cached function, which may be a helper called by the highlighted `await`. The dev overlay points to where the route consumes the cached result.
- When both are set, `expire` must be longer than `revalidate`.
- Adding `use cache` again does not resolve this error. The function is already cached.
- Wrapping the access in `<Suspense>` or setting `instant = false` does not satisfy [`ensureStatic = 'navigation'`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic#navigation). A fully static route must increase the lifetime or remove the access.

## Other options

If the short lifetime is intentional and the route does not require fully static output, choose the alternative for the location of the access:

| Location      | Other fixes                                                                                                                                                                                                 |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Route content | [Wrap in or move into Suspense](/docs/messages/blocking-prerender-runtime#wrap-in-or-move-into-suspense), or [allow a blocking route](/docs/messages/blocking-prerender-runtime#allow-blocking-route)       |
| Metadata      | [Use static metadata](/docs/messages/blocking-prerender-metadata-runtime#use-static-metadata), or [mark the route as dynamic](/docs/messages/blocking-prerender-metadata-runtime#mark-the-route-as-dynamic) |
| Viewport      | [Use static viewport](/docs/messages/blocking-prerender-viewport-runtime#use-static-viewport), or [allow a blocking route](/docs/messages/blocking-prerender-viewport-runtime#allow-blocking-route)         |

For a fully static route, [remove the short-lived cache access](/docs/messages/static-route-runtime#remove-the-data-access) or replace it with a [static metadata](/docs/messages/static-metadata-runtime#use-static-metadata) or [static viewport](/docs/messages/static-viewport-runtime#use-static-viewport) export. The route's static requirement still applies when the access is behind `<Suspense>`.

## Verifying the fix

After changing the lifetime, reload the route and navigate to it from another page. Confirm the error clears and the page immediately displays meaningful content. If you chose streaming instead, check that the fallback covers only the region that streams in. Wrapping the whole page in a fallback can leave the page showing only that fallback while the content loads.

Production builds may report a combined uncached/runtime diagnostic when they cannot identify the cause more precisely. Check the lifetimes of any cached functions consumed by the reported component. Run `next build --debug-prerender` for more detailed stack traces, and use [`--debug-build-paths`](/docs/app/api-reference/cli/next#debugging-prerender-errors) to focus on affected routes.
