A page or layout on this route exports [`unstable_ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) with the `'navigation'` value, requiring fully static server output.

During [prerendering](/docs/app/glossary#prerendering), `generateViewport()` performed an uncached `fetch` request, database call, or `connection()`. The operation requires request-time server work and cannot be included in fully static output.

Request-specific reads from `cookies()`, `headers()`, `params`, or `searchParams` have different fixes. See [Runtime data in `generateViewport()` on a route that must be fully static](/docs/messages/ensure-static-viewport-runtime).

## Cache the viewport

Choose this fix when viewport data can be shared across requests.

### Patterns

Cache `generateViewport()` with [`use cache`](/docs/app/api-reference/directives/use-cache) and choose an appropriate [`cacheLife`](/docs/app/api-reference/functions/cacheLife) profile:

```jsx filename="app/page.jsx"
import { cacheLife } from 'next/cache'

export async function generateViewport() {
  'use cache'
  cacheLife('hours')
  const response = await fetch('https://api.example.com/content')
  const data = await response.json()
  return { themeColor: data.themeColor }
}
```

### Trade-off

Visitors share the cached viewport data until it is revalidated.

### Gotchas

- This fix does not apply to [`connection()`](/docs/app/api-reference/functions/connection), whose purpose is to require request-time rendering.
- Caching does not make cookies, headers, parameters, or search parameters static.

### Short-lived caches

For fully static navigation, a cache's `expire` must be at least 300 seconds, `stale` at least 30 seconds, and `revalidate` greater than zero.

## Use static viewport

Choose this fix when viewport settings do not need the uncached value.

### Patterns

Replace `generateViewport()` with a static [`viewport`](/docs/app/api-reference/functions/generate-viewport#the-viewport-object) export:

```jsx filename="app/dashboard/layout.jsx"
export const viewport = { themeColor: 'black' }
```

### Trade-off

The viewport is determined during prerendering rather than from the removed data source.

### Gotchas

- This fixes viewport settings only. Page content, metadata, and other segments must also satisfy the static requirement.
- If the value is required per request, remove the `unstable_ensureStatic = 'navigation'` requirement instead.

## Verifying the fix

After applying a fix, reload the route and confirm that this error no longer appears. Wrapping the operation in Suspense or setting `instant = false` does not relax the fully static requirement.

In [`next dev`](/docs/app/api-reference/cli/next#next-dev-options), the error overlay points at the failing function with file paths and line numbers. When working from a build instead, the default [`next build`](/docs/app/api-reference/cli/next#next-build-options) output is more abbreviated. Run `next build --debug-prerender` for full user-frame stack traces and `next build --debug-build-paths /dashboard /settings` to iterate on specific routes.

## Don't want this validation?

If the route requires a request-time viewport, remove `unstable_ensureStatic = 'navigation'` from the pages or layouts that set it.
