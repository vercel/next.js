---
title: 'A `<Link prefetch={true}>` navigated to a route that has not enabled Partial Prefetching'
kind: insight
---

With [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) enabled, [`<Link prefetch={true}>`](/docs/app/api-reference/components/link) is a legacy "full" prefetch that pulls down the route's dynamic data instead of only the [static shell](/docs/app/guides/instant-navigation). Routes that opt into [Partial Prefetching](/docs/app/guides/adopting-partial-prefetching) prefetch only the shell and defer dynamic data to navigation time, which is what makes navigation feel instant. When a `<Link prefetch={true}>` navigates to a route that has not opted into Partial Prefetching, the prefetch defeats the static/dynamic split that Cache Components provides.

The check runs at navigation time (not prefetch time) so existing apps that have recently enabled Cache Components are not flooded with warnings for every `<Link prefetch={true}>` on the page. You only hear about a route when you actually navigate to it.

> **Good to know**: In [`next dev`](/docs/app/api-reference/cli/next#next-dev-options), the error overlay points at the failing component. Run `next build --debug-prerender` to get the full list of blocking routes with stack traces. When iterating on specific routes, use `next build --debug-build-paths /dashboard /settings` to rebuild only those pages.

## Opt into Partial Prefetching

Choose this fix when the target route is a good candidate for Partial Prefetching. Most pages with a static shell and dynamic content below it are. Adding [`prefetch = 'partial'`](/docs/app/api-reference/file-conventions/route-segment-config/prefetch) to the page or layout tells Next.js to prefetch only the route's static shell and defer the dynamic data to navigation.

### Patterns

#### Per-route opt-in

Export `prefetch` from the page or layout of the route the link points at.

```jsx filename="app/dashboard/page.js"
export const prefetch = 'partial'

export default function DashboardPage() {
  return <Dashboard />
}
```

#### App-wide opt-in

Set [`partialPrefetching`](/docs/app/api-reference/config/next-config-js/partialPrefetching) to `true` in `next.config` to opt the whole app in.

```js filename="next.config.js"
module.exports = {
  partialPrefetching: true,
}
```

Learn more: [Adopting Partial Prefetching](/docs/app/guides/adopting-partial-prefetching).

### Trade-off

The route's dynamic data isn't included in the prefetch. The user sees the static shell instantly and the dynamic content streams in after navigation. For most routes this is the right trade-off; the shell appears immediately and the dynamic content arrives only marginally later than it would with a full prefetch.

### Gotchas

- Partial Prefetching only works with [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) enabled.
- If the route doesn't have a clear static shell (everything below the layout reads dynamic data), Partial Prefetching has nothing to prefetch and behaves the same as no prefetch. Move static content above the dynamic boundary first.

## Prefetch only the static shell

Choose this fix when you don't need the dynamic data prefetched and the default `<Link>` behavior is fine. Removing `prefetch={true}` lets the link use Next.js's default prefetch strategy, which under Cache Components prefetches the static shell only.

### Patterns

#### Remove the `prefetch` prop

```jsx filename="app/nav.js"
import Link from 'next/link'

export default function Nav() {
  return <Link href="/dashboard">Dashboard</Link>
}
```

### Trade-off

The link no longer forces a full prefetch. The user gets the static shell on hover or when the link becomes visible, and the dynamic data is fetched at navigation time. This is the default behavior under Cache Components and is the right choice for most links.

### Gotchas

- Removing `prefetch={true}` does not disable prefetching. It falls back to the default. To disable prefetching entirely, use `prefetch={false}`.

## Disable validation on this route

Choose this fix when you genuinely need the legacy full prefetch behavior (for example, a route where prefetching the dynamic data has a measurable user-experience benefit and the cost is acceptable). Setting [`instant`](/docs/app/api-reference/file-conventions/route-segment-config/instant) to `false` on the target route opts it out of instant-navigation validation and silences the warning.

### Patterns

#### Opt the route out

Add the export to the page or layout file of the target route.

```jsx filename="app/dashboard/page.js"
export const instant = false

export default function DashboardPage() {
  return <Dashboard />
}
```

### Trade-off

The link continues to do a full prefetch, including dynamic data, and the warning is silenced. The route no longer participates in instant-navigation validation, so other instant-navigation issues on the route will not surface either.

### Gotchas

- `instant = false` also disables other instant-navigation checks for the route (blocking-route warnings, unrendered-segment warnings, etc.). Use it sparingly.

## Don't want this validation?

Instant-navigation validation runs by default in [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) apps and is what surfaces this error.

- **One segment**: add [`export const instant = false`](/docs/app/api-reference/file-conventions/route-segment-config/instant) to the page or layout file. This opts out the segment itself. Child segments are still validated during client navigations.
- **Entire app**: set [`experimental.instantInsights.validationLevel`](/docs/app/api-reference/file-conventions/route-segment-config/instant#configuring-validation-defaults) to `'manual-warning'` in `next.config`. This limits validation to segments that explicitly export `instant`.

See [Ensuring instant navigations](/docs/app/guides/instant-navigation) for the full model.
