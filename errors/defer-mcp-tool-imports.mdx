---
title: Defer imports that only an MCP tool's `execute()` uses
---

> Load modules that only an `@next/mcp` tool’s `execute()` uses with `await import()`, so they do not lengthen the MCP route’s cold start.

## Why This Error Occurred

A file that defines an MCP tool with `defineTool` imported a module at the top level, but only uses it inside `execute()`, or inside helper functions that only `execute()` calls. Or it constructed something at module scope, such as an SDK client, that only `execute()` uses.

An MCP route loads every tool module when it starts, because `tools/list` needs each tool's description and input schema. Everything a tool file does at the top level therefore runs on every cold start of the route, even for requests that never call that tool. One tool that imports a cloud SDK or a database client slows down every tool on the server.

```ts filename="app/mcp/tools/upload_file.ts"
import { defineTool } from '@next/mcp/tools'
import { z } from 'zod'
import { S3Client, PutObjectCommand } from '@aws-sdk/client-s3'
import { db } from '@/lib/db'

// Runs on every cold start, only so execute() can use it.
const s3 = new S3Client({})

export default defineTool({
  description: 'Upload a file.',
  inputSchema: z.object({ name: z.string(), body: z.string() }),
  async execute({ name, body }) {
    await s3.send(
      new PutObjectCommand({ Bucket: 'files', Key: name, Body: body })
    )
    return db.file.create({ data: { name } })
  },
})
```

## Possible Ways to Fix It

Keep only what `tools/list` needs at the top level of a tool file: the description, the schemas, and their imports. Load everything else inside `execute()` with `await import()`. Move clients into a shared module, which constructs them on first import and reuses them for later calls:

```ts filename="lib/s3.ts"
import { S3Client } from '@aws-sdk/client-s3'

export const s3 = new S3Client({})
```

```ts filename="app/mcp/tools/upload_file.ts"
import { defineTool } from '@next/mcp/tools'
import { z } from 'zod'

export default defineTool({
  description: 'Upload a file.',
  inputSchema: z.object({ name: z.string(), body: z.string() }),
  async execute({ name, body }) {
    const [{ s3 }, { PutObjectCommand }, { db }] = await Promise.all([
      import('@/lib/s3'),
      import('@aws-sdk/client-s3'),
      import('@/lib/db'),
    ])
    await s3.send(
      new PutObjectCommand({ Bucket: 'files', Key: name, Body: body })
    )
    return db.file.create({ data: { name } })
  },
})
```

Loading independent modules with `Promise.all` means the first call waits for the slowest import, not all of them in sequence.

For a plain import used in a single async function, the rule offers an editor suggestion that moves it into that function: `execute()`, or the helper that uses it. It does not change module-level code for you, because moving a client changes when it is created.

Imports used by `description`, `inputSchema`, `outputSchema`, or `approval` are needed when the module loads and are never flagged. Neither are type-only imports, side-effect imports, `next`, `@next/mcp`, `zod`, or Node.js built-in modules. To allow more modules, pass `allow`:

```js filename="eslint.config.mjs"
export default [
  {
    rules: {
      '@next/next/defer-mcp-tool-imports': ['warn', { allow: ['@/lib/flags'] }],
    },
  },
]
```

The rule sees one file at a time. It cannot tell a small helper module from one that pulls in a database client, and it cannot tell when another module, such as the route's auth function, already loads the same dependency eagerly. In that case deferring it saves nothing.
