A page or layout on this route exports [`unstable_ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) with the `'navigation'` value, requiring fully static server output.

During [prerendering](/docs/app/glossary#prerendering), Next.js encountered data in the page or layout that prevented the route from completing. The build could not determine whether the cause was runtime data or uncached data.

Use the page that matches the data access shown in the stack trace:

- [Runtime data on a route that must be fully static](/docs/messages/ensure-static-route-runtime), such as `cookies()`, `headers()`, `params`, or `searchParams`
- [Uncached data on a route that must be fully static](/docs/messages/ensure-static-route-dynamic), such as a `fetch` request, database call, or `connection()`

Wrapping the work in Suspense or setting `instant = false` does not relax the fully static requirement.

## Cache the data

Choose this fix when the stack trace points to an uncached fetch or database call whose result can be shared across requests.

### Patterns

Add [`use cache`](/docs/app/api-reference/directives/use-cache) to the function that reads the data:

```jsx filename="app/data.js"
export async function getData() {
  'use cache'
  return db.query('SELECT * FROM posts')
}
```

### Trade-off

Visitors share the cached result until it is revalidated.

### Gotchas

- This fix does not apply to [`connection()`](/docs/app/api-reference/functions/connection) or request-time APIs.
- For the complete caching guidance, see [Uncached data on a route that must be fully static](/docs/messages/ensure-static-route-dynamic#cache-the-data).

### Short-lived caches

For fully static navigation, a cache's `expire` must be at least 300 seconds, `stale` at least 30 seconds, and `revalidate` greater than zero.

## Remove the data access

Choose this fix when the route does not need the reported request-time or uncached value.

### Patterns

Keep the static requirement and remove the access:

```jsx filename="app/page.jsx"
export const unstable_ensureStatic = 'navigation'

export default function Page() {
  return <Content />
}
```

### Trade-off

The route no longer varies based on the removed data source.

### Gotchas

- Remove the access itself, not only the JSX that displays its result.
- Other data accesses in layouts, metadata, and viewport code must also satisfy the static requirement.

## Provide static parameters

Choose this fix only when the stack trace points to dynamic route `params`.

### Patterns

Return every parameter value that the route should prerender:

```jsx filename="app/blog/[slug]/page.jsx"
export function generateStaticParams() {
  return [{ slug: 'hello' }]
}
```

### Trade-off

The returned paths are generated at build time. Other values wait for a blocking prerender before Next.js serves their static output.

### Gotchas

- This fix does not apply to `cookies()`, `headers()`, `searchParams`, `connection()`, uncached data, or short-lived caches.
- Include every dynamic parameter. An empty array does not satisfy the static requirement.

## Read search parameters on the client

Choose this fix only when browser UI needs the query string.

### Patterns

Read it with [`useSearchParams()`](/docs/app/api-reference/functions/use-search-params) in a Client Component:

```jsx filename="app/search/query.jsx"
'use client'

import { useSearchParams } from 'next/navigation'

export default function Query() {
  return <p>{useSearchParams().get('q')}</p>
}
```

### Trade-off

The query-dependent UI renders in the browser.

### Gotchas

- This fix does not apply to cookies, headers, route parameters, `connection()`, or uncached data.
- Render the Client Component inside Suspense, and do not pass the server's `searchParams` promise to it.

## Verifying the fix

After applying a fix, reload the route in [`next dev`](/docs/app/api-reference/cli/next#next-dev-options). Then run [`next build`](/docs/app/api-reference/cli/next#next-build-options) and confirm that the route completes prerendering.

Run `next build --debug-prerender` for full user-frame stack traces and `next build --debug-build-paths /dashboard /settings` to iterate on specific routes.

## Don't want this validation?

If the route requires request-time server data, remove `unstable_ensureStatic = 'navigation'` from the pages or layouts that set it. The route then follows the ordinary [Cache Components](/docs/app/getting-started/caching) rendering rules.
