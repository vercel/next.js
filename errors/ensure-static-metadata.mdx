A page or layout on this route exports [`unstable_ensureStatic`](/docs/app/api-reference/file-conventions/route-segment-config/ensureStatic) with the `'navigation'` value, requiring fully static server output.

During [prerendering](/docs/app/glossary#prerendering), Next.js encountered data in `generateMetadata()` that prevented the route from completing. The build could not determine whether the cause was runtime data or uncached data.

Use the page that matches the data access shown in the stack trace:

- [Runtime data in `generateMetadata()`](/docs/messages/ensure-static-metadata-runtime), such as `cookies()`, `headers()`, `params`, or `searchParams`
- [Uncached data in `generateMetadata()`](/docs/messages/ensure-static-metadata-dynamic), such as a `fetch` request, database call, or `connection()`

Wrapping the work in Suspense or setting `instant = false` does not relax the fully static requirement.

## Cache the metadata

Choose this fix when the stack trace points to uncached data that can be shared across requests.

### Patterns

Cache `generateMetadata()` with [`use cache`](/docs/app/api-reference/directives/use-cache):

```jsx filename="app/page.jsx"
export async function generateMetadata() {
  'use cache'
  return cms.getMetadata()
}
```

### Trade-off

Visitors share the cached metadata until it is revalidated.

### Gotchas

- This fix does not apply to [`connection()`](/docs/app/api-reference/functions/connection) or request-time APIs.
- See [Uncached data in `generateMetadata()`](/docs/messages/ensure-static-metadata-dynamic#cache-the-metadata) for the complete caching guidance.

## Use static metadata

Choose this fix when the metadata does not need the reported data source.

### Patterns

Export a static metadata object:

```jsx filename="app/layout.jsx"
export const metadata = { title: 'My page' }
```

### Trade-off

The metadata is determined during prerendering rather than per request.

### Gotchas

- This fixes metadata only. Page content and other segments must also satisfy the static requirement.
- Remove the dynamic access itself, not only the value that displays its result.

## Provide static parameters

Choose this fix only when `generateMetadata()` reads dynamic route `params`.

### Patterns

Return every parameter value that the route should prerender:

```jsx filename="app/blog/[slug]/page.jsx"
export function generateStaticParams() {
  return [{ slug: 'hello' }]
}
```

### Trade-off

The returned paths are generated at build time. Other values wait for a blocking prerender before Next.js serves their static output.

### Gotchas

- This fix does not apply to cookies, headers, search parameters, `connection()`, uncached data, or short-lived caches.
- Include every dynamic parameter. An empty array does not satisfy the static requirement.

## Verifying the fix

After applying a fix, reload the route in [`next dev`](/docs/app/api-reference/cli/next#next-dev-options). Then run [`next build`](/docs/app/api-reference/cli/next#next-build-options) and confirm that the route completes prerendering.

Run `next build --debug-prerender` for full user-frame stack traces and `next build --debug-build-paths /dashboard /settings` to iterate on specific routes.

## Don't want this validation?

If the route requires request-time server data, remove `unstable_ensureStatic = 'navigation'` from the pages or layouts that set it. The route then follows the ordinary [Cache Components](/docs/app/getting-started/caching) rendering rules.
