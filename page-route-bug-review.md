# Page/Route representation assumptions for human review

This inventory records **48 assumptions requiring human review**, not confirmed bugs, from the [Page/Route brand migration](https://github.com/vercel/next.js/commit/c30230e23e3eacbb33b93d9d78528758ca414068). Runtime behavior and test expectations were intentionally preserved. The sites have local explanatory `@ts-ignore` notes rather than assertions concealing representation mismatches.

`Page` is a raw module identifier retaining internal modifiers and leaf suffixes; `Route` is a normalized URL pathname or pattern. This inventory covers flagged mismatches, **not approval of all remaining `as Page` or `as Route` assertions**.

References identify source files and functions rather than unstable line numbers. Full paths are repository-relative; abbreviated `lib/`, `build/`, and `server/` paths are relative to `packages/next/src`. The final `turbopack/entry-key.ts` shorthand refers to `packages/next/src/shared/lib/turbopack/entry-key.ts`.

1. `packages/next/src/shared/lib/router/utils/app-paths.ts`, normalizeAppPath return: contract is Page->Route, but interception markers survive (e.g. `/feed/(..)photo/page` -> `/feed/(..)photo`, not actual `/photo`). Existing algorithm deliberately leaves these matcher-key modifiers. Assertion at return was replaced with @ts-ignore and an explicit note. Whether all results should be considered URL Routes requires human review; do not change algorithm.
2. `packages/next/src/shared/lib/router/router.ts`, resolveDynamicRoute cleanPathname: normalized client Route is passed to denormalizePagePath(Page):Page and its result is treated as Route. This applies file-specific `/index` handling to URL input. May be intentional historical Pages-router encoding; preserve behavior and flag this representation assumption rather than cast.
3. `packages/next/src/shared/lib/router/utils/resolve-rewrites.ts`, reassignment to fsPathname after prepareDestination: `newUrl` may include a hash (prepareDestination compiles pathname+hash), but existing code uses this full path string instead of `parsedDestination.pathname` as normalized pathname for page matching. Preserve existing code with a local @ts-ignore; potential fragment contamination needs review.

4. `packages/next/src/server/require.ts`, checkManifest condition `!manifest[curPath]`: curPath is the bundle filename obtained from manifest[page], not a page identifier. Checking the page-keyed manifest using this filesystem/bundle string is a representation mismatch. Preserve the existing locale-fallback condition with a local explanatory @ts-ignore.

5. `packages/next/src/server/base-server.ts`, minimal-mode matchedPath denormalization: matchedPath is extracted from a parsed URL (Route), then passed to Page-file denormalizePagePath and assigned back to Route. Deployment-specific filename encoding may explain it, but is an unverified normalization assumption. Preserve the statement with a narrow human-review @ts-ignore; do not cast this pathname to Page.

6. `packages/next/src/server/base-server.ts`, SSG minimal-mode `req.url = stripNextDataPath(req.url)`: full request URL text (possibly including query) is passed to a Route pathname decoder applying Page filename rules. File `.json$` stripping may not work with query text. Keep the call unchanged with local human-review @ts-ignore rather than branding a full URL as Route.

7. `packages/next/src/server/next-server.ts`, runApi edge dispatch comparison and `runEdgeFunction({page: match.definition.pathname})`: raw edge Page module keys are compared to normalized API Route, which is then sent to Page-keyed edge module lookup rather than using raw definition.page. This is a Pages-router same-namespace assumption, potentially affected by normalization (e.g. locale handling). No definition is provided to this call; this is actual module dispatch/lookup, not merely a trace label. Preserve both comparison and property with narrowly placed @ts-ignore comments. (Two suppression statements for one underlying assumption.)
8. `packages/next/src/server/next-server.ts`, custom-server renderToHTML ensures `page: pathname`: public URL pathname is sent directly to raw Page filesystem discovery without selecting an app entry. This may be valid for legacy Pages-router namespace but is not established for app modifiers/leaf suffixes. Preserve existing ensure behavior with narrow @ts-ignore, rather than an unverified Page cast.

9. `packages/next/src/build/templates/edge-ssr.ts`, requestHandler srcPage is `VAR_DEFINITION_PATHNAME` (Route), unlike Node's `VAR_DEFINITION_PAGE` (Page). It is forwarded to prepare.srcPage and renderOpts.page, which both expect raw Page. For `/index` and other file encodings, review the edge-vs-Node normalization assumption. Preserve both property statements with narrowly placed @ts-ignore comments; do not replace the placeholder or cast it to Page. (Two suppression statements for one underlying assumption.)

10. `packages/next/src/build/webpack/loaders/next-app-loader/index.ts`, getStaticSiblingSegments: allNormalizedAppPaths is populated by Object.keys(appPathsPerRoute) in build/entries (normalized Route keys). normalizeAppPath is called a second time on each Route and can strip a real URL `/page` or `/route` leaf.
